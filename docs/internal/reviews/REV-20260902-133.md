# REV-20260902-133 — digest heredoc executes prose as a root command

Review date: 2026-09-02
Reviewer: ChatGPT
Reviewed delivery: PR #260, head `d3cd8d36648972d3e8654c47e6c8fe531295518d`
Canonical base checked: `fd57178a4902b349ddf63575f85f9c0d05b2a9b5`

## Verdict

**CHANGES REQUIRED — P2: the new explanatory comment contains unescaped
backticks inside an expanded heredoc, so generating `alert-digest.sh` attempts
to execute `Doba:` as a command.**

The date/period behavior itself is coherent and the focused functional cases
pass. The delivery is blocked only on removing this unintended execution and
pinning that property in the focused test.

## F1 — P2 BLOCKING — rendering the generated script executes comment text

- Severity: P2
- Blocking: yes
- Affected: `deploy.sh`, the `alert-digest.sh` heredoc, and
  `test/alertmail/run.sh`.

### Evidence

PR #260 adds this text inside the unquoted heredoc used to generate
`/root/scripts/alert-digest.sh`:

```sh
# THE PERIOD THE EVENTS COVER, not the moment this mail is sent. `Doba:
# $TODAY` was the send date ...
```

An unquoted Bash heredoc performs parameter expansion and command substitution
before `cat` receives its input. Comment syntax in the generated output does
not suppress those expansions. The backticks therefore span the newline and
attempt to invoke a command named `Doba:` while `deploy.sh` is running.

The delivery's own focused suite reports `37 PASS / 0 FAIL`, but also emits:

```text
./test/alertmail/run.sh: line 313: Doba:: command not found
```

Line 313 is the `eval` that renders the real heredoc for the test. The suite
does not assert that generation is silent, so CI remains green despite the
execution attempt.

Reviewer-only discriminating control rendered the same heredoc from canonical
`main` and from the exact PR head, with identical fixed expansion inputs:

```text
main=
head=environment: line 3: Doba:: command not found
```

Thus the error is introduced by exact head
`d3cd8d36648972d3e8654c47e6c8fe531295518d`; it is absent from canonical
`main` `fd57178a4902b349ddf63575f85f9c0d05b2a9b5`.

### Failure mode and impact

Every real non-check deployment that creates or upgrades digest v10 evaluates
the comment as root, emits a misleading command-not-found error, and writes a
comment whose text has been altered by substitution. Today the command name is
constant and normally absent, so the intended digest behavior still installs;
the immediate risk is deployment integrity and a green test that masks
unintended execution, not data loss.

### Acceptance criteria

1. Remove or escape command-substitution syntax from every newly added comment
   inside the expanded digest heredoc; rendering it must execute no comment
   text and emit no stderr.
2. Preserve the intended v10 behavior: the header names the event period,
   events from another day carry their date, and today's rows remain time-only.
3. Extend the focused heredoc test so it fails on
   `d3cd8d36648972d3e8654c47e6c8fe531295518d` and passes on the fix by asserting
   both empty generation stderr and that a sentinel executable named `Doba:`
   in `PATH` is never invoked.
4. Keep the scope to heredoc safety and its focused regression; do not add
   automatic alert-staleness semantics in this correction.

### Required verification

- `bash test/alertmail/run.sh` with no unexpected stderr;
- the new focused generation control against the old and fixed SHAs;
- `./test/impact.sh --verify` and exact-head CI.

No live ZFS, mail delivery or fleet campaign is required: the defect is fully
decided while rendering the generated shell script.
