# REV-20260901-131 — dataset-level `gfs` silently overrides every tier

Review date: 2026-09-01
Reviewer: ChatGPT
Reviewed delivery: PR #244, head `2443d74caf1235e60a28bcd82f909e8b7131d7d7`
Canonical base checked: `a23df1c43eeeb7b2d486ce8f5ec17a3f6466286a`

## Verdict

**CHANGES REQUIRED — P1: the new validator exemption accepts `gfs` in a
profile's `[dataset]` block, where it silently overrides every referenced
tier instead of applying only to the tier that declared it.**

## F1 — P1 BLOCKING — the `gfs` exemption is wider than its stated contract

- Severity: P1
- Blocking: yes
- Affected: `lib-profile.sh` and the focused profile ownership coverage.

### Evidence

PR #244 correctly adds `gfs` to the template policy schema so one tier can
request its own `-G` ladder. It also exempts `gfs|gfs_pattern` before checking
the section kind:

```sh
case "$field" in gfs|gfs_pattern) ;; *)
    if [ "$kind" = dataset ] || [ "$kind" = prune ]; then
        ...
    fi
;; esac
```

The accompanying explanation only justifies `[prune] gfs`: there, one combined
ladder is a property of the section. It does not justify `[dataset] gfs`, where
`resolve_field gfs "$ds" "$tmpl" ...` reads the dataset section first and the
same value therefore wins over every tier template.

Reviewer-only control on exact merged `main` `54698a552347235b473652d229916158603b31c0`:

1. copy the shipped lowercase `d30h24` profile;
2. add `gfs = yes` to its `[dataset]` block;
3. run `profile_validate_file` against the real `gen-cron.sh`;
4. run the existing focused profile suite over that profile.

Observed:

```text
profile_validate_file: rc=0, PROFILE_ERR empty
FAIL: naming: ... d30h24(lowercase but rendered a -G ladder)
profiles: 83 passed, 1 failed
```

The unmodified submitted head passes `profiles: 84 passed, 0 failed`, so the
existing suite checks shipped output but does not exercise the newly widened
ownership boundary.

### Failure mode and impact

A user profile can put one `gfs=yes` in `[dataset]`, pass production validation,
and change all referenced tier families from flat-count retention to time-bucket
retention. The generated config remains valid and jobs run, so this is a silent
semantic change rather than a fail-closed configuration error. It also breaks
the documented lowercase profile shape while the source profile still appears
to assign policy per tier.

### Acceptance criteria

1. Exempt `gfs` from the template-only rule only for the `[prune]` fragment;
   `[dataset] gfs` must be refused as policy that belongs in `[template:tier]`.
2. Preserve valid `[prune] gfs = yes` and `gfs_pattern` behavior used by shipped
   combined-ladder profiles.
3. Preserve valid per-tier `gfs = yes` in `[template:tier]`, including the new
   `y5m12d31h24` profile and its emitted `-G` lines.
4. Add one focused negative for `[dataset] gfs = yes` and matched positives for
   `[prune] gfs` and template-level `gfs`; do not broaden into a live campaign.
