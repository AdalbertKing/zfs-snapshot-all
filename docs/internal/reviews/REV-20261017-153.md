# REV-20261017-153 — restore must distinguish a remote host without an explicit user

## Verdict

**CHANGES REQUIRED before merging PR #601.** The intended local-beside fix
and early remote-PUSH refusal work for the tested account@host spelling, but
the new local classification misroutes another supported remote spelling.
This is independent of REV-152; that review remains open for F5 evidence.
No frozen engine change is requested or authorised.

## F1 — P1 blocking: host:dataset is classified as local and changes the restore host

- Affected: `zfs-restore.sh`, `restore_dest_peer`, `restore_scope_dest`,
  `restore_relations`, `restore_run_scope`, the planner's remote-copy branch,
  and the transport comparison in `restore_report_handover`.
- Blocking: yes, PR #601 must not be merged as submitted.

### Evidence

The supported engine/generator transport is `[user@]host:dataset`; the user
is optional. `gen-cron.sh` documents this at its src field and validates a
literal colon-bearing src; `snapsend.sh` documents the same remote dst form.
The changed restore branches instead test only `*@*:*`.

An independent read-only reproduction used the actual generator and restore
config readers, not a fake local/remote classifier:

```ini
[defaults]
 host_label = collector
[template:h]
 send_schedule = 7 * * * *
 prefix = automated_
[dataset:hdd/backups/pve9/hdd/home]
 use_template = h
 src = pve9:hdd/home
 pair_label = rel
[dataset:hdd/home]
 use_template = h
 dst = pve10:hdd/backups
 pair_label = pushrel
```

The real generator accepts this with rc 0 and emits a pull from
`pve9:hdd/home` and a push to `pve10:hdd/backups`.
With `RESTORE_DEST_PEER` unset (the documented config fallback), the actual
`restore_scope_dest` path for `restore rel rel --onto=hdd/restore/home`,
selected source `pve9:hdd/home`, returns:

```text
ACTUAL_DEST=hdd/restore/home
```

That is a collector-local path, not a path on pve9. `restore_dest_peer`
returns 3 for the nonempty remote source because it has no @. The new
same-label branch accepts that as LOCAL and drops the host. The previous
implementation refused this fallback instead of selecting a local host.
No actual receive, overwrite or ZFS mutation was performed.

The same address-shape gap remains in the new PUSH refusal:
`restore_relations` calls `pve10:hdd/backups/hdd/home` a local push, and
`restore_run_scope` with that copy address reaches an instrumented
`restore_pause_take` sentinel. The new early refusal never runs. This is the
same parser assumption, not a separate implementation task.

### Failure mode and impact

A valid remote relation can be offered a recovery onto the collector instead
of its source host when no record-provided peer overrides the config fallback.
A local path is then processed by the existing local restore/grant rules.
Normal preflight and confirmation still exist; this reproduction does not
claim they were bypassed or that live data was destroyed. They cannot make a
wrong host selection correct, particularly when both hosts have the chosen
pool/path. A generated record using account@host avoids this case, but the
supported CONFIG surface and explicit fallback must also fail safely.
The PUSH case also retains the false copy-location report and pauses a job
that should have been refused before pause.

### Required outcome

1. Classify local and remote addresses consistently with the supported
   generator/engine transport forms, including optional user and the bare
   user@host sync destination where applicable. Do not turn an unrecognised
   or ambiguous remote shape into a local destination.
2. `restore rel rel --onto` for a host-only remote source must either keep
   that host and the established SSH/grant checks or explicitly refuse before
   mutation. It must never return a local path as if the relation were local.
3. Remote PUSH copies must be reported as remote and refused before the pause
   in every supported remote spelling. Genuine local relations keep the new
   local-beside behavior; different local relations remain refused.
4. Apply the same transport identity to the handover report, so absence of an
   explicit account cannot erase the machine identity.

### Required verification

- Real CONFIG-reader tests with `src = host:dataset`, with and without
  RESTORE_DEST_PEER, for same-label beside recovery. Assert the destination
  host, or an explicit safe refusal, and no collector-local write path.
- `dst = host:base`, `dst = user@host:base`, and supported sync spelling:
  correct plan plus refusal before a pause/SSH/ZFS mutation sentinel.
- Positive controls: real local source/copy, same-label local beside,
  cross-local refusal, existing account@host remote target.
- Include these in the shipped suite and show they fail on PR #601's head.
  Run affected restore/TUI and impact verification; disposable live target
  only if a write is needed to establish behavior.

## Nonblocking scope guidance for the PR's open questions

The existing preflight rc 2 is explicitly preserved by REV-127 and its tests;
PR #601 need not silently change that established contract. A later status
clarification should distinguish preflight refusal from changed/incomplete
execution, with caller tests, without loosening the safety boundary.

The already-present-snapshot mirror behavior is documented in the existing
engine proposal and is not a reason to thaw engines in this restore fix.
The restore message should describe the measured condition accurately:
copy cleanup may wait for a run with a new source snapshot, rather than
unconditionally claiming the next run does it. This wording and the existing
chain design questions do not replace or dilute blocking F1 above.
