# REV-20260908-140 — cron source lookup trusts an unrelated comment outside the managed block

Review date: 2026-09-08
Reviewer: ChatGPT
Reviewed delivery: PR #364, implementation `7d8faf1ef86923f183a78cdc8588287c5db035a0`
Canonical merge checked: `bf5466674cd5c2d5e373d9faf412df8f4bc154dc`

## Verdict

**CHANGES REQUIRED — P1: the new shared `cron_block_source()` helper selects
the first `# Source:` line in the whole crontab, even when that line is outside
the managed block. A harmless foreign comment can therefore make the install
guard accept a different config and permit replacement of the live jobs.**

The corrected second-line grammar in `jobs_block_config()`, the real-shape
fixtures and the `list-jobs` behavior are not rejected. The blocker is confined
to binding every source lookup to the managed block that owns it.

## F1 — P1 BLOCKING — an out-of-block Source line bypasses config ownership checks

- Severity: P1
- Blocking: yes
- Affected: `cron_block_source()` and its full-crontab callers in
  `zfs-backup.sh`, especially `assert_cron_config_matches_installed()` and
  `assert_config_not_claimed_if_missing()`.

### Evidence

On exact implementation `7d8faf1ef86923f183a78cdc8588287c5db035a0`, the
reviewer supplied this synthetic crontab:

```text
# Source: /tmp/want.conf -- unrelated user comment
# BEGIN zfs-backup-managed (generated)
# Source: /tmp/actual.conf -- DO NOT EDIT BY HAND, re-run gen-cron.sh instead
0 1 * * * /r/snapsend.sh tank/live tank/backup
# END zfs-backup-managed
```

`assert_cron_config_matches_installed /tmp/want.conf` returned `rc=0`. The
control with the unrelated first line removed returned `rc=1` and correctly
reported that installing from `want.conf` would delete every job described by
`actual.conf`.

`cron_block_source()` currently runs `grep -m1 '^# Source: '` on its entire
stdin. Although `jobs_block_config()` narrows its input to the managed block,
the safety guards, account discovery and setup-server adoption pass the whole
crontab. Cron permits arbitrary comments outside this project's block, so the
first matching comment is not an ownership record.

### Failure mode and impact

The false success reaches mutating install paths guarded by
`assert_cron_config_matches_installed()`: config B can replace the one managed
block generated from config A, deleting A's scheduled send, prune and monitor
lines. The missing-config guard can likewise overlook that the live block
claims the missing file it is about to recreate empty. This is a credible
unsafe operational path, so the finding is P1 rather than a parser-only P2.

### Existing verification and why it missed the defect

- PR #364 exact-head CI is green: run `34266315964`.
- Independent focused runs on canonical `main`:
  `listjobs 26 PASS / 0 FAIL`, `realshape 18 PASS / 0 FAIL`.
- Both fixtures begin directly with this project's managed block. Neither puts
  a syntactically valid but unrelated `# Source:` comment before it.

### Acceptance criteria

1. Derive a config source only from bytes between this project's matching
   `# BEGIN zfs-backup-managed` and `# END zfs-backup-managed` markers.
2. Every full-crontab caller of the shared helper must ignore `# Source:` lines
   outside that region; account discovery, adoption, warning and both install
   guards must agree on the same scoped source.
3. The discriminator above must make
   `assert_cron_config_matches_installed /tmp/want.conf` refuse, naming the
   managed block's `/tmp/actual.conf`; removing the foreign comment must retain
   the same refusal.
4. Add the symmetric missing-config discriminator: an unrelated earlier source
   must not hide that the managed block claims the missing config.
5. Preserve parsing of the generator's real two-line header, `list-jobs`
   population and the fail-closed behavior for unreadable configs.

### Required verification

- focused: the two direct guard discriminators above;
- regression: `./test/zfsbackup/run.sh --section listjobs` and
  `./test/realshape/run.sh`;
- consistency: `./test/impact.sh --verify` and exact-head CI.

No ZFS, live cron mutation or full product campaign is required. A synthetic
crontab stream decides the defect.

Publish one exact implementation SHA reachable from canonical `main`, explain
