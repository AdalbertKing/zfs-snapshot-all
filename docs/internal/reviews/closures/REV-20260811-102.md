# Closure — REV-20260811-102

Closed after independent review of the evidence-only resubmission `b9fcd402594ed2e989b773f437b513c4e759d8e2` and the real-ZFS continuity campaign run on pve1/pve2 as delegated `zfsbackup`.

The remaining REV-102 acceptance boundary is now proven rather than inferred:

- where an ordinary common snapshot remains, the next transfer after source prune is genuinely incremental (`zfs send -I`);
- where the ordinary common snapshot is gone but a usable bookmark remains, the real PULL path falls back to an incremental send from that bookmark and preserves TARGET history;
- where neither common snapshot nor bookmark remains, PULL refuses explicitly with exit 1 and leaves TARGET history unchanged;
- the recursive `-r` no-base case also refuses explicitly and preserves the TARGET tree;
- local PUSH in the equivalent no-base state is rejected by `zfs recv` rather than silently overwriting TARGET history;
- explicit `-f` remains a human-selected destructive recovery and announces that boundary.

This satisfies REV-102's safety/continuity acceptance property. No transfer-engine change is required to close REV-102.

The same campaign exposed a separate operational-resilience risk: relationships without usable bookmark insurance can stop permanently once source retention ages out the last common base. That does not invalidate the REV-102 safety result, because TARGET history is preserved and the failure is explicit, but it deserves an independent follow-up. See REV-20260812-111.
