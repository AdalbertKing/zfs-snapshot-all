# REV-20260810-094 — Phase 6 runnable CONFIG examples lack a dependency-driven regression edge

Status: APPROVED
Severity: P2 — test/dependency-graph defect
Blocking: next-slice (Phase 6)

## Independent review

The documentation slice is directionally appropriate and does not modify production runtime. The four files under `docs/examples/*.conf` are not merely prose, however: the delivery explicitly presents them as runnable CONFIG artifacts, says each was validated by the real `gen-cron.sh`, and tells operators they may copy and re-run them.

That creates a durable contract edge:

`gen-cron.sh CONFIG grammar/rendering` -> `docs/examples/*.conf` -> `documented operator behavior`.

The original dependency graph did not represent that edge. `test/deps.conf` listed `gen-cron.sh` suites without one covering the runnable examples; the example files were likewise not registered with a suite. That allowed their validity to silently rot after a future generator/schema change while `impact.sh` remained green.

## Required outcome

Add the smallest regression edge that proves the actual dependency, without broadening into a full campaign:

1. Add one focused suite that runs the real `gen-cron.sh -c` against every checked-in `docs/examples/*.conf`.
2. Pin more than exit 0: assert the few semantic line properties each current example exists to teach.
3. Add dependency edges so a change to `gen-cron.sh` selects this suite and a change/addition under `docs/examples/*.conf` selects it as well; the suite must select itself.
4. Include one meaningful negative control showing the suite would fail if a runnable example drifts from the intended generated shape.
5. Run only this targeted suite plus the dependency-driven cascade selected by the graph change and `test/impact.sh --verify`. Real ZFS/crontab/SSH proof is not required because this finding is confined to the pure generator boundary.

## Verification of implementation `58f67f69`

Verified independently from the submitted diff and current tree:

- `test/configexamples/run.sh` invokes the real `gen-cron.sh -c` for every current `docs/examples/*.conf` and fails if the directory contains no subjects.
- The suite pins the intended rendered semantics of all four current examples: independent H/D retention without GFS; per-dataset quiesce separation and three distinct send lines; short-local versus long-store retention; recursive/manual prune, bookmark prune, and monitor-only carrier without duplicate prune.
- `test/deps.conf` now routes changes in `gen-cron.sh`, `docs/examples/`, and the suite itself to `configexamples`, and declares the suite.
- The in-suite `keep 24 -> 99` mutation is a meaningful negative control against the pinned `-H24` property.
- No production runtime or environment-dependent path changed, so no live ZFS/crontab/SSH proof is warranted for this finding.

The submitted change therefore satisfies REV-094 for the four runnable examples that triggered it. A separate durability issue for *future newly-added examples* is tracked independently rather than keeping this finding open.

## Verdict

APPROVED. The missing dependency-driven regression edge for the current runnable examples is repaired by `58f67f69dc3ac8225c93b58d5b643758c3284978`.
