## F1 — P1: a `prune_foreign` rewrite can silently weaken an existing protected family

- Severity: **P1**
- Blocking: **yes for relying on the install guard before a destructive
  `prune_foreign` reactivation**
- Affected: `zfs-backup.sh`, `foreign_normalized_identity()` and the seventh
  exception in `assert_target_block_not_clobbered()`.

### Evidence

The seventh exception must recognize one intended transition: the finest
`delsnaps.sh` tier changes from its family pattern to an empty pattern and gains
generated `-P "<other-family>:all"` / `-P "<replica>:2"` protections. Its
normalizer currently removes **every** `-P` token from both installed and
proposed lines:

```bash
sed -E -e '/delsnaps\.sh/ s/ -P "[^"]*"//g' \
       -e '/delsnaps\.sh/ s/ "[^"]*"( -[HDWMYhdwmy][0-9 ])/ "<PAT>"\1/'
```

That also removes pre-existing, independent `[excluded:]` floors. The shipped
guard therefore distinguishes `vzdump:2 -> vzdump:0` when it is the only
change, but accepts the same weakening when it accompanies the empty-pattern
U4 rewrite.

Safe reproducer using the actual shipped guard, a stub read-only `crontab`, and
no ZFS or installation:

```bash
bash docs/internal/reviews/evidence/REV-20261024-174-prune-foreign-guard.sh \
  ./zfs-backup.sh
```

Result on inspected main:

```text
plain_protection_change_rc=1
combined_foreign_and_protection_change_rc=0
u4_only_rc=0
REPRODUCED: prune_foreign exception hides an unrelated -P protection change
```

The exact-head U4 tests are otherwise useful and pass: historical
`test/cron` 165/165, `test/cron2conf` 35/35, `passivepick` 12/12 and
`mirrorguard` 8/8. Replacing the three production files with exact base
versions produces the advertised 7, 4, 1 and 1 failures. Current main also
passes generator 123/123, cron 230/230, passivepick 15/15 and mirrorguard 8/8.
The hole remains because mirrorguard tests changed retention count and pattern,
but never changes an existing `-P` floor during the U4 transition. PR #465
exact-head CI run `37522116804` succeeded and therefore does not cover F1.

### Failure mode and impact

An installed line can protect the two newest `vzdump` snapshots while the
proposal simultaneously enables the empty-pattern foreign carrier and changes
that floor to zero. The guard reports only the named, allowed U4 conversion and
returns success. On the next real retention run, `delsnaps.sh` matches every
unprotected family because the pattern is empty; older `vzdump` snapshots now
compete in the finest tier and can be deleted. The same bypass applies to any
unrelated explicit `-P` prefix/count change hidden beside the U4 rewrite.

This evidence proves the fail-open installation decision and the resulting
destructive command shape. The reviewer did not install cron or run ZFS and
does not claim a live snapshot was deleted.
