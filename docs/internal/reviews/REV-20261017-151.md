## F1 — `-H` turns a refused unrelated target into a forced replication receive

- Severity: **P0**
- Blocking: **yes**
- Affected: `snapsend.sh`, the no-common-snapshot P-0 gate and construction of
  the full-history send/receive pipeline.

### Evidence

PR #480 promises that both engines refuse an existing target with snapshots
when no source snapshot or bookmark matches it by GUID, before sending. The
push guard instead contains an undocumented exception:

```bash
if [ $FORCE_FULL_SEND -ne 1 ] && [ "$FULL_HISTORY_SEND" -ne 1 ] \
   && [[ "$common_snapshot" == "null" ]] && [ -z "$bookmark_base" ] \
   && [ "${#tgt_snaps[@]}" -gt 0 ]; then
    # refuse
fi
```

`-H` sets `FULL_HISTORY_SEND=1`, so it skips that refusal. With no common base,
the same invocation then selects `zfs send -R` and the default receive flags
remain `-F -s`. This is not merely a misleading diagnostic: a replication
stream received with `-F` is a destructive synchronization boundary. The
[OpenZFS receive manual](https://openzfs.github.io/openzfs-docs/man/master/8/zfs-recv.8.html)
states that snapshots absent at the sending location are destroyed when a
`zfs send -R` replication package is received.

The pull twin does not make this exception: `snapget -H` refuses the same
fixture before transfer. The documented meaning of `-H` is full history when
no common base exists, not permission to replace an existing unrelated
dataset. The explicit destructive decision already has its own option, `-f`,
and the P-0 diagnostic itself says that decision must be made by a human.

I exercised the current production CLI with disposable `zfs`, `zpool`,
`mbuffer`, compressor and logger stubs. No real host or ZFS pool was accessed
and no tracked production file was changed. The fixture supplies source
`tank/src@new` (GUID 111) and existing target
`backup/tank/src@foreign` (GUID 222), with no bookmarks. This compact
reproduction is executable from the repository root:

```bash
tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT
mkdir -p "$tmp/bin" "$tmp/lock"; trace="$tmp/trace"; export trace
cat >"$tmp/bin/zfs" <<'EOF'
#!/bin/bash
echo "ZFS $*" >>"$trace"; last="${*: -1}"
case "$1" in
  list)
    case " $* " in
      *" -t snapshot "*)
        case "$last" in
          tank/src) echo tank/src@new ;;
          backup/tank/src) echo backup/tank/src@foreign ;;
        esac; exit 0 ;;
      *" -t bookmark "*) exit 0 ;;
      *" -t filesystem,volume "*)
        case "$last" in tank/src|backup/tank|backup/tank/src) echo "$last"; exit 0;; esac
        exit 1 ;;
    esac
    case "$last" in tank/src|backup/tank|backup/tank/src) echo "$last"; exit 0;; esac
    exit 1 ;;
  get)
    case " $* " in
      *" receive_resume_token "*) echo - ;;
      *" guid "*)
        case "$last" in tank/src@new) echo 111;; backup/tank/src@foreign) echo 222;; *) echo -;; esac ;;
      *" encryption "*) echo off ;;
      *" keystatus "*) echo available ;;
      *" mounted "*) echo no ;;
      *" written"*) echo 0 ;;
      *" canmount "*) echo noauto ;;
      *) echo - ;;
    esac; exit 0 ;;
  holds|hold|release|bookmark|set) exit 0 ;;
  send) exit 0 ;;
  recv|receive) cat >/dev/null; exit 0 ;;
  create|destroy) echo "MUTATION $*" >>"$trace"; exit 0 ;;
esac
exit 0
EOF
cat >"$tmp/bin/zpool" <<'EOF'
#!/bin/bash
echo "ZPOOL $*" >>"$trace"
case " $* " in *" -o health "*) echo ONLINE;; *) echo tank;; esac
EOF
for x in mbuffer zstd pigz; do printf '#!/bin/bash\ncat\n' >"$tmp/bin/$x"; done
printf '#!/bin/bash\nexit 0\n' >"$tmp/bin/logger"; chmod +x "$tmp/bin"/*
run() {
  name=$1 engine=$2; shift 2; : >"$trace"; mkdir -p "$tmp/lock/$name"
  set +e
  out=$(PATH="$tmp/bin:$PATH" LOCKDIR="$tmp/lock/$name" \
    STATS_LOG="$tmp/stats" NOTIFY_SCRIPT=/bin/true bash "./$engine" "$@" 2>&1)
  rc=$?; set -e
  printf '\n=== %s rc=%s ===\n%s\n--- trace ---\n' "$name" "$rc" "$out"
  cat "$trace"
}
set -e
run push-normal snapsend.sh -e -N tank/src backup
run push-H      snapsend.sh -H -e -N tank/src backup
run pull-H      snapget.sh  -H -e -N tank/src backup
```

Decisive output from fresh main:

```text
=== push-normal rc=1 ===
Refusing: 'backup/tank/src' already exists and shares no common snapshot ...
# trace contains no send or receive

=== push-H rc=1 ===
ZFS send -v -P -R tank/src@new
ZFS recv -F -s -u backup/tank/src

=== pull-H rc=1 ===
Refusing: 'backup/tank/src' already exists and shares no common snapshot ...
# trace contains no send or receive
```

The `push-H` final status is 1 only because the deliberately static receive
stub does not create `@new`, so the engine's post-transfer GUID verification
fails. The safety failure occurs earlier and is decisive: unlike both controls,
the actual engine has already crossed the destructive boundary and invoked
`recv -F` on the unrelated existing target.

### Failure mode

An operator can reasonably read `-H` as selecting a fuller history stream and
use it on a target which unexpectedly retained an unrelated snapshot lineage.
Instead of the P-0 fail-closed refusal, push feeds that target a full `-R`
replication package through `recv -F`. Target snapshots and descendant state
not represented by the source can be destroyed before later verification can
help. This contradicts PR #480's stated every-mode policy and the engine's own
message reserving destructive recreation for explicit `-f`.

### Required outcome

`-H` may select full-history stream contents; it must not authorize destructive
replacement of an existing target with snapshots and no common GUID/bookmark.
Push must refuse nonzero before `zfs send` or `zfs recv`, matching pull, unless
the operator made the existing explicit destructive `-f` decision. Preserve
`-H` for an absent/new target and preserve established common-base D3 backup
landing behavior. Do not redesign divergence, mirror, restore or force-full
policy.

Only `snapsend.sh` is opened by the marker above. Update the normal freeze and
twin evidence for the actual bounded diff. No production fix was made by the
reviewer.

### Notes and uncertainty

The stub reproduction proves the missing gate and destructive command
construction, not that this disposable fixture lost real data. OpenZFS defines
the `send -R`/receive behavior that makes crossing this boundary unsafe. The
P0 rating follows from invoking `recv -F` on an unrelated existing target
without the explicit destructive flag. Extend the canonical response for this
REV with the fixing full SHA and evidence; do not split the same finding into
