# REV-20260812-114 — Phase 7 slice 2 SAFE restore cleanup ownership race

## Verdict

APPROVED — F1 is resolved at `180de4c24a5e8293a88656ee2ad5bfa92fc281b0`.

Independent diff verification confirms that cleanup ownership is no longer inferred from the timing of an absence check. The receive now targets a per-attempt staging dataset under the restore namespace; that staging name is checked for pre-existence and refused rather than reused; GUID verification happens on staging; and only a verified staging dataset is promoted to the predictable public landing with `zfs rename`.

The failure path never destroys the public landing or its ancestors. Its sole cleanup candidate is the attempt's staging path, guarded to the `restore-staging-*` namespace. The original landing collision check remains only an ergonomic early refusal and no longer authorizes destructive cleanup.

The required race control is discriminating: a foreign landing is injected after the early check, promotion must fail, the foreign dataset must survive, no `destroy` may name it or a containing ancestor, and this attempt's staging must still be removed. That last assertion prevents the false-green implementation that simply performs no cleanup.

The environment-dependent primitive introduced by the correction is also covered proportionately. On real pve1 / OpenZFS 2.1.9, `zfs rename` onto an existing destination refused with the source preserved and destination untouched; rename to a free destination succeeded. A separate live end-to-end restore staged, GUID-verified and promoted an 8 MB dataset, with the GUID confirmed independently and no staging dataset left afterwards.

The reported dependency-selected evidence is appropriate to the changed boundary: `test/restore` 27/27 plus `localbackup` 57/57 and `zfsbackup` 401/401. No broad campaign is required for this ownership/promotion correction.

The residual uniqueness assumption (pid + epoch + RANDOM) is bounded by an explicit staging-exists refusal before receive, so a coincidental name collision is a safe refusal rather than adoption or destruction of an existing staging dataset.

Phase 7 slice 2 is reviewer-clean at this implementation. No further finding remains in REV-114.
