## F1 — P1 BLOCKING — `migrate-profile --profile=/path/file.conf` records the new digest without replacing that profile's installed templates

### Affected code

- `zfs-backup.sh:1283-1289` — `profile_name_of()` deliberately maps a path to the template namespace basename.
- `zfs-backup.sh:7847-7859` — the migration accepts and loads an explicit profile path.
- `zfs-backup.sh:7932-7939` — destination-template removal interpolates raw `target_profile` instead of the canonical namespace.
- `zfs-backup.sh:8060-8067` — the client record is then stamped with the requested profile and current digest.
- `test/zfsbackup/run.sh` — path resolution and edited named-profile migration are tested separately, but their combined path is not.

### Evidence

For `/tmp/mine.conf`, the supported namespace function returns `mine`, and rendering creates sections such as:

```text
[template:profile__mine__daily]
```

The removal loop instead searches for:

```text
[template:profile__/tmp/mine.conf__...]
```

An exact independent negative control on reviewed `main` confirms the mismatch:

```sh
printf '[template:profile__mine__daily]\n' |
  grep -oE '^\[template:profile__/tmp/mine.conf__[^]]+\]'
# exit 1
```

The control using `profile__mine__` matches. Because `ensure_cron_config` is additive, the already-present old templates suppress the append of edited policy. The transaction can therefore retain the old effective retention while the later record rewrite stores the new `PROFILE_DIGEST_RECORDED`. A following migration then qualifies for the "nothing to migrate" path even though the installed policy never changed.

### Failure mode

An operator edits a custom profile supplied by full path (for example `keep = 7` to `keep = 10`) and runs the documented migration command. The command may report success and permanently record the new digest while the cron configuration continues to enforce the old retention. This is silent configuration-state divergence in backup retention, not a cosmetic path bug.

### Acceptance criteria

1. Derive the destination template identity once through `profile_name_of "$target_profile"` (or the same canonical helper used by rendering) and use that identity everywhere templates are compared or removed.
2. A migration to an edited profile supplied as an explicit absolute path must replace its old template family and the real rendered cron must change from the old retention to the new retention.
3. Client records may receive the new profile digest only after the candidate containing the new effective policy has been validated and installed successfully.
4. A second invocation with the unchanged file must be the real no-op path.
5. Add a discriminating regression that fails on `b0a3a289b7bfd2a9e89b8de75c5d600e382f6c0d`; do not satisfy the test by inspecting only generated profile fragments or record text. Assert the installed/rendered retention before and after migration.

No live ZFS campaign is required if the correction stays within deterministic profile/config composition and uses the existing transactional install boundary.

## F2 — P1 BLOCKING — Restore silently accepts an incomplete comma list ending in `,`

### Affected code

- `zfs-restore.sh:823-868` — `restore_scope_resolve()` list parser.
- `test/restore/run.sh:1941` — doubled-comma refusal exists, but no leading/trailing-comma case pins the stated contract.

### Evidence

The loop is guarded by `while [ -n "$rest" ]`. For `rpool/a,`, the first iteration resolves `rpool/a`, assigns an empty string to `rest`, and exits. It never creates the empty final member that lines 838-841 explicitly say must be refused.

An independent source-level harness on reviewed `main`, with `restore_resolve_try` reduced to one unambiguous installed mapping, produced:

```text
trailing-comma accepted=1 src=backup@host:rpool/a copy=hdd/copy/a
```

The existing doubled-comma test remains green because an empty member occurs while nonempty text still follows; it does not exercise the terminal-empty case.

### Failure mode

The owner contract says the entire multi-dataset VM scope resolves before a plan is shown. A trailing comma commonly means an unfinished list. Silently turning it into a valid shorter scope can show a convincing but partial recovery plan. The public destructive multi-dataset execution door is not yet open, but accepting this grammar now bakes partial-scope behavior into the safety boundary that execution will later trust.

### Acceptance criteria

1. Reject every empty member: leading comma, doubled comma, and trailing comma.
2. Refuse before any plan output, confirmation, fence, snapshot, record change, or ZFS mutation.
3. Cover the public `--target` and `--source` paths with exact trailing-comma cases, plus a leading-comma case and the existing doubled-comma case.
4. Keep a positive control proving that a valid two-or-more-member list still resolves completely and in order.
5. The regression must fail on `b0a3a289b7bfd2a9e89b8de75c5d600e382f6c0d` for the expected reason.

No live ZFS campaign is required for the parser correction. Reassess evidence only if the fix changes planner or execution semantics beyond rejecting malformed input.
