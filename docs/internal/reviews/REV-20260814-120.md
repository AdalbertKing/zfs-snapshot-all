## F1 — P1 — residual race after the exact-set measurement

The new executor correctly enumerates snapshots and bookmarks and compares the observed set to the approved set immediately before destruction. However, it then still executes recursive rollback:

```sh
observed="$( ... list snapshots + bookmarks ... )"
[ "$approved" = "$observed" ] || return 1
...
zfs rollback -r "$RESTORE_SRC_BASE_SNAP"
```

The response itself records the remaining risk accurately: `readonly=on` does not prevent another privileged process from creating a bookmark, so a bookmark can appear after the final measurement and before `zfs rollback -r`; recursive rollback can then delete that new bookmark even though it was never displayed or approved.

That is exactly inside REV-120 F1 acceptance item 3: a bookmark appearing after confirmation but before the destructive command must be detected/refused unless an equivalent fence proves it cannot occur. A pre-command read narrows the window but does not close it.

### Required change

Remove the possibility that execution can widen the approved destructive set after the last validation. Do not rely on timing.

One acceptable shape, not a mandated implementation, is to destroy only the exact approved objects explicitly and then use a non-recursive rollback whose native semantics refuse if any newer snapshot/bookmark appeared meanwhile. Any equivalent construction is acceptable if it proves that a late object cannot be silently consumed.

Preserve the already-correct properties:

- bookmarks are represented in preview/confirmation;
- failed snapshot/bookmark listings are `unproven`, never empty;
- blocker comparison is based on local `createtxg`, not `creation` ordering;
- final verification is GUID/identity anchored and checks complete newer state;
- truthful failure classification and readonly provenance restoration remain intact.

### Required discrimination

Add a targeted fault case that injects a new bookmark specifically **after the last executor set validation and before the rollback operation**. The result must prove that the late bookmark survives and the restore refuses/partially fails truthfully without claiming an approved destructive completion.

A bounded live-ZFS proof is required only if the chosen mechanism depends on OpenZFS command semantics not already demonstrated by the existing live transcript.
