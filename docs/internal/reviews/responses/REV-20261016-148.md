# Response to REV-20261016-148

## F1 — IMPLEMENTED

### Analysis

I accept the contract as written. All six observations hold on the tree:

- an early return inside `process_dataset` would still reach `mirror_target`
  from the main loop;
- `adopt_legacy_state` runs on the function's first lines;
- the mbuffer check and the remote compression default sit outside the
  function;
- the quiesce window runs before the per-dataset function and already tells
  `QUIESCE_SNAPPED=1` apart from a safe degradation;
- the main loop's `success` record names a target;
- `test/snapget` does not exist.

So `-s` does not branch inside `process_dataset` at all. It has its own
function and its own loop, and both end before the pull path begins.

### Implemented change

`snapget.sh` only (v2.74 → v2.75), plus a new suite and the graph entries.

1. **Option and refusals** (requirement 1).
   - `-s` is added to `OPTSTRING`.
   - While `getopts` runs, every letter that only shapes a transfer is
     collected: `-e -t -M -f -F` (the named contradictions) and
     `-z -Z -g -N -l -A -b -H -i -T -w -o -x -u -U -E`.
   - Policy: **refused, not ignored.** None of these can act on a run that
     transfers nothing, and a flag that silently does nothing looks like it
     worked.
   - Kept, because they apply to source work: `-m -j -v -n -r -R -X -S -q -Q
     -L -p -k -K -O -c`.
   - A second positional argument is refused too.
   - Both refusals sit right after the usage check. That is before `-L`, the
     lock, the dependency checks and any ssh, quiesce or snapshot. So a
     contradictory command fails the same way when its relationship is paused.
   - All of this is documented in the header's `-s` entry.
2. **Dry run** (requirement 2). `-n -s` runs, per selected dataset:
   - the loopback guard (`validate_remote_host`);
   - the source pool health check;
   - the source probe.

   It then prints `PLAN=SNAPSHOT-ONLY src=<dataset>`. These are read-only
   source calls, plus the `-R` listing. It creates nothing and runs no quiesce.
   It writes no stats record and makes no `zfs`/`zpool` call on this host
   (the local `-L` marker and lock are still read). A missing source
   or a refusing peer produces no plan and rc 1. A local source with `-q` is
   refused under `-n` too, because the real run would refuse it.
3. **Real run** (requirement 3).
   - `snapshot_only_dataset` (new, section 3B) runs the same three checks and
     then `create_snapshot`. That is the existing function, which uses ssh for
     a remote source, `RUN_SUFFIX`, and `-r` under `RECURSIVE`.
   - The `-s` block in 5B sits after the quiesce window and before the `-t`
     checks. It loops over `DATASETS` and exits on its own. It never reaches
     `process_dataset`, `adopt_legacy_state`, `tune_apply`, `mirror_target`,
     a hold, a resume token, a bookmark or a progress watcher.
   - The mbuffer check and the remote compression default are skipped under
     `-s`. `-A` is refused, so autotuning never starts. Without `-s` both
     guards are true and the two steps run exactly as before.
   - The ssh multiplexer (`tune_ssh_enable`) is kept. It is connection reuse,
     not transfer tuning.
4. **Unchanged guards** (requirement 4).
   - `-L` exits before the `-s` work.
   - The peer's disabled gate (rc 93) is handled where it always was:
     `probe_dataset` returns 2, and `remote_list` reports the refusal.
   - `SSH_OPTS` comes from the same `-K/-k/-p/-O/-c` code.
   - The lock key is unchanged.
5. **Quiesce** (requirement 5): the existing block, untouched.
   - Clean window: `QUIESCE_SNAPPED=1`, and `snapshot_only_dataset` records the
     window's snapshot without creating a second one.
   - `,degrade` (rc 8): `SNAP_MESSAGE` carries the crash marker, the set is
     taken once, and the run exits 8.
   - Strict failure: rc 1, no fallback.
   - Local source: refused.
6. **Recursion** (requirement 6). The `-r`/`-R`/`-X`/`-S` expansion code is
   unchanged and still runs first.
   - A failed `-R` listing exits 1 before any snapshot.
   - A member that fails is reported with the source diagnostic. The other
     members still run, and the run exits 1.
7. **Logs and stats** (requirement 7).
   - Per dataset: `Snapshot-only: created <snap> on <host> -- nothing
     transferred, no copy on this host`, or `Snapshot-only: FAILED to create
     ...`.
   - Final line: `Snapshot-only: N source dataset(s) snapshotted on <host>,
     nothing transferred`.
   - Stats status: `snapshot_only` / `snapshot_only_failed` with an empty
     `target`. These are two new values of the existing field. The schema and
     `lib-zfs-snap.sh` are unchanged.

**Twin:** not ported, as the review allows. No twinned function moved, and
`test/twins` is 94/0 with no bless. The freeze entry in
`docs/project/ENGINE-FREEZE.md` names this REV and records "twin: NOT ported".

## F2 — IMPLEMENTED

### Analysis

Accepted. I did not run the reviewer's snippet itself. I reproduced the
defect with the new section 12b, which executes the real payload the same
way, against `snapget.sh` from `main` `0e822311`. All four failure cases fail
there: the failed or empty listing streams the payload and snapshots the
parent.

The cause is the call site. The scope was read through
`done < <(remote_list ...)`, and a process substitution drops its exit status.
`remote_list` had already printed its diagnostic and returned 2, and nothing
read that. My F1 response recorded this path as existing behaviour and left
it. It is inside the mode's contract: requirement 5 (strict quiesce
without an unquiesced fallback) and requirement 6 (a listing failure must not
become a successful set).

### Implemented change

`snapget.sh`, the remote quiesce block in 5B, one call site:

- under `-r` the listing goes into a variable through
  `_qlist=$(remote_list ...) || { log 0 ...; exit 1; }`. A failure refuses
  with rc 1, also a failure after partial output, since `remote_list` returns
  2 on any remote rc ≥ 2 or an ssh failure;
- an answer with no lines refuses too. A recursive listing always names the
  root itself. A missing dataset makes the remote `zfs list` exit 1, which
  `remote_list` passes on as success (rc 0) with empty output, so the empty
  answer is checked on its own;
- both refusals come before `quiesce_remote_run` (no payload is streamed)
  and before any snapshot or stats record. The message says nothing was
  frozen and no snapshot was taken;
- **safety change recorded:** the ordinary pull (`snapget -r -q` without
  `-s`) passes through the same block, so it gets the same refusal. Before,
  in this case it made an unquiesced recursive set under the normal name and
  returned 0. Successful listings are unchanged in both modes.

The library and `snapsend.sh` are unchanged. snapget stays v2.75, refreeze
done.
