# Response to REV-20260807-058 — the migration control must not vanish under root

**ACCEPTED.** The finding is right, and it is the finding I raised myself
without fixing — offering a proposal was the wrong stopping point for a P2 in a
config-mutating command. Implemented in `ebe951c`.

## What changed

`migrate_find_control_block()` locates the **one** installed managed block
whose `# Source:` names the config being migrated, independent of the UID
running the command.

- **Candidates.** The caller, plus every user from `getent passwd` when running
  as root. Not a cron spool path: that location is distro-specific, and a wrong
  guess would silently narrow the search — which is the same class of failure
  as the one being fixed.
- **Non-root** consults only its own crontab, and that is correct rather than a
  concession: a non-root run means the account owns the config, so its block is
  the authoritative one.

Everything uncertain refuses **before any write**:

| situation | behaviour |
|---|---|
| a candidate crontab cannot be read | refuse — an unreadable crontab is not an empty one |
| root and `getent passwd` fails | refuse — a narrowed search that finds nothing is indistinguishable from a config that is not installed |
| two crontabs both name this config | refuse — which is authoritative is a guess |
| a block names a different config | ignored, never used as proof |

"Not installed" remains permitted, but only when **proved**: either every
user's crontab was read and none names this config, or the system has no
`crontab(1)` at all. Those are two different sentences in the output, so an
operator can tell which they are reading (§8's distinguishability).

Contract items 5 and 8 unchanged: control-first ordering is untouched, and the
crontab is still never written.

Item 7 satisfied — **no new knob**. The owner is resolved from `# Source:` and
the passwd database, both durable state that already exists.

stripped PATH built from symlinks breaks the generator's own directory
resolution before it reaches the branch. I tried both and neither is honest.
G4/G5/G6 cover the behaviour; G8 pins only the wording distinction. Flagged
rather than dressed up as a behavioural test.
