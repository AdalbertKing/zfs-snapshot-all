# Response to REV-20260909-142

## F1 — IMPLEMENTED

### Analysis

Accepted. `cmd_add_client` writes `PASSIVE=0|1` and every reader in the
program tests `"${PASSIVE:-0}" = "1"` (the passive-flags composer, the
sync-mode branches, the monitor exclusion). The export composer alone tested
"non-empty and not the literal `no`", so an ordinary record's `PASSIVE=0`
became the `--passive` switch, and the importer -- which reproduces the file
verbatim by design -- turned the restored relationship passive. The
`exportrel` fixture never carried a `PASSIVE` line at all, so it could not see
the difference between "no switch" and "switch from a false value".

### Implemented change

The accepted boolean representation is the one the program already reads:
**`PASSIVE=1` is true; everything else (`0`, empty, absent, `no`) is false.**
`cmd_export_relation` emits the `--passive` switch and the `PASSIVE`
declaration only for `"1"`. Nothing in `cmd_import_relation` changes: it
replays what the file says, and the file now says the truth.
