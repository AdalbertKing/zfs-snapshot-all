# Response to REV-20260904-134

## F1 — IMPLEMENTED

### Analysis

Correct, and the diagnosis is exactly right about the class. `record_load`
assigns every field by name into the reader's own shell, so the field gate
is the only thing standing between a record and the reader's control state,
and a deny-list is not a gate: it names the variables someone thought of.
`DIE_MAIN_PID` was not on it, and neither was `SRC_PROFILE_NAME`, `PEER_MODE`
or any other uppercase global of either program. The comment above the gate
said "a field name a record may carry"; the code said "anything but these".
Recorded as E36 under R3 in `docs/internal/IMPLEMENTER-ERROR-LOG.md`.

### Planned or implemented change

**How field assignment is bounded.** `lib-record.sh` gains a second gate,
`record_field_allowed <set> <name>`, evaluated by `record_load` after the
existing shape/deny gate and before any assignment. It is a per-set list of
the names this package writes into that kind of file:

| set | names | source of the list |
|---|---|---|
| `client` | 44 (40 fixed + 4 numbered shapes) | every first argument of `write_client_field` in any revision, the stamps appended to the record (`SEED_COMPLETED_AT`, `FINAL_CATCHUP_*`, `REMOVED_AT`), `EXCLUDE_FAMILY_<n>` / `EXCLUDE_CHILD_<n>`, and the pre-rename shapes `EXCLUDE_SNAP_<n>` / `EXCLUDE_<n>` |
| `manifest` | 30 | the initiator heredoc (`PEER_SAVED_*`, `PEER_ROTATING`, the two pubkeys), the joiner heredoc (`PEER_JOIN_*`), the remote-join stamps, `PEER_JOIN_ACCOUNT_UID` / `PEER_JOIN_GRANTED_DATASETS` appends, `GRANTED_REMOTELY_BY` |
| `pause` | 2 | `PAUSED_AT`, `PAUSED_REASON` |
| `server` | 3 | `DEFAULT_TARGET`, `CRON_CONFIG`, legacy `LOCAL_USER` |

A name outside the set's list is refused with the same `die` the `PATH` case
already used, so the whole record is rejected before the offending name is
assigned (criterion 1). Numbered fields are accepted only when the text after
the last underscore is all digits. An unknown `<set>` is itself a `die`.

The lists are deliberately supersets of today's writers: every name any
release ever wrote was taken from `git log -p --all` (2026-09-04), so a
record on a host that carries `ENDPOINT_LAN_HOST` or `EXCLUDE_SNAP_1` still
loads and reaches the downstream legacy refusal that names the new spelling.
The class is closed by construction (criterion 2): an uppercase name that is
not on the set's list cannot be assigned, whatever it is called.

**Round-trip (criterion 4).** Nothing about value parsing changed
(`record_unquote` untouched; its `%q` / heredoc / literal-substitution
round-trip test still passes). The suite now also round-trips every listed
name of every set through `record_load`. Three fixtures in `test/zfsbackup`
sections 57/58 wrote `PEER_SAVED_*` into a *client* record — a shape the
package never writes — and are corrected: the stub of
`load_client_and_connection` now supplies those fields, as the real function
does from the manifest.

**Compatibility.** `server.conf` says "edit by hand if needed"; a hand may now
only set the three fields the package reads from it. Client records and
manifests on the estate carry only listed names (all writers are listed; the
2026-09-01 legacy shapes are listed too). No engine, no frozen file touched.

**One deviation from criterion 3's wording, stated.** `cmd_set_endpoint`
loads the record *before* it parses `--host`. On the fixed head the
reproducer therefore ends at the record refusal, so the single FATAL names
`DIE_MAIN_PID`, not the host; `invalid endpoint host` is never reached. The
properties the criterion is after — status 1, exactly one FATAL, never
`refusing to switch`, record byte-identical — are asserted, plus the absence
of the host FATAL, and the fatal-die path itself keeps its own control in the
`fataldie` section (a legitimate record, `bad host`, one FATAL).

### Remaining risk

A future writer that adds a field without listing it is caught by assertion 4
in CI, not on a host; a future *reader* that loads a record into a set name
other than the four dies at once. The list for `client` accepts the four
pre-U9 endpoint fields and the two pre-rename `EXCLUDE_` shapes so that old
records load; that is a wider door than today's writers need, by design, and
each of those names is data the reader already knew how to refuse or ignore.
