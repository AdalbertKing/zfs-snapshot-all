# Response to REV-20260807-056 — monitor age from dataset creation

**ACCEPTED**, implemented in `1124933`. All six contract points and every
required test case.

## Contract

1. **Uniform age rule — IMPLEMENTED.** No matching snapshot, dataset exists,
   has at least one snapshot → age from `creation`, same WARN/CRIT ladder,
   explicit and `-R` discovered alike. No config field, no inferred recursion.
2. **Container leniency — UNCHANGED.** A non-explicit `-R` descendant with no
   snapshots at all still SKIPs; pinned by B3, which also asserts the SKIP line
   itself so a future change cannot quietly turn empty nodes into monitored
   leaves.
3. **Provenance — IMPLEMENTED.** Lines caused by dataset age read
   `-- no snapshot found matching this pattern; age measured from dataset
   creation`. Under `-v` the below-warning case emits `OK` with the same
   clause; without `-v`, cron stays silent (E1 asserts empty output, not just
   rc=0).
4. **Unreadable timestamps — UNKNOWN, exit 3.** Never fed to arithmetic.
5. **The pre-existing matching-snapshot path — FIXED in the same change.** Both
   reads now go through one validated helper, `creation_epoch()`, which returns
   failure on an empty, non-numeric or `-` value. The old inline
   `$((NOW - $(zfs get ...)))` read those as 0, so a failed read became an age
   of the entire Unix epoch and a CRITICAL with a measurement nobody made.
   C2 pins both halves: UNKNOWN, and *not* CRITICAL.
6. **No production surface — CONFIRMED.** `gen-cron.sh`, `cron2conf.sh`,
   generated crontabs and deployed configs are untouched. The only runtime file
   changed is `check-snap-age.sh`; the rest of the commit is `test/monitor`,
   `test/deps.conf` and `PROJECT_STATUS.md`.

One thing not in the contract, added because the same branch invites it: a
future-dated `creation` (clock skew, a pool imported from a host running ahead)
clamps to age 0 rather than going negative. A negative age is not evidence of
freshness, but it would have sorted like it.

## `scenarios` — run, and it found one thing

`sudo ./test/scenarios/run.sh` was selected by the graph and needs root + ZFS +
mbuffer, which this workstation does not have. Run on metropolis pve2 against
`hdd/tests`: **33/34 first, then 36/36.**

The one failure was **S2**, and it was a test encoding the contract this review
replaced. It asserted `check-snap-age exits 2 when no snapshot matches at all`
using thresholds of 90m/3h against a scratch dataset created seconds earlier —
which passed only because "nothing matches" used to be an unconditional
CRITICAL. Under the new rule a seconds-old dataset is correctly OK. Not a
regression; a survivor.

Fixed in `0534961` so S2 pins **both** halves rather than the half that
happened to survive:

- CRITICAL when nothing matches and the dataset is older than crit — using a
  1m threshold against a dataset S2 has already waited 65s for, so the
  threshold is genuinely crossed rather than assumed;
- OK when nothing matches on a dataset created moments ago;
- and the provenance clause, so the end-to-end path carries the same wording
  the unit suite pins.

Worth saying plainly: this is the case the deterministic suite could not have
caught. `test/monitor` proves the branch; only the scenario proves that the
rest of the toolchain still agrees with it.
