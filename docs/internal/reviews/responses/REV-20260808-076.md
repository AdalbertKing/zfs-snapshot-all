## What was built

`lib-profile.sh` — the profile boundary, in production:

| entry point | purpose |
|---|---|
| `profile_schema_dump` | reads the field schema from `gen-cron.sh --dump-fields`; fails closed if it cannot |
| `profile_check_field` | one field: must exist for that section kind, must not be relationship-owned, no `recursive` override on prune |
| `profile_validate_fragment` | `dataset.inc` / `prune.inc`, including the no-section-header rule |
| `profile_validate_templates` | **`templates.conf`, field by field inside every `[template:NAME]`** |
| `profile_validate_dir` | the whole profile — what a runtime should call |

`test/profiles/run.sh` now calls **this** validator; its own copy is gone. Your
point 7: a test can no longer bless a rule production never executes.

## Points 4 and 6 — the schema is untouched, and the field list is not restated

The schema stays as it is. `src`/`dst` in a `[template:]` are legitimate, and
pve0 runs one in production — `[template:vm_archive]` with
`dst = hdd/backups/pve1` feeding two real dataset sections. **A template is
deployment-owned; a profile is a restricted template.** Narrowing gen-cron would
forbid deployment-owned topology in order to police profile-owned policy, which
collapses the distinction REV-073 drew. A positive control pins that such a
config still renders.

Which fields exist is still read from `--dump-fields` and never restated in the
library. Only the ownership exclusions live there, because that is a different
contract — your point 6, and the reason both REV-054 and the REV-074 follow-up
hurt.

## One thing the change surfaced

`.gitignore` here is a **whitelist**: `*` then explicit `!` per tracked file. So
`lib-profile.sh` was invisible to git until whitelisted. Since deployment is a
`git pull`, an unwhitelisted library would simply not exist on the hosts — the
runtime would fail there and only there, after passing every local suite. Fixed
by adding it to the list, not with `git add -f`.

## Remaining risk

`profile_validate_dir` is what a runtime *should* call, but no runtime exists
yet, so nothing enforces that it does. That is the residue I named in the
finding and it is unchanged: this removes the "third hand-written copy" risk and
gives no structural guarantee. B1 must call it, and that obligation is now a
reviewable line in `deps.conf` rather than a memory.
