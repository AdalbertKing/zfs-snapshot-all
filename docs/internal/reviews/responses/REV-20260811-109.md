# Response to REV-20260811-109

## F1 — IMPLEMENTED — targeted L0 execution boundary for `test/zfsbackup`

### Analysis

ACCEPTED. The smallest convenient execution unit for `test/zfsbackup` was the whole
~389-assertion / ~7-min file, so every narrow REV-102/108/110 audit correction (the
last ~13 assertions) paid the full campaign per reviewer round — disproportionate to
the risk and a delivery-throughput problem, contrary to the L0/L1/L2 policy.

### Implemented change (kept small; no framework, no coverage deleted)

1. **Cost audit** recorded in `docs/discussions/TEST-SUITE-COST-AUDIT-2026-08-11.md`:
   assertion counts, wall-clock, selection triggers, existing targeting, and the
   biggest offender (`zfsbackup`, 389 sequential, gen-cron-heavy).

2. **Targeted boundary:** `test/zfsbackup/run.sh --section retention` runs ONLY the
   source-retention audit group (REV-102/108/110, sections 57–59). Implementation is a
   single guard: everything from section 1 to section 56/92 is wrapped in
   `if [ -z "$ONLY_SECTION" ]; then … fi`; the retention group lives below the `fi` and
   is always eligible. No per-section dispatcher, no new orchestration.
   `retention`, `57`, `58`, `59`, `102`, `108`, `110` are accepted ids; an unknown id
   exits non-zero.

3. **Self-contained group (no false-green from skipped state):** the retention group
   builds its OWN profile fixture (`RP56`, copied from `profiles/default`) and its own
   `gen-cron` stub, rather than reusing `P56`/`GC5` that the skipped sections built.
   `--section retention` therefore does not depend on any earlier section running.

4. **Full-suite gate preserved:** no-argument `./test/zfsbackup/run.sh` still runs the
   whole regression suite with equivalent coverage (now 391 with the REV-110 section-59
   additions), and it runs the same retention group — one source of truth, not a fork.

### Evidence — the selector discriminates

1. `./test/zfsbackup/run.sh --section retention` → **13/13** in **~1m12s** (vs ~7 min),
   and it executes the intended REV-102/108/110 assertions including their negative
   controls (F3 bookmark-only / unrelated-prefix, F4 endpoint-mismatch refusal, REV-110
   neighbour-prefix, REV-108 without-`-e` discriminator) — a regression in the audit
   code is caught by the targeted run alone.
2. Unrelated sections are demonstrably NOT executed: targeted `PASS=13` vs full
   `PASS=391`; sections 1–56/92 produce no output under `--section retention`.
3. Self-contained: the group passes under `--section retention` even though section 56
   (which builds `P56`) is skipped — it uses its own `RP56`.
4. Full no-argument suite still passes with the same substantive assertions:
   `test/zfsbackup` 391/391.
5. `./test/impact.sh --verify` remains clean.

### Policy applied going forward (REV-109 §5)

- intermediate REV-102/108/110 fixes: L0 `--section retention` + `impact.sh --verify`;
- full affected suite(s): once, when the complete REV is marked IMPLEMENTED for
  reviewer verification (this submission ran L1);

"extract the high-churn section" guidance). Other sections keep the full-suite-only
boundary; if a different area becomes high-churn later, the same one-guard pattern
extends to it. No coverage was removed.
