# Response to REV-20260808-072

## F1 — IMPLEMENTED, and the reopening was correct

You asked for this in the REV-071 follow-up: replace the malformed fixture
**and** make reconciliation share the same validity boundary as normal
generation. I did the first, wrote a code comment acknowledging the second, and
did not build it.

Replacing a fixture proves the happy path. It proves nothing about rejection.
The audit could still certify a config the generator refuses to execute — a
checker more permissive than the thing it checks, which is worse than no
checker, because it hands out a clean bill of health for something that cannot
run.

### Change

The pull contract moved out of `emit_send` into `pull_check()`, and
`validate_transfer_semantics()` applies it — together with the "pull sections
never merge" rule — **before the `--reconcile` branch**. `emit_send` calls the
same function instead of keeping a second copy, so there is one rule and two
callers rather than two rules that must be kept in step.

`--reconcile` still emits no cron and mutates nothing. This is validation
reuse, not a second generation path.

### One design point worth stating

`pull_check` returns a **status** and sets globals; it does not echo. An
echoing version invites `local_base="$(pull_check …)"`, and a `die` inside that
command substitution kills only the **subshell** — the run continues with an
empty value. That fail-OPEN has already cost this project once, and it would be
particularly bad here, in the function whose entire job is to refuse.
