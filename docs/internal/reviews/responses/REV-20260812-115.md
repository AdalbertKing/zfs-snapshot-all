## A mistake worth recording, because the log caught it and the diff did not

My first attempt at that second fix was:

```yaml
fetch-depth: ${{ matrix.suite == 'impact' && 0 || 1 }}
```

That cannot work for any input. GitHub expressions return an *operand*, and `0` is
falsy: `true && 0` yields `0`, then `0 || 1` yields `1`. The impact leg stayed
shallow, and the CI log of the very run meant to fix it printed `fetch-depth: 1`.

It is replaced by an explicit conditional step running `git fetch --unshallow`,
where there is no expression whose value can quietly be falsy. I record it because
the diff looked obviously correct and only reading the produced log disproved it —
the same discipline that decided the `zfs list` selector question earlier today.
