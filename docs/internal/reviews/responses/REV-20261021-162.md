# Response to REV-20261021-162

## F1 — IMPLEMENTED

### Analysis

Accepted as stated. `restore_snapdev()` takes the per-dataset `flock` on a
new file description. A TERM inside `restore_snapdev_locked()` runs
`exit 130`, and the EXIT trap's `cleanup()` then calls `restore_snapdev()`
again. That second call opens another file description on the same lock file
and waits for the lock the outer, interrupted call still holds. After
`BROWSE_LOCK_WAIT` it gives up, fail-closed, and the dataset stays `visible`.
The reviewer's failure reproduces on the REV-161 blob with the new test
(see Evidence).

### Implemented change

`tui/browse.sh`:

- **The lock is re-entrant within the process.** `snap_lock` records the key
  (`SNAPLOCK_KEY`) and a depth (`SNAPLOCK_DEPTH`).
  - When this process already holds the lock for the same key, the call
    returns immediately with depth +1. It opens no second file description
    and does not call `flock` again.
  - `snap_unlock` closes the fd only when the depth reaches 0.
  - A request for a different key while a lock is held is refused. That
    cannot happen today: one session has one `SNAPDEV_DS`.
  - So the EXIT re-entry completes the restore transition under the lock it
    already owns. The holder is already gone and `orig2` is still there.
    Then the exit status of the signal (130) stands.
- **Unchanged.** Another process still waits for the lock and fails closed
  after the timeout (REV-161 case 22). The same holds for every other
  REV-159/160/161 path.
- **`test_pause` is one-shot and records the PID.** It writes `.done` before
  pausing and the session's `$$` into `.at`. The test can therefore send
  exactly one signal into the pause, and the EXIT re-entry passes the same
  point without stopping.

### Remaining risk

- A SIGKILL cannot be handled. The kernel releases the lock, the valid `orig2`
  stays, and the next session or a manual `zfs set`/`zfs inherit` restores the
  value (REV-159 path).
- No live signal test on a lab zvol. The stubbed entry-point test covers the
  lock logic.
