# Response to REV-20260810-096

## F1 — IMPLEMENTED

### Analysis

Accepted. The finding is right that REV-094 protected the four examples that
triggered it but left one part of the durable-contract goal on reviewer memory:
Layer 1 discovers every future `docs/examples/*.conf` but only requires it to
render; Layer 2's semantic assertions are hard-coded for the four names that
existed when the suite was written. So a fifth example could be added, parse,
and pass with no semantic coverage — the exact silent gap the graph edge was
meant to close.

### Implemented change

A Layer-3 meta-guard in `test/configexamples/run.sh` that makes semantic
coverage **exactly total** over the runnable example set:

- `COVERED` — an inline registry of the example basenames that carry Layer-2
  assertions;
- `coverage_mismatches <dir> <registry>` — reports `uncovered:<base>` for any
  `*.conf` with no registry entry and `stale:<base>` for any registry entry with
  no file. Empty output means the registry equals the file set exactly;
- the real-tree assertion `coverage/total` fails if `COVERED` and
  `docs/examples/*.conf` disagree in either direction.

This satisfies the acceptance criteria:

1. every current example is still rendered by the real `gen-cron.sh` and keeps
   its Layer-2 assertions (unchanged; suite 21 -> 24);
2. **adding a fifth `.conf` without registering it fails** — proven on the real
   tree: a throwaway `docs/examples/proof-unregistered.conf` drove the suite to
   `FAIL coverage/total` and exit 1, then was removed (tree unchanged);
3. **deleting/renaming an example without updating the registry also fails** —
   the `stale:<base>` half of the same guard;
4. two deterministic negative controls prove the guard mechanism discriminates,
   both on a **throwaway fixture directory / augmented registry string** so the
   real repository tree is never mutated during the committed run:
   `coverage/negctl-uncovered` (a fixture dir carrying an unregistered
   `new-unregistered.conf` is flagged) and `coverage/negctl-stale` (a registry
   augmented with a name that has no file is flagged).

The registry now has one maintenance point: add an example and its assertions,
add its basename to `COVERED` — and the guard fails loudly if that step is
skipped, rather than the coverage silently thinning.

No production code changed; the finding requested none.

### Remaining risk

Layer 2's assertions remain inline rather than per-example functions, so the
registry proves *presence* of coverage per example, not that each example's
assertions are individually non-trivial. That was out of scope for this finding
(REV-094 already pinned the four current examples' semantics, and the drift
control proves those assertions discriminate); the registry closes the "no
coverage at all" gap the finding named.
