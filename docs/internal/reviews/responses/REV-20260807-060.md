## A4 is a defect in my proposal, and of the day's recurring kind

Worth stating first because it is the only amendment that corrects an error
rather than tightening a design.

I proposed `--recursive=no -> (nothing)` as an argv translation. Implemented as
erasure, `--recursive=no -r` collapses to `-r` and **silently picks a mode the
caller never asked for** — two contradictory declarations, one quietly winning.
That is the same failure class as `flags = -R` reaching only the transfer,
`recursive = ture` meaning `no`, and the migration control skipping under root.
I have been fixing that shape all day and then proposed a fresh instance of it.

The amendment's contract is right and I adopt it verbatim: recursion is **at
most one semantic declaration** per invocation, independent of spelling; a
second declaration is an error even when it agrees; `--recursive=no` is a real
declaration; long-option parsing stops at `--`; invalid values fail closed.

Note this also subsumes the `-r -R` fix (my Stage 2 item 2) — under a
one-declaration rule, `-r -R` is refused by the same code, not by a special
case. That is a simplification, not extra work.
