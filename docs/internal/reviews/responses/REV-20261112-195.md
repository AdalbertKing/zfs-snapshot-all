## F1 — IMPLEMENTED

### Analysis

Accepted. In `snapsend.sh` the divergence check before `recv -F` required
`common_snapshot != null`. The bookmark-wins rule sets it to null, so the check was skipped. The
skip also predates #1175: the bookmark-only path, with no common snapshot at all, never had the
check either. `snapget.sh` has always taken the target head as `recv_base` when a bookmark
rescued the increment.

### Planned or implemented change

`snapsend.sh`: the check now runs when `common_snapshot != null` OR `bookmark_base` is set. On the
bookmark path `recv_base` is the target's head, the snapshot whose GUID the bookmark carries.
That is the same branch as `snapget.sh:2005`. The decision itself is unchanged:
- backup landing: D3 discards, and says so;
- `written@` query failed: refuse;
- bytes written on a sync or `-t` target: refuse;
- snapshots only, nothing written: receive without `-F`.

### Evidence

- commit: `a66aca67`
- test/snapsend `R195 F1`, both engines, `-t`:
  - a write after the bookmarked head: both refuse, and the copy keeps `auto_1 auto_2`. The push
    log says "is not a backup landing".
  - the same with no common snapshot (bookmark only): both refuse.
  - positive, no write: both continue to `auto_1 auto_2 auto_3`.
- pve9 (real ZFS), `./test/remote-suite.sh snapsend origin/fix/rev-195-bookmark-guards`: every
  R195 case PASS. Negative control on `fix/rev-195-negctl` (pve9): the write case gives `0 1` (the push rolled the write back, the pull refused), and the bookmark-only case fails too; the positive case passes on both.
- Not covered: an unreadable `written@` on the bookmark path has no case of its own. It uses the
  same `[ -z "$p0_written" ]` refusal as the common-snapshot path, which existing cases cover.

### Remaining risk

The backup-landing behaviour (D3) is intentionally unchanged.

## F2 — IMPLEMENTED

### Analysis

Accepted. A failed list made both engines send the single diff. The bookmark then moved past
the snapshots in between, for good. An incomplete list (no bookmark row, or no newest-snapshot
row) printed nothing with rc 0, which is the same answer as a proved empty interval.

### Planned or implemented change

- `bookmark_bridge_snap` returns rc 3 when the list lacks the bookmark or the newest snapshot. It
  returns rc 1 when the list cannot be read, as before. Empty output with rc 0 now means only a
  proved empty interval.

  return 1. The next run tries again.
- Explicit `-i` never asks for a bridge, so it is unchanged.

### Planned or implemented change

New `release/coverage-gate.sh`, run by `publish.sh --push` after the MANIFEST resolves and before
anything is written:
- Input: the previous release's dev revision (`RELEASE-OF` of the release checkout) and the
  shipped run-time paths (the MANIFEST list minus `docs/`, `*.md`, `LICENSE`, `.gitattributes`).
- It lists every non-merge commit in `prev..rev` that touches those paths. Ancestors of any SHA
  the ledger names (Implementation or Reviewed) are covered.
- Anything left: refuse, and name each commit.
- Exit 2 when it cannot run: no ledger, or an unknown previous or current revision. A release
  checkout without `RELEASE-OF` makes `publish.sh` refuse before the gate runs.
- There is no override flag. The way out is a submission, which then meets `review-gate.sh` and
  its named Owner acceptance.
