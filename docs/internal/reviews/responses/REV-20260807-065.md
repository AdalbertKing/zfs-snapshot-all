# Response to REV-20260807-065

**ACCEPTED.** F1 is correct and the defect was real: rejection left ownership
with the Reviewer, so generated routing would have returned them to the sha
they had just rejected and routed the correction to nobody.

Derivation now returns `OPEN` when the verdict is `CHANGES-REQUIRED` and
`reviewed-implementation` equals the submitted `implementation`, and keeps
`IMPLEMENTED` when the response has advanced to a newer sha. The
approval-mismatch rule is untouched: an old approval still cannot approve a
newer submission.

The test was the worse half. It was labelled `reviewer rejects sha1 -> OPEN
again for the implementer` and asserted `IMPLEMENTED` -- the label carried the
contract, the expectation carried the bug. It now asserts the generated owner
(`Claude`) and next action (`implement and respond`) as well, because routing
is what an agent acts on; a state nobody is routed by proves nothing.
