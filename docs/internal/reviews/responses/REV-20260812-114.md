# Response to REV-20260812-114

## F1 — ACCEPTED without reservation, and the bug was destructive

You are right, and this is the most serious defect found in my work today. The
implication I built on —

> collision refusal runs first → therefore anything present after a failed attempt
> was created by this run

— is a TOCTOU, and its consequence was not a wrong message but `zfs destroy -r` on
a dataset this run never created. Temporal ordering is not an ownership proof; I
wrote it down as though it were, in a comment that made it look reasoned.

## The correction — ownership is now a fact

Staging plus verified promotion, which is the first shape you list:

1. the receive lands in `<pool>/restore/restore-staging-<pid>-<epoch>-<random>`,
   a name unique to this attempt. Nothing else can plausibly own it, so destroying
   it is provably safe without reference to any earlier observation;
2. the guid is verified on the staging dataset;
3. only then is it promoted with `zfs rename` to the predictable public path;
4. `zfs rename` refuses an existing destination, so a landing that appeared while
   the attempt was running loses the race through ZFS's own atomicity — fail
   closed, competing dataset untouched;
5. on any failure the only cleanup candidate is this attempt's staging dataset,
   guarded by a pattern check. The landing path is never a candidate, because
   after the race we cannot prove we created it. That is the whole of F1.

### Two demotions/reversals, both deliberate

**The early collision check stays, demoted.** It is now only an ergonomic
short-circuit that avoids transferring gigabytes into an attempt that will be
refused. It proves nothing and nothing depends on it. Leaving it in while removing
its authority is the honest shape: the check is useful, the inference was not.

**Namespace ancestors are created and NOT removed.** This reverses the previous
cut, which destroyed its own scaffolding to keep retries clean. With staging,
retries are clean regardless — and ancestor removal is precisely the case where
ownership cannot be proven, since an ancestor may have been created by anyone. An
empty dataset inside the restore namespace strands nothing. The safer option
became free, so it wins. Pinned by an assertion, so a later cleanup-minded change
has to argue with a test.

## Required properties

| # | property | where |
|---|---|---|
| 1 | predictable final landing remains the public result | promotion target unchanged; live proof below |
| 2 | cleanup only touches an artifact demonstrably owned by the attempt | unique staging name + pattern guard |
| 3 | a dataset created after the check by another actor survives untouched | race control below |
| 4 | concurrent final-landing collision fails closed | `zfs rename` refusal, proven live |
| 5 | retry after an ordinary failure stays clean, no new lifecycle | staging is removed; no state, no marker |
| 6 | cleanup clamped away from pool/production | staging pattern is anchored under `<pool>/restore/` |

## Evidence

### The race negative control (stub)

Injecting a competing dataset between another process's check and its receive is
not reproducible on a live host, so this is where a stub is the right instrument.
`INJECT_LANDING` creates a foreign dataset at the final landing **after** the
collision check has passed. Asserted:

- the restore fails, with `appeared while this restore was running`;
- the injected dataset still exists;
- **no `destroy` call names it, or any ancestor containing it** — the recorded
  call list is scanned for the landing, `hdd/restore/rpool`, `hdd/restore` and
  `hdd`;
- and this attempt's own staging **is** still cleaned up, because that one it owns.

The last line matters: without it, "cleaned up nothing" would pass the control for
the wrong reason.

### Live proof of the primitive the stubs cannot prove — pve1, `zfs-2.1.9-pve1`

```
# zfs rename hdd/backuptest/rn1 hdd/backuptest/rn2     # destination exists
rc=1  cannot rename 'hdd/backuptest/rn1': dataset already exists
    source still there:      hdd/backuptest/rn1
    destination untouched:   hdd/backuptest/rn2
# zfs rename hdd/backuptest/rn1 hdd/backuptest/rn3     # destination free
    ok -> hdd/backuptest/rn3
```

Fail-closed on collision, succeeds on a free destination. Disposable datasets,
destroyed afterwards.
