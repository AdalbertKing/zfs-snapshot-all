## F1 — IMPLEMENTED

### Analysis

Accepted without reservation. The sentence that matters is the reviewer's:
`written@<latest source snapshot> == 0` **is not a fact about this medium**. I
built a fast path out of a source-side measurement and then used it to make a
decision about a disk I had deliberately not looked at.

The rotation sequence in the review is not an edge case — it is the shape the
whole feature exists for, and it was the owner's chosen model two hours before I
introduced the defect. Two weekly disks alternate; whichever is off-site is by
definition behind; a quiet source then reads as "nothing to do" for the one that
comes back. The log said there was nothing to copy, which was true of the source
and false of the disk, and on an archival dataset the off-site copy would never
have advanced again.

The reviewer's reading of my test is also right. L1 modelled one source snapshot
and one byte count and no target state at all, so `101/0` proved the branch ran
and could not tell a current medium from a stale one — the same missing
discriminator as the defect itself.

### Implemented change

The fast path now needs a fact about the MEDIUM, and one obtainable without
importing it, or the optimisation would cost the very window it exists to avoid.
Two things make that possible:

* `zpool import`'s scan prints each importable pool's `id:` — its GUID — without
  importing anything, so the disk in the slot can be identified;
* `detach` records, after a verified transfer, which source snapshot the medium
  of that GUID then held.

Skipping now requires all three facts together: the recorded GUID **is** the disk
in the slot, the snapshot it recorded is **still** the newest of the family, and
nothing has been written since.

Per the criteria:

| criterion | how it is met |
|---|---|
| 1 — per-medium, keyed by stable pool GUID, advanced only after a verified transfer | the record holds `guid=` and `snap=`; it is written in `detach`, while the pool is still imported (the only moment its GUID is readable), and only when this run both OWNED the import and was told `--engine-rc 0` |
| 2 — A/B rotation case | new `L2`; fails against `a0ed00d` |
| 3 — optimisation preserved | `L1`: a medium proved current plus a quiet source still skips without importing |
| 4 — missing, unreadable, stale, contradictory fail open | `L4` no record, `L5` unreadable, `L3` a different disk of the same pool name, `L2` behind, `L6` source not quiet — every one imports |
| 5 — no new modes or surface | nothing added but the record and its checks; `--engine-rc` is passed by the existing bracket |

A skipped run and a foreign import never advance the record: the write sits in
the branch that is only reached when `marker_is_ours` returned 0.

### Remaining risk

every disk holds. That is safe by construction — no record means import — but it
means the first run after such a loss opens the window for each medium once.

## Round 2 — F1 reopened, and F2

Both findings are mine and both are accepted without reservation.

### F1 — IMPLEMENTED (the ordering, not the record)

The reviewer is right that a conjunction across sources does not make a
first-of-several medium identity unambiguous. The per-medium record shipped in
round 1 was necessary and not sufficient: `scan_guid()` prints the FIRST
candidate and exits, and the ambiguity refusal sat AFTER the no-work fast path.
With a record matching that first GUID the gate returned SKIPPED and never
reached the refusal — two disks in the slot producing a silent skip
attributed to whichever one ZFS listed first.

The count now runs BEFORE any GUID is consulted. More than one candidate takes
the existing `ambiguous` refusal, `exit 2`, imports nothing, and cannot emit
the no-work result.

**Why my own live check passed on the defect.** I ran two `repl` media on pve9
and saw `rc=2` with the refusal — but with NO `.synced` record, so the fast
path never fired and control reached the refusal on its own. The preconditions
are what make the ordering visible; I tested the half that could not fail.

`M8` is the discriminator and needs BOTH: two media AND a current record. Each
half alone passes on the broken build.

### F2 — IMPLEMENTED

The lineage refusal ran `bounded_export >/dev/null 2>&1 || :` and then deleted
`$OURS` unconditionally, reading an ATTEMPT as a success. Ownership evidence is
now cleared only after export is known to have succeeded; on failure the marker
stays so the bracket's `detach` can finish the job, the verb still returns
non-zero, and the operator gets the same `DO NOT UNPLUG` warning every other
failed export emits.

`N1b` reuses the existing `EXPORT_FAILS` stub. `N1` covered only the
successful-export branch, which is why exact-head CI was green on the defect.
