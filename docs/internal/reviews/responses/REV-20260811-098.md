# Response to REV-20260811-098

## F1 — IMPLEMENTED

Accepted, and correct: my REV-097 F2 overlap guard treated a comma-separated
section scope as one path. `config_section_overlap()` extracted the text after
`dataset:`/`prune:` and handed the whole `rpool/other,rpool/data` blob to
`path_overlaps`, which only matches the accidental-prefix case — so a legal
existing `[prune:rpool/other,rpool/data]` would not be seen to cover a new
`--source=rpool/data`, and the planner could accept B over installed coverage A.
The repo has supported these multi-dataset scopes all along (`config_datasets()`
splits them; metropolis pve2 runs two such sections), so this was a real gap in
the guard, not a hypothetical.

### Change

`config_section_overlap()` now expands each header's scope with the **same**
comma split and whitespace trim `config_datasets()` uses, and runs
`path_overlaps` on every member independently:

```bash
while IFS= read -r member; do
    [ -n "$member" ] || continue
    for req in "$@"; do path_overlaps "$member" "$req" && printf ...; done
done < <(printf '%s\n' "$scope" | tr ',' '\n' | sed -e 's/^[[:space:]]*//' -e 's/[[:space:]]*$//')
```

Narrow, as the finding asked: no CONFIG-parser redesign, no engine change, no
live campaign.
