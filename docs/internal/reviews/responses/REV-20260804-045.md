# Response to REV-20260804-045 — Pair-scoped pause and hard-disable contract

## Scope declaration (required by the review before coding)

**Implemented scope: logical pause only.**

`pause-client` / `resume-client` / `status`. The peer-side SSH gate — and with
it `disable-pair` / `enable-pair` — is **not** implemented.

The review requires that this choice be stated rather than marketed around, so
stating it plainly: **local pause is bypassable by an ad-hoc command that omits
the relationship identity.** A hand-written `snapget.sh`/`snapsend.sh` without
`--pair-label`, and raw `ssh` with the relationship's key, both still work while
a relationship is paused. Nothing in this delivery is called `unallow`, and
nothing in it claims manual transfers are blocked.

That limitation is not left in this file where only the reviewer will see it. It
is in `README.md` as a blockquote, in `zfs-backup.sh --help`, printed by
`pause-client` on every invocation, shown by `status` on a paused client, and
asserted by a test that fails if the bypass ever silently closes without the
documentation changing with it.

## F-by-F

The review is a feature-design request, not a finding list, so this responds
per design boundary.

### §1 Do not edit cron for pair pause — IMPLEMENTED

Generated jobs carry `--pair-label <LABEL>`; pausing writes a marker file and
touches nothing else. Cron, the generated job config, `zfs allow` and
`authorized_keys` are all untouched by both `pause-client` and `resume-client`.

The label rides in the existing `flags` field of the generated `[dataset:]`
section (`emit_client_sections`). That is what keeps `gen-cron.sh` out of this
change entirely: `flags` is already a verbatim pass-through and `lint_flags()`
rejects only `-f` and `-n`. Verified end to end rather than assumed — a config
carrying `flags = -z --pair-label pve2` renders to:

```text
snapget.sh -m "automated_hourly_" -z --pair-label pve2 "zfsbackup@10.0.0.2:rpool/data" "hdd/kopia/pve2" ...
```

Gate position: after every argument check in section 5A, before the
single-instance lock in 5A2. So a paused job still reports a malformed `-X`
regex (pausing must not hide misconfiguration), and still creates no snapshot,
takes no hold, opens no ssh, starts no compressor and does not even reach
`flock`.

Result shape is the required one, `SKIPPED: relationship LABEL is paused`, plus
a second line naming `SKIPPED_PAUSED` and the resume command. Exit status is 0
so an intentional pause does not fire `notify-fail.sh` every hour; the
distinction the review asks for lives in the stats log
(`"status":"SKIPPED_PAUSED"`), never in the exit code.

### §2 Stable identity, never endpoint identity — IMPLEMENTED

The key is the client label recorded at enrolment. Nothing in the gate reads a
host, IP, port, account or `HostKeyAlias`. All datasets and all endpoint
candidates of one relationship observe one marker, because there is exactly one
marker per label.

### §3 State storage — IMPLEMENTED, with one path deviation

Path is `/etc/zfs-snapshot-all/relationships/<LABEL>/paused`, not
`/var/lib/...`. The review permits following repository convention, and every
other piece of durable state this tool owns (`clients/`, `peers/`,
`zfs-backup.conf`) lives under `/etc/zfs-snapshot-all/`, which is already
root-owned and world-readable — the latter mattering because the gate is read
by the **delegated non-root account** that runs the job.

- atomic creation: written to `.paused.XXXXXX` in the same directory and
  `mv`-renamed, so a reader sees the marker absent or complete, never partial;
- removal: targeted `rm -f` plus a non-recursive `rmdir`, never `rm -rf` on a
  path built from an argument;
- strict label validation on both sides (see the contract note below);
- root-owned, mode 0644 (world-readable, not world-writable), asserted;
- idempotent both ways;
- `status` exposes state, `paused_at`, `paused_by` and the optional `--reason=`;
- `remove-client` clears residual state for that relationship only;
- re-enrolment **fails closed**: `add-client` refuses if a marker for that label
  already exists, naming the file and the command to clear it. It does not
  silently consume or silently clear stale state, because it cannot tell an
  interrupted teardown from a genuinely different relationship reusing a name.

### §4 In-flight behavior — IMPLEMENTED

Pause prevents new transfers; it does not kill a running one. `pause-client`
reports an in-flight transfer when it finds one and says explicitly that the
current run will finish while subsequent runs are blocked.

Detection is best-effort and labelled as such in the code: it matches the label
in a running command line (`pgrep -f`), which a managed cron job carries. It
cannot see a hand-written transfer that omitted the label — the same blind spot
the whole feature has, named rather than hidden.

### §5 Do not use routine `zfs unallow` as pause — HONOURED

No grant is touched by any toggle.

### §6 Do not rewrite `authorized_keys` on every toggle — HONOURED (vacuous)

Nothing in this delivery reads or writes `authorized_keys`; there is no SSH
gate to toggle.

### Hard disable, required truth table, SSH guidance — NOT IMPLEMENTED

Out of the declared scope. The review's truth table for "local logical pause
only" is the one this delivery satisfies:

| case | behavior |
|---|---|
| managed cron command carrying `--pair-label LABEL` | blocked before SSH |
| manual command carrying the same label | blocked |
| raw manual command omitting the label | **not blocked** — asserted by test |

## Root cause / design note

There was no defect here; this is new capability. The one thing worth recording
as a root-cause-shaped observation: `client_name_valid` accepted a leading `.`
or `-`, and therefore accepted `..`. That was harmless while a client name only
became `"$CLIENTS_DIR/$name.conf"`, and stops being harmless the moment the same
string becomes a **directory component** under `$PAIR_STATE_DIR`. Rather than
carry two namespaces, `client_name_valid` now delegates to `pair_label_valid`:
one validator, so a name that can be enrolled can always be paused. Every name
this repo has enrolled or tested starts alphanumeric, so nothing legitimate is
newly refused.

## Known limitations and remaining risk

1. **Local pause is not a security boundary.** Restated because it is the single
   most important thing a reader could get wrong.
2. **Retention is not gated.** `delsnaps.sh` jobs keep running while a
   relationship is paused, so the source can prune past the last replicated
   snapshot. The existing per-target **bookmark** is what preserves the
   incremental base in that case, so a long pause is safe *provided* bookmark
   pruning (`delsnaps.sh -B`) does not also run against that relationship —
   documented in README. Gating retention on pause was not implemented because
   the review does not ask for it and it changes retention semantics; flagged
   here as an owner decision if long pauses become routine.
3. **Existing clients need one re-activation to gain the label.** Until
   `activate-client` regenerates their cron lines, `pause-client` writes a
   marker no job reads. `status` shows the marker, so the state is visible, but
   it is not effective. There is currently **no warning** that a client's
   installed cron predates the label — a reviewer may reasonably want one, and
   it would be a small follow-up.
4. **In-flight detection is best-effort** (`pgrep -f` on the label) and blind to
   unlabeled transfers.
5. **Race between local precheck and connection is not closed**, and cannot be
   by a collector-local mechanism: a job that passed the gate microseconds
   before `pause-client` committed will run to completion. The review names the
   peer-side gate as the authority for that case; without it, this remains open
   by construction.
6. **`check-snap-age.sh` does not know about pause.** A long pause will
   eventually raise ordinary staleness alerts. The review's §1 asks that
   expected staleness while paused not produce ordinary failure noise; that half
   is **not** delivered here. It is separable and was deliberately left for its
   own commit rather than folded into this one — see below.
