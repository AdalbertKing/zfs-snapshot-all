# Response to REV-20260908-139

## F1 — IMPLEMENTED

### Analysis

The finding is correct, and it is the same defect I had just finished fixing one
level up in the same file. REV-20260908-138 was about a producer whose failure
was invisible through process substitution; this is about two producers whose
failure was invisible because **nobody looked at their exit status at all**.
I wrote the primary read's guard carefully and then, four lines later, wrote:

```sh
local ubs; ubs=$(zfs get -H -p -o value usedbysnapshots "$ds" 2>/dev/null)
case "$ubs" in ''|*[!0-9]*) ubs=0 ;; esac
local nbook; nbook=$(zfs list -H -t bookmark $depth -o name -- "$ds" 2>/dev/null | grep -c . )
```

Two separate mistakes, one per line:

* the status was discarded, so a permission error and an empty answer were the
  same event, and the `case` then **normalised the refusal to zero**;
* `| grep -c .` reports on the **pipeline**, so even a status check there would
  have been the counter's, not the producer's.

`0` is a valid measurement for both fields, which is what makes this worse than
a crash: the document asserted *there are no bookmarks* and *the snapshots
occupy no space* — on the screen introduced to explain storage pressure.
Reproduced against the reviewed implementation `adda72f1` with the reviewer's
three-branch stub (snapshot list succeeds, both auxiliaries refuse):

```text
adda72f1 : "total_snapshots":1,"bookmarks":0,"used_by_snapshots":0
this SHA : "total_snapshots":1,"bookmarks":null,"used_by_snapshots":null
           + unavailable:[{used_by_snapshots, why}, {bookmarks, why}]
```

### Planned or implemented change

**The partial-read contract, stated once (criterion 3).** The families *were*
measured, so they are published; a metric that could not be read is `null` —
never `0` — and is named in an `unavailable` array with the reason. A front end
reading `.used_by_snapshots` gets `null`, not a healthy-looking zero, and can
render *not measured* instead of *nothing there*.

That is the distinction this tree already draws twice: `list-jobs` puts a block
it cannot explain in its own `unreadable` array, and `list-profiles --no-render`
omits the keys it did not render rather than emitting empty ones. Choosing a
nonzero whole-document error instead would have thrown away the family
inventory, which is the part that *was* read and the part the panel exists for.

Each producer is now run on its own, its status checked before its output is
used, and the bookmark count taken from the captured output rather than from a
pipeline:

```sh
ubs=$(zfs get -H -p -o value usedbysnapshots "$ds" 2>/dev/null); ubs_rc=$?
bmk=$(zfs list -H -t bookmark $depth -o name -- "$ds" 2>/dev/null); bmk_rc=$?
```

A non-numeric answer with `rc=0` is also treated as *not measured*, with its own
reason, rather than silently becoming zero.

The same policy governs the primary-failure document: when the snapshot list
itself cannot be read, both metrics are `null` and both are named — one policy,
both documents. The text form prints `?` where a metric is unavailable, so an
operator at a terminal sees the same distinction a front end does.

### Remaining risk

The contract change is visible to any reader already consuming `show-scope`:
`bookmarks` and `used_by_snapshots` can now be `null`. The verb is two days old,
merged today, and has no consumer outside this tree yet — the GUI it was written
for does not exist — so the change costs nothing to adopt now and would cost a
migration later.

`null` is a wider type than a number, and a front end that does arithmetic on it
without checking will produce `NaN` rather than a wrong number. That is the
intended trade: a visibly broken cell beats a confident zero.

### A note on the pattern, since this is the second one in two days

REV-138 and REV-139 are the same defect at two boundaries in the same function,
and I shipped the second while fixing the first. The lesson is recorded as E49:
when a guard is added to one producer, every OTHER producer in that function is
part of the same change — the question is not "is this call checked" but "which
calls in here are not".
