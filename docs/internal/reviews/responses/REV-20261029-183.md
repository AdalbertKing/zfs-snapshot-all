# Response to REV-20261029-183

## F1 — IMPLEMENTED

### Analysis

Accepted as reported. `cmd_job_stats` has two caches that the GUI requests with `--vol-cache`:
the snapshot listing in `_js_snaps` and the volume rows. Both chose `$XDG_RUNTIME_DIR` or
`/run/user/<uid>` and fell back to `/tmp` when that was not a writable directory. Both wrote
through the predictable name `"$cf.$$"`. A redirection follows a symlink planted at that name,
and the following `mv -f` renames the link onto the stable name. The ownership check guarded only
the read of the stable name. The volume cache (`zfs-snapshot-all-jobstats-vol.<uid>.<since>`) has
the same shape as the snapshot cache in the finding and is fixed the same way.

### Planned or implemented change

New helpers in `zfs-backup.sh`, used by both caches:

- `jobstats_cache_dir`: the cache directory is the user's runtime directory only. It must be a
  real directory (not a symlink), owned by this user, writable by this user, and with no group or
  other write bit. Otherwise there is no cache: the listing is read fresh, as cron and the digest
  always did. `/tmp` is never used.
- `jobstats_cache_write`: the temporary file is created by `mktemp` (exclusive creation) inside
  that directory, written under `umask 077`, then `mv -f -T` renames it over the stable name. A
  rename replaces a link at the destination; it does not follow it. Any failure removes the
  temporary file and leaves no cache. The command still succeeds.
- `jobstats_cache_safe`: a stable name is read only when it is a regular file, not a symlink,
  owned by this user, and has exactly one link.

What is kept: one listing per call, cache reuse for the same user, files `0600`, valid JSON output,
and each cache's own freshness rule -- the snapshot listing is invalidated when a cron log is newer
than it, the volume rows stay time-only (`--vol-cache` seconds), as before this change.

### Remaining risk

- A host where the runtime directory does not exist for root (no logind session, e.g. a `su -`
  shell without `/run/user/0`) now runs without the cache. The GUI is slower there by one snapshot
  listing per refresh. That is correct behaviour, not a regression in safety.

  pve9, in throw-away directories.
