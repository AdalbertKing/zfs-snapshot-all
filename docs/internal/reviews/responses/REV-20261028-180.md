# Response to REV-20261028-180

## F1 — IMPLEMENTED

### Analysis

Accepted as reported. The local branch of `restore_live_guard()` read the state with
`st="$(command -v "$kind" >/dev/null 2>&1 && "$kind" status "$id" 2>/dev/null)"` and refused only on `*running*`;
an empty result was diagnosed (as a log line, not a refusal) only for a remote host. A missing
CLI, a failing call or an unreadable answer therefore returned 0.

One case needs a deliberate answer rather than a blanket refusal: the disk of a guest that no
longer exists. Restoring the disk of a destroyed VM is an ordinary recovery, and there is no
guest that could be running. Measured read-only on pve10 (2026-10-28):

```text
qm status 99999   -> rc 2, "Configuration file 'nodes/pve10/qemu-server/99999.conf' does not exist"
pct status 99999  -> rc 2, "Configuration file 'nodes/pve10/lxc/99999.conf' does not exist"
qm status <existing, stopped> -> rc 0, "status: stopped"
```

That answer (rc nonzero and `Configuration file '.../<id>.conf' does not exist`, any
node path) is parsed and passes as "no such guest". Everything else that is not an
explicitly parsed `status: stopped` refuses.

### Implemented change

`zfs-restore.sh`, `restore_live_guard()`, local branch:

- no `qm`/`pct` in `PATH` -> refuse, naming the guest ID and the remedy (run as root on the
  Proxmox host that owns the guest);
- nonzero `status` -> refuse with the rc and the first line of the answer, unless it is the
  "Configuration file '.../<id>.conf' does not exist" answer above (logged, passes);
- rc 0: the first line, trailing whitespace stripped, must be exactly `status: stopped`
  (pass) or `status: running` (refuse, unchanged wording); anything else, empty included,
  refuses with the answer quoted.

The remote `pgrep` branch already mapped to `status: running`/`status: stopped` and is
unchanged; the mounted-root and `fuser` guards and non-Proxmox datasets are untouched. The
guest-state parsing uses only shell builtins, so the guard still runs under the reviewer's
constrained `PATH`.
