# Response to REV-20261004-146

## F1 — IMPLEMENTED

### Analysis

Accepted as written. The finding is the defect I hit live on pve10 on
2026-10-04, while re-creating `pve9-synchro` after PR #448.

- Seed passed. Activation then stopped with "none of the known endpoints
  answered".
- `snapget -n` printed `PLAN=INCREMENTAL` for every dataset and exited 1.
- The exit 1 came from snapget's conflict list: 144 hourlies that pve10 still
  keeps and the producer on pve9 had already pruned.
- `probe_snapget_endpoint()` counted every nonzero status as a failure before
  it read a single verdict.
- The hourly pull runs past those snapshots, because an incremental from the
  common base does not touch older ones. Only the probe failed.

The relationship has had no cron since then (state `seed_complete`), so this
response is also the unblocking step for it.

### Implemented change

Changes are limited to the probe classification, as the review asks.

`zfs-backup.sh`, new `probe_conflicts_are_history()`, consulted only when the
engine exits **1**:

- **criterion 1:** it accepts only when all of the following hold:
  - every non-`PLAN=` stdout line is `<dataset>@<snap>`;
  - that dataset is the `tgt=` of a `PLAN=` line;
  - that plan has a non-null `base=`;
  - the snapshot's `createtxg` is strictly lower than the base's.

  Both values are read from this host's own copy, with one
  `zfs list -H -p -o name,createtxg -t snapshot -d 1` per target dataset.
- **criterion 2:** it returns nonzero in each of these cases:
  - a snapshot newer than the base, or with a txg equal to it;
  - an absent, `null` or malformed base;
  - a line that is neither a verdict nor a snapshot name;
  - no `PLAN=` line at all;
  - a txg that cannot be read or is not numeric.
- **criterion 3:** the probe calls it only under `[ "$rc" -eq 1 ]`. Every other
  nonzero status fails exactly as before. After the exception, the existing
  `PLAN=` parser still runs, so `FULL-FOREVER` still stops activation. Clean
  status 0 is untouched.
- **criterion 5:** on acceptance the probe logs
  `<ds>: N older snapshot(s) exist only on this host (it keeps longer than the source) -- history, not a conflict`.
