# Response to REV-20261020-154

## F1 — IMPLEMENTED

### Analysis

Accepted as reproduced. U49 (`ec01a6aa`) chose snapget for every non-empty
`dst` without `:`. The supported bare `user@host` spelling (push-sync) has no
`:` and is a remote push; snapget refuses it at runtime as a non-local base.
The re-blessed `sync-mode.expected` carried the wrong line, so the golden
suite could not catch it: the review's point that text pinning is not a
transport contract is correct.

### Implemented change

- `gen-cron.sh` `emit_send`: snapget only when `dst` is non-empty and has
  neither `:` nor `@`. `[user@]host:path`, bare `user@host` and an absent
  `dst` stay on snapsend. No engine file changed.
- `test/fixtures/sync-mode.expected`: push-sync back on `snapsend.sh`, same
  arguments.
- `test/run.sh`: new "routing" check over every `test/fixtures/*.conf`
  rendered by the real generator. For each transfer line it derives the
  transport from the arguments (host in the source -> pull -> snapget;
  remote `dst` -> snapsend; local `dst` -> snapget; no `dst` -> snapsend)
  and compares it with the engine on the line.
