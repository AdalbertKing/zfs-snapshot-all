# Response to REV-20260811-106

## F1 — IMPLEMENTED — SOURCE family is derived from the profile's actual prune templates, not from `keep_*`

### Analysis

Accepted. `cmd_local_backup()` built the SOURCE template family by selecting only
rendered headers matching `__keep_` and textually rewriting `__keep_ -> __src_keep_`.
That is namespace-agnostic but **not template-name-agnostic**: a valid profile whose
prune templates are named e.g. `ret_hourly` matches no `__keep_` header, so the
`sed` renamed nothing and the SOURCE `[prune:]` kept pointing at the TARGET's
template identities — SOURCE and TARGET silently re-coupled, and the candidate still
validated. The comment's "works for any --profile" claim was false.

### Change

One shared, template-name-agnostic composer at the profile/composition boundary in
`zfs-backup.sh` (reused by local PUSH now and by the remote-PULL source prune under
REV-102 — no second implementation):

- `profile_prune_ref_ids <prune fragment>` — the template identities the rendered
  `prune.inc` **actually references** via `use_template`.
- `profile_to_src_id <id>` — SOURCE identity = the referenced identity with its
  **last `__` turned into `__src_`**. So the built-in default's
  `profile__default__keep_hourly` stays `profile__default__src_keep_hourly`
  (byte-identical to the accepted REV-104 output), while a custom
  `profile__P__ret_hourly` becomes `profile__P__src_ret_hourly`.
- `emit_source_template_family` — copies **each referenced template** under its
  source identity, and **fails closed** (`die`, run in the current shell via process
  substitution so the abort propagates) if a referenced template is missing from the
  rendered set — never a silent fall-back to the target's authority.
- `emit_source_prune_fragment` — rewrites the source `[prune:]` `use_template` list
  exactly (comma-list aware, no substring rewrite that could couple prefix-sharing
  ids).

The two `cmd_local_backup` call sites now call these instead of `awk .../__keep_/`
and `sed 's/__keep_/__src_keep_/g'`.

Required properties, mapped:

1. any validator-accepted, GFS-prunable profile gets distinct SOURCE/TARGET
   identities — derived from its own `use_template`, proven with a `ret_*` profile;
2. equal initial values — SOURCE is byte-copied from the selected profile's actual
   prune policy;
3. edit-one-side isolation — proven both directions for the custom profile;
4. missing/unresolvable referenced template fails closed (`emit_source_template_family` `die`);
5. built-in `default` output is semantically unchanged (same `src_keep_*` identities
   and retain values; localbackup REV-104 tests still pass);
6. remote PULL (REV-102 step 3) will reuse the same helper — the composer is
   scope-independent.
