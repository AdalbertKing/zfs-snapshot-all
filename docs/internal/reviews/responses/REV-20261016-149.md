# Response to REV-20261016-149

## F1 — IMPLEMENTED

### Analysis

Accepted as written. I had reported this as the twin remaining risk of
REV-20261016-148 F2. The cause matches the review. The push scope loop in
`snapsend.sh` read its scope through `done < <(quiesce_scope ...)`, and a
process substitution drops the exit status. `quiesce_scope` itself returns
the status of `zfs list` (it is the last command in its `-r` branch). Only the
caller lost it. So, as the review says, `lib-zfs-snap.sh` does not need to
change, and it is not touched.

I did not run the reviewer's snippet itself. I reproduced the defect with the
new section 14 against `snapsend.sh` from `main` `86809fb9`. The six refusal
cases fail there, and both controls pass.

### Implemented change

`snapsend.sh`, the local quiesce scope loop in the main quiesce block, one
call site:

- the scope goes into a variable through
  `if ! quiesce_list=$(quiesce_scope "$dataset" "$RECURSIVE"); then ... exit 3`.
  A failed `zfs list -r` refuses, also one that failed after printing part of
  the list;
- an empty answer refuses too. A recursive listing always names the root
  itself;
- both messages name the dataset and say that no snapshot was taken and
  nothing was sent: "Quiesce: the guests under '<ds>' could not be listed on
  this host (zfs list -r failed) -- refusing ..." and "... returned nothing
  (not even the dataset itself) -- refusing ...";
- **exit 3** is the code every other push quiesce refusal uses (for example
  `quiesce_prepare`'s strict refusals). The refusal sits inside the block that
  has already installed the EXIT trap `quiesce_thaw_all`. So if earlier roots
  of the same run already prepared guests, the existing cleanup path undoes
  that (acceptance 1);
- the refusal comes before `QUIESCE_SNAPS_BY_POOL` gets the parent. The run
  therefore never reaches the snapshot, the stats record or the transfer.

Successful listings feed the same loop as before through `<<<`. Freeze/thaw,
delegation, transfer, P-0, naming and successful discovery are unchanged.
snapsend stays v2.76. Refreeze done.

**Twin:** this is the port of snapget's REV-148 F2. Both engines now refuse
a failed or empty `-r` quiesce scope listing. Each uses its own quiesce
refusal code: exit 1 for pull, exit 3 for push. No twinned function moved,
and `test/twins` is 94/0 with no bless.
