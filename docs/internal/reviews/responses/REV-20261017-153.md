# Response to REV-20261017-153

## F1 — IMPLEMENTED

### Analysis

Accepted as reproduced. The branches PR #601 added (and the hand-over
comparison before them) told local from remote with `*@*:*`. The supported
transport is `[user@]host:dataset` with an optional account (gen-cron `src`/
`dst`, `snapsend.sh` dst, the engines' `parse_remote`), plus `snapsend.sh`'s
sync dst, a bare `user@host`. A host-only source therefore read as LOCAL. A
beside-restore was given a collector path, and a host-only push copy was
planned "local push" and reached the pause.

### Implemented change

`zfs-restore.sh`:

- `restore_addr_machine <address>` prints `[user@]host` and returns 0 for a
  remote address, using the engines' rule: remote when there is a `:` and
  nothing before it contains `/`, or when the address is a bare `user@host`
  with no `:` and no `/`. It returns 1 for a local path. `restore_addr_host`
  is the same with the account dropped.
- `restore_dest_peer`: any remote spelling names the machine (`pve9` from
  `pve9:hdd/home`), so `restore rel rel --onto=…` with a host-only source keeps
  that host (`pve9:hdd/restore/home`). Everything after that is the existing
  remote path: `restore_one` treats `host:ds` as remote and runs the
  established ssh and grant checks. Only a genuine local relation (sources are
  paths) gets the local-beside answer. A different local relation is still
  refused.
- `restore_relations`: a `dst` in any remote spelling is planned as a
  "remote push", with the copy at `<dst>/<ds>`. The sync `dst = user@host` is
  planned with its copy at `user@host:<ds>`, the same path on that host.
- `restore_run_scope` (the PUSH refusal before the pause) and the planner's
  copy-snapshot line use the same classifier.
- `restore_report_handover` compares HOSTS through the classifier. A missing
  account does not erase the machine (`pve9:` and `root@pve9:` are one host),
  and a local path has none.

No engine or frozen file changed.

### Remaining risk

- A local dataset whose name has a `:` with no `/` before it (for example a
  pool-level name with a colon) reads as remote. That is the engines' own rule
  (`parse_remote`), applied here on purpose so that the two never disagree.
- The nonblocking guidance (the preflight rc 2 wording, the mirror
  "next run" sentence) is unchanged in this fix.
- No live host was used; the reviewer's reproductions are read-only, and so
  are these tests.
