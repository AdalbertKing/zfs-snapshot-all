## F1 — `--join` executes pairing-package configuration as root — IMPLEMENTED

### Analysis

Accepted, and confirmed in the source before any code was written:

```
deploy.sh:1550  tar -C "$workdir" -xzf "$JOIN_PACKAGE"
deploy.sh:1553  . "$workdir/peer.conf"
```

The finding is correct on every point. `source` executes; the archive was
unpacked before anything inspected it; and the feature's whole premise is that
the two hosts do not trust each other yet, so the package is attacker-controlled
by definition.

One thing the review does not name, found while fixing it: `--join` writes the
values it read into `/etc/zfs-snapshot-all/peers/<label>.conf`, and *that* file
is read back with `.` by later runs. A value carrying a newline would therefore
inject whole lines into a file that is sourced later, by a different invocation.
Rejecting control characters is what closes it; quoting the manifest writes
alone would not have.

### Implemented change

Commits `5ef323c`, `d4e65fe`, `162eebb`.

- `assert_package_members` — exactly two members, exact names, once each,
  checked from `tar -tzf` **before** extraction. This single check covers
  traversal, absolute paths, duplicates and extra payload.
- Extraction with `--no-same-owner --no-same-permissions` into a `0700`
  directory; each member must then be a regular file and not a symlink. A member
  name containing a newline could split into two lines that *look* like the
  expected pair, and is caught here rather than by the name check.
- `parse_peer_conf` — line-based, allow-list of the seven keys. Rejects unknown
  keys, duplicates, non-assignments, and any value containing a quote,
  backslash, `$`, backtick or control character. One optional layer of double
  quotes is stripped, as `--pair` writes for `PEER_CONF_DATASETS`.
- `validate_peer_conf` — role `pull|push`, as `root|delegated`, port `1..65535`,
  account against a POSIX username grammar (it is passed to `useradd`), target
  and every dataset against a ZFS name grammar, label against a path-component
  grammar. `role=pull` with an empty dataset list is refused.
- `validate_pubkey_file` — exactly one non-blank record, which must **start**
  with a key type. That is what refuses a `command="..."` options prefix.
- All of it completes before the first persistent change; the point is marked in
  the code. A rejected package leaves no temporary directory.
- The initiator label is no longer sanitised with `tr`. A label that needs
  sanitising is now a package to refuse, not one to quietly repair.

`--join-check=PACKAGE` was added: it validates a package, prints what it
declares, changes nothing and needs no root. It is useful on its own — look
before running `--join` as root on a host that trusts nobody — and it is what
makes this testable without a test whose own mistakes would create real accounts
on real hosts.

### Evidence

- suite: `./test/join/run.sh` — 34 checks, no root/ZFS/network. Registered in
  the test graph as `[suite:join]`.
- Covers every case the review lists: `touch`-payload and command substitution,
  `../../etc/cron.d/payload`, absolute paths, symlink member, duplicate member,
  extra member, unknown and duplicate keys, invalid role/account/dataset/target/
  port/label, two public keys, `authorized_keys` options prefix.
- Every rejection case also asserts a canary file was **not** created.
- One positive case asserts a legitimate package is still accepted and
  normalises to the same values `--pair` wrote — without it, "reject everything"
  would have scored full marks.
- The symlink case `SKIP`s where the platform cannot create symlinks rather than
  passing for the wrong reason, which is what it did when first written.
- live, pve1 → pve2 (192.168.28.9 → .8): a real `--pair` package passes
  `--join-check` **as a non-root account**; a real `--join` completes; the
  resulting pull transferred 2 datasets with both GUIDs matching the source.
- graph: `./test/impact.sh --verify` clean, `test/impact/run.sh` 20/20,
  `deploy.sh --check-only` rc=0 on a host with and without a delegated account.

Two defects in the first version of this fix were found by **running** it on a
real host, not by reading it, and are fixed in `d4e65fe`:

- the cleanup trap referenced a function-local variable and fires at shell exit,
  where that name no longer exists — under `set -u` it died and removed nothing.
  "A rejected package leaves no temp dir" was false for every rejected package;
  two were sitting in `/tmp` on pve2. All 32 assertions passed while this was
  true, because they checked what the code said rather than what it left behind.
  The suite now counts temp directories and treats a dying trap as a failure;
  that assertion is verified to fail against the previous commit.
- `pubkey_fingerprint` was defined below the block that moved above the root
  check, so `--join-check` printed an empty fingerprint.

### Remaining risk

- Package **authenticity** is unchanged and out of scope for this finding: safe
  parsing does not tell you who sent the archive. Transfer is still manual and
  out-of-band, as designed.
- The account grammar is POSIX-conservative (`[a-z_][a-z0-9_-]{0,31}`). A site
  using uppercase or longer account names would be refused. No such site exists
  here; raising it is a one-line change if one appears.
- `--join-check` and `--join` duplicate the unpack-and-validate preamble. A
  shared helper would be tidier; two call sites felt cheaper than the indirection
  and both are covered by the suite.

Status: `IMPLEMENTED`, not `CLOSED` — technical closure is the reviewer's.

## F4 — production hosts follow mutable `main` — ACCEPTED as a risk, PARTIALLY IMPLEMENTED

The evidence is correct and this session is a live demonstration of it: roughly
a dozen commits reached six root-executing deployments within the hour, with no
gate, including one whose cleanup trap was broken.

**The delivery model is not changed, by owner decision** — which this finding
itself says only the owner can make. Two reasons, both concrete rather than
preference:

- pinning production to a tag costs a manual step on every fix, and this fleet
  is administered from a phone;
- the alternative to pulling is hand-copying scripts, which has already broken
  `--ff-only` permanently on one host here.

The recommended default (production tracks a tag, `main` stays a development
branch) remains the better shape for a fleet with more hosts or more
contributors, and is recorded as such rather than dismissed.

**What was not waived is the other half**, implemented in `75bf956`:

- the hourly pull now records the revision it is LEAVING before it moves, so a
  one-command rollback always exists;
- every run, `--check-only` included, reports the active revision and subject,
  whether the checkout is dirty, and how far behind the last fetched
  `origin/main` it is.

The dirty-worktree warning is the part that earns its place: a local
modification makes every future `--ff-only` pull fail, and that failure is
otherwise invisible — the host stops updating while everything still looks
healthy. This project has had exactly that, on one host, permanently.

An existing pull line is replaced rather than appended to (two would both run),
and the replacement lands after `gen-cron.sh`'s `# END zfs-backup-managed`
marker, so the next `--install` cannot wipe it. Verified on all four hosts:
one pull line each, line count unchanged, outside the managed block.

Not implemented, and honestly out of scope for a decision to keep tracking
`main`: a smoke gate before switching revision, and a pinned default.

Status: risk `ACCEPTED` by the owner; visibility and rollback `IMPLEMENTED`.

## F5 — no automated PR gate — ACCEPTED, IMPLEMENTED with one departure

`.github/workflows/tests.yml` (`552b586`) runs on every push to `main`, every
pull request, and on demand: `bash -n` over every *tracked* shell script
(`git ls-files`, so a stray file in a working copy cannot fail somebody's CI),
`./test/impact.sh --verify`, and the six suites whose `deps.conf` entry says
`needs = nothing` — gencron, impact, quiesce, tune, statekey, join. Permissions
are read-only.

First run green: 9/9 jobs, including `join` on Linux where the symlink, FIFO,
device and oversize cases all execute rather than skipping.

**The departure:** it does not gate merges and does not require a PR. Work lands
directly on `main` here by owner decision (see F4), so a gate that blocked that
would be removed or worked around. Running on push is the half that pays for
itself — learning that something broke beats being stopped before it can break.

The last acceptance criterion is honoured explicitly: a final job prints the
obligations a green tick does NOT cover, reading them from `impact.sh --all`
rather than restating them, so it cannot drift from the graph. A comment in a
YAML file would not have been visible; a job in the run list is.

`.gitignore` needed `.github/` added — it is deny-all-plus-allow-list, so the
workflow would have been created on disk and silently not committed, exactly as
happened with `docs/` earlier the same day. `.gitattributes` now pins
`.github/**` to LF, because the `run:` blocks are bash and a CRLF checkout ends
every line with `\r`.

Status: `IMPLEMENTED`, with the PR-gate criterion consciously not met.
