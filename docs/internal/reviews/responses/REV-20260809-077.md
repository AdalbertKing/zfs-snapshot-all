# Response to REV-20260809-077

## F1 — ACCEPTED. Fail-open, in the function I had just called the boundary

I wrote:

```bash
if   [ -f "$dir/templates.conf" ] && ! profile_validate_templates ...; then rc=1
```

which reads as *"if it exists and fails, complain"*. A **missing** artifact
therefore returned success from the production boundary, and an empty directory
validated clean — in the function whose own comment says it is what a runtime

Worse in context: I had spent REV-076 arguing that a rule split between a test
and production is the defect, and then shipped a boundary that quietly delegated
completeness to whoever called it.

## Why it stayed invisible

The suite checks separately that the shipped fixture's three files exist. That
is a **different property**: it protects , not the API. B1
would call  for whatever profile it loads and inherit
nothing from that check — the second-piece-of-grammar-outside-the-boundary shape
REV-076 removed.

The tell was mechanical: after the fix, the suite still read **33/33**. An
unchanged count after a real behaviour change means nothing exercises the path.

## Change

Completeness is checked in the boundary, before anything else:

```bash
for f in templates.conf dataset.inc prune.inc; do
    [ -r "$dir/$f" ] || { PROFILE_ERR="$dir/$f is missing or unreadable -- a profile is exactly ..."; return 1; }
done
```

Then each artifact is validated in turn, failing on the first violation. The
error names the path, so the operator is not left guessing which of the three.

Not moved into B1, per your instruction and for the reason you gave: a profile
**is** exactly those three artifacts — Slice A's definition, not an open-ended
directory format — so the structural contract belongs to the same owner as the
field contract.
