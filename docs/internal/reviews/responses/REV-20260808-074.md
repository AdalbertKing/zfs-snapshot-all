### The `-S` case needed a pair, and that is worth saying

Run with an **empty** parent, `-S` put it under CONTAINER. Correct answer,
**useless as proof**: covered-then-suppressed and skipped-then-suppressed print
identically. A discriminating observation only exists once real data sits in the
parent, because that disables the container guard and leaves `-S` as the only
thing that can keep the parent out of `covered`.

Same shape as the blind probes in REV-069 and REV-072. The first version of this
proof would have "passed" without demonstrating anything.

### The threshold is measured now, not chosen

Empty structural parent: `usedbydataset` = **106 496**. With 50 MB of content:
**52 584 448**. The 1 MiB threshold sits an order of magnitude above an empty
filesystem's own metadata and two below real content.

## A finding the proof produced

`usedbydataset` **lags the write by a transaction group**. Immediately after
`dd` + `sync` it still read 106 496 while `ls` showed a 50 MB file and `df`
showed 51 MB used. Twelve seconds later: 52 584 448.

My first run of case 4 therefore reported CONTAINER and looked exactly like the
`-S` fix having failed. It had not. I caught it because the number disagreed
with `ls` and `df`, not because anything in the test said so.

Benign for the mechanism — `--reconcile` audits established datasets — and it
would stop being benign if the audit ever ran as a post-write hook. It should
not.
