# Response to REV-20260807-066

**ACCEPTED.** The finding is right and it is the mirror image of the lesson this
project learned the hard way today.

We already knew a large green count can be weak evidence. REV-066 states the
other half: **a live-host run on a path that cannot discriminate the change is
not stronger evidence, only more expensive.** My `Wspólne` section applied one
cascade to three independent changes, which is exactly the cost pattern we just
decided to stop.

## What changed

Verification is now asked per change, from one question: *what environment
property does this actually depend on?*

| | depends on | what discriminates it |
|---|---|---|
| 2.1 suffix | real snapshot timing | **only real ZFS** |
| 2.2 one declaration | nothing environmental -- argv normalisation | **nothing**; a host adds no evidence |
| 2.3 long options | whether the **installed** copy understands the spelling | **one** delegated invocation |

So: 2.1 keeps exactly one real-ZFS scenario, because run-level correlation
exists nowhere else. 2.2 gets **no** ZFS and **no** host run -- `-r -r` and
`--recursive=ture` behave identically on a production host and here, so a live
run would prove only that ssh works. 2.3 gets one delegated invocation, because
a local pass cannot settle whether the *deployed* file accepts the new spelling.

Generated-cron byte identity is now conditional on the graph selecting
`gen-cron.sh`. If that file is untouched I do not rerun `cron`/`cron2conf` to
prove an unchanged file did not change.

Truly common: `./test/impact.sh --verify`, because it validates the graph
itself. Escalation beyond that is conditional on blast radius or a graph edge
this document did not anticipate -- not on caution.

## Acceptance criteria

- [x] each of 2.1/2.2/2.3 maps to its own minimal automated, negative-control
      and live evidence;
- [x] every live/real-ZFS requirement is attached to a property that
      environment can actually discriminate;
- [x] `test/cron` / `test/cron2conf` are no longer unconditional;
- [x] escalation is explicitly conditional, not default;
- [x] negative controls report both counts.

Behaviour contracts 2.1/2.2/2.3 are unchanged, as the review left them standing.
