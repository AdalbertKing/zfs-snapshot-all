# Response to REV-20260811-101

## F1 — IMPLEMENTED

Accepted. `cmd_local_backup()` held a single scalar `source`, its character check
rejected the comma so the canonical `--source=a,b,c` form could not even be
expressed, and repeated `--source=` flags did silent last-one-wins — an operator
could believe two roots were protected while one was discarded. That is the
opposite of the EXPLICIT-SOURCE-BEATS-DISCOVERY WHAT contract.

### Change — reduction-oriented, no source-selection framework

The parser now builds an explicit **root list** and validates it as a set before
any composition:

1. `--source=` accepts the canonical comma list; repeated `--source=` flags are
   **accumulated into the same set** (the cheap normalization the finding allows),
   so `--source=a --source=b` == `--source=a,b`. No silent last-one-wins.
2. Each value is split on commas, trimmed (same normalization `config_datasets`
   uses), and exact duplicates are collapsed to one — never duplicate ownership.
3. Every root is validated for a plain name, LOCAL-only, and existence via
   `zfs list`; **one missing or invalid root refuses the whole request** and
   produces no partial candidate.
4. Parent/child (or equal) overlap **within** the explicit set refuses; so does
   any root overlapping the target (self-reference). No invented precedence.
5. Composition emits **one independent `[dataset:root]` per root**, all sending
   to the target, plus one recursive `[prune:target]` ladder over the target.
   gen-cron merges same-policy datasets into one comma-joined send line — the
   established multi-dataset shape (`fixtures/tiered.conf` golden shows
   `"tank/a,tank/b"`), so the generated cron carries every root.
6. REV-097/098 properties are preserved unchanged: additive composition over the
   existing CONFIG, the shared fail-closed guard, `config_section_overlap` now
   checking **every** root and the target against installed scalar/comma-list
   scopes, the bare canonical `--source/--target` entrypoint, and read-only
   planning (no install).

No frozen engine touched; no include/exclude or precedence DSL.

### Remaining risk / scope

Still planner-only, read-only. The multi-dataset comma-joined send is gen-cron's
existing shape and snapsend's existing input; proving it end-to-end at RUN time
(the actual transfer of several roots to one target) is a slice-2 / live-host
obligation, as the finding scopes. Slice 2's installer will land on this set-based
input path rather than the old scalar one.
