# Response to REV-20260810-094

## F1 — IMPLEMENTED

### Analysis

Accepted in full. The finding is correct and the contradiction it names is real:
`DELIVERIES.md` called the slice "docs only, no graph impact" while
`ACTIVE-WORK-PLAN.md` recorded the same files as a known test-hygiene gap. Under
this repository's impact discipline those cannot both stand. Once a checked-in
config is promised runnable against the production generator and operators are
told to copy and re-run it, the file carries a contract edge —

`gen-cron.sh grammar/rendering -> docs/examples/*.conf -> documented behavior`

— and an edge that `impact.sh` cannot see is exactly the class of gap the graph
exists to close. The examples were valid at `5df7452`; the defect was that their
validity could rot silently after a future generator change while `impact.sh`
stayed green.

### Implemented change

One focused suite plus the three dependency edges the finding asked for, no
broader campaign:

1. **`test/configexamples/run.sh`** renders every `docs/examples/*.conf` through
   the real `gen-cron.sh -c` (deterministic env, same idiom as
   `test/cron2conf/run.sh`). Layer 1 holds every example — including any future
   one — to "it parses (exit 0)". Layer 2 pins the semantic line properties each
   current example exists to teach, on the generated command, not exit status:
   - independent-tiers: `-H24` and `-D14` are two independent counts **and no
     `-G`/GFS ladder is emitted**;
   - selective-quiesce: `-q agent` / `-q sync` on the right datasets, the plain
     dataset has no `-q`, and the differing `-q` keeps them **three unmerged
     send lines**;
   - short-local-long-store: local `-H48` self-prune vs store `-D90`;
   - manual-prune: `-H72`/`-W12` recursive store prune, the `-B ... -d30`
     bookmark line, and the monitor-only carrier — a `check-snap-age.sh` line
     for `backup/store/hot` **with no second `delsnaps` line on that scope**
     (the race `prune = no` exists to prevent).

2. **Dependency edges in `test/deps.conf`**: `configexamples` added to
   `[file:gen-cron.sh]` suites; new `[file:docs/examples/]` -> `configexamples`
   (a directory-prefix edge, same mechanism as `[file:profiles/]`); new
   `[file:test/configexamples/run.sh]` -> `configexamples` self-select; new
   `[suite:configexamples]`.

3. **Negative control** (finding point 4): in-suite, the run mutates a runnable
   example (`keep 24 -> 99`) and asserts the pinned `-H24` assertion no longer
   holds — so a green run is not vacuous. Additionally verified out-of-band that
   the whole suite exits **rc=1** when a real example drifts, then restored the
   file unchanged.

No production code was touched, as the finding anticipated.

### Remaining risk

The semantic assertions match on substrings of the generated command, so a
future intentional rename of a flag surface (e.g. `-H`) would require updating
both the example and the assertion — which is the point: the edge now forces
that update to be a deliberate, tested act rather than silent rot. Real
ZFS/crontab/SSH was correctly not required; the finding is confined to the pure
generator boundary.
