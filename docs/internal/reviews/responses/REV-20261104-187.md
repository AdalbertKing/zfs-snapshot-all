### Planned or implemented change

- `zfs-backup.sh`: `snaponly_cfg_tiers` (tiers in file order, managed sections only),
  `snaponly_show_tiers_json` (keep/retain/mechanism from `snaponly_src`, schedule, quiesce, prefix,
  pattern and monitor fields from `snaponly`), `snaponly_tiers_apply_ops`. `show-tiers` on a
  snaponly relation prints `"mode":"snaponly"` and the same `target` shape as a copy relation;
  `set-tiers` accepts `--tier`, `--keep=N`, `--retain`, `--quiesce`, `--send-schedule`,
  `--prune-schedule` and rewrites ONE field per op in its section (`set_or_remove_section_field`),
  so hand edits of other fields and tiers stay as installed. Changing the tier set or the method
  (`--add-tier`, `--drop-tier`, `--method`) is refused with "use the template action
  (edit-relation NAME --profile=P)"; `keep=0`, an unknown tier, an op without a tier refuse with
  "nothing was changed" and the working copy removed. The rest of `set-tiers` is shared with copy
  relations: `gen-cron` validation of the working copy, the activation proposal, then the atomic
  replace-and-install -- refusal, cancellation or a failed generator leaves the installed config
  and crontab as they were.
- `tui/edit-relation.sh`: the "Harmonogram i retencja" row opens the template menu as for a copy
  relation; its "Ręcznie..." entry now runs `harm_flow` for snaponly too (title "MIGAWKI NA
  ŹRÓDLE"), where it used to save `relacja-<NAME>` and run `edit-relation --profile=`. The snaponly
  template step and the hidden-template restore (`restore_hidden`) are removed. Picking a template
  in that menu ("Użyj szablonu", `edit-relation --profile=`) stays the one named action that reads a
  profile and shows its plan before WYKONAJ.
- What still reads `relacja-<NAME>`: the edit window lists profiles on open (the menu and the
  current-profile label) and fast prune (U136) reads its base from the `relacja-<NAME>-fastprune`
  marker. Neither feeds the retention change above; the show-tiers/set-tiers path reads no profile.
- Creation: the wizard may still write `relacja-<NAME>` as its draft for the first render; a
  missing, stale or altered file afterwards does not change a retention edit.
