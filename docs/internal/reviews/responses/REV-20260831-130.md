# Response to REV-20260831-130

## F1 — IMPLEMENTED

### Analysis

The finding is correct as written, and it was reached from the same evidence
here: the defect was surfaced independently while splitting `-E` out of the
`flags` sack for the Profiles stage, with `-X` as the control, and reported in
the draft PR the Reviewer was reading. The two accounts agree on the mechanism,
the failing invocation and the blast radius, so there is nothing to dispute.

One correction to the REV's premise, in the implementer's favour rather than
against it: the drift is not only `E:`. `t` is missing from the pre-pass
`OPTSTRING` too. It is harmless — `t` takes no argument, so both grammars give
`opt_takes_arg` the same answer — but it is the same drift, and it is what
decided the shape of the fix.

### Planned or implemented change

**The fix is a deletion, not an addition.** Adding `E:` to `OPTSTRING` would
satisfy acceptance 1 while leaving the actual defect in place: two literals
describing one grammar, with nothing keeping them in step for the next letter
somebody adds. That is exactly how `E:` came to be missing, next to a comment
which states in as many words that a hand-kept list drifts and that the drift
would be silent.

So `while getopts` now consumes `$OPTSTRING` in both engines, and the variable
carries the string getopts was already parsing with:

```sh
# before -- two literals, disagreeing about E: and t
OPTSTRING="m:ezZgNl:v:rRniHj:uUfwVp:k:Aq:T:o:x:c:b:FX:SK:O:L:"
while getopts "m:ezZgNl:v:rRtniHj:uUfwVp:k:Aq:T:o:x:c:b:FX:SK:O:L:E:" opt; do

# after -- one string, and the disagreement is no longer expressible
OPTSTRING="m:ezZgNl:v:rRtniHj:uUfwVp:k:Aq:T:o:x:c:b:FX:SK:O:L:E:"
while getopts "$OPTSTRING" opt; do
```

No option gains or loses an argument: the value is the one the final grammar
already had. `opt_takes_arg` is the only other consumer, and it is the function
whose wrong answer produced the finding.

`gen-cron.sh` had the same omission in its own getopts-equivalent walker
(`FLAGS_ARG_LETTERS`) and is fixed on the same branch, separately. The REV is
right that the generator correction does not resolve this finding; they are two
copies of one mistake in two programs, and both are closed.

### Remaining risk

Low, and named rather than waved at.

**What the fix cannot regress:** nothing this package generates was ever
affected. `gen-cron.sh` renders short options only, so no cron line on the
estate can carry the shape that breaks. The defect was reachable by an operator
typing both spellings together, and by anything outside this package driving
the engines.

**What is not covered:** the `-E` grammar is now consistent between the
pre-pass and `getopts` by construction, but neither is checked against the
engines' `--help` text, which lists allowed options as a third hand-written
literal. That list is prose today and a drift there is cosmetic rather than
functional, so it is left alone rather than fixed in a frozen file for tidiness.

**A note for the record, since it is the kind of thing this REV exists to
catch:** the implementer's own regression covered three of the five acceptance
criteria and the gap was not noticed until the criteria were read one by one
against the assertions. The two missing cases are added above. The lesson is
the one already in section 1 of the error log as R12 — a pass proves the shapes
it ran, and the report must name them.
