### A fleet condition the second host exposed

Running this on more than one host mattered. On pve2 the first attempt still
failed — not on my new lock, which was created correctly, but on **lib-cron's**
per-user lock, left `0644 root` by an earlier root-side run.

Survey of all four hosts found the same latent state on three of them:

| host | `lib-cron.zfsbackup.lock` before |
|---|---|
| pve0 | 664 (fixed during Stage 0) |
| pve1 11.11 | **644** |
| pve1 28.9 | 664 |
| pve2 28.8 | **644** |

Repaired with exactly the one-line fix the error message prescribes. That
mechanism worked as designed and cost one command per host — a good contrast
with the message F1 is about.

**Left open deliberately:** whether `deploy.sh` should ensure lock-file modes so
this cannot be latent on a fresh host. `lib-cron` refuses rather than chmod'ing
a foreign file on purpose, and changing that is a design decision, not a bug
fix. Filed as a thread.

## F2 — PROJECT_STATUS staleness — IMPLEMENTED (`e8ecde3`)

The document is refreshed to the post-Stage-0 state and VM 104 is out of the
open-gap summary.

More to the point, the required prevention is in place. `./test/impact.sh
--verify` now reads an explicit machine marker:

```
<!-- status-covers-commit: <sha> -->
```

and fails when any commit after it touches a file that declares the
`project-status` obligation. The watched set comes from `deps.conf` itself, so
the two cannot drift apart. Per A2 it is keyed off the marker and never the
prose — rewording the Polish introduction cannot silently disable it.

**Positive control, not just a green run:** moving the marker back to `123fca8`
makes `--verify` report

```
  STALE. These behaviour-changing commits landed after the marker (123fca8):
    f26a205 gen-cron: the install lock must live where the account can reach it
```

One bug in the mechanism, found and fixed before shipping: the marker was first
extracted with a `sed` backreference, which was eaten while generating the file
and left the check reading an **empty** marker — reporting "not a commit"
instead of "stale". A freshness check that fails for the wrong reason is one
nobody trusts twice. It now takes the whole matched line and strips a fixed
prefix and suffix.
