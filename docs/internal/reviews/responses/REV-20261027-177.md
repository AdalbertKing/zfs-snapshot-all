# Response to REV-20261027-177

## F1 — IMPLEMENTED

### Analysis

Accepted as reported. `rel_panel_pairs()` chose the dataset named by the error with
`s in text`, a substring test. `pool/vm-10` therefore matched an error naming `pool/vm-100`,
and `data` matched `metadata`. When that happened, the panel listed the whole shared scope
instead of the one dataset the error named.

### Implemented change

- `tui/zfs-tui.py`: new `text_names_dataset(text, ds)` counts a match only on the whole
  dataset name.
  - Before the name: anything except a name character (`A-Za-z0-9_`), `.` or `-`. In practice
    the start of the text, whitespace, a quote, `:` (`host:ds`, `account@host:ds`) or `/` (the
    copy under a target base, e.g. `hdd/backups/pve2/rpool/ROOT/pve-1`).
  - After the name: anything except a name character, `-`, `/` (that is a child dataset), or
    `.` followed by a name character. In practice the end of the text, `@` (a snapshot), `:`,
    whitespace, a quote, or a period that ends a sentence.
- `rel_panel_pairs()` uses it. Grouping by cron label (one failure counted once) is unchanged.
  Exactly one named member names that member; none or more than one shows the complete
  shared scope.

## F1 round 2 (reviewer verification of `a37fe416`) — IMPLEMENTED

### Analysis

Accepted. `lib-scope.sh` `pc_is_dataset()` allows `:` inside a dataset name, and the round-1
matcher treated every `:` as a boundary. An error naming `pool/foo:bar` was therefore pinned on
the member `pool/foo`. The same split also cut a member's own scope: `rel_panel_pairs()` took
`scope.split(":")[-1]`, which turns `zfsbackup@pve1:pool/foo:bar` into `bar`.

### Implemented change

- `tui/zfs-tui.py`:
  - `_DS_NAME_CH` holds the name characters, `:` included.
  - `_transport_prefix(text, colon)`: a `:` is the transport separator only when the word
    before it (back to whitespace, a quote, a bracket, `,`, `=`, `<`, `>` or the start) is
    non-empty, has no `/`, and
    consists of host or account characters (`host:ds`, `account@host:ds`). After a path such
    as `pool/foo:` it is an in-name colon.
  - `text_names_dataset()` now scans every occurrence of the member name:
    - **Before the name:** a name character refuses the match. `/` is accepted (a copy under
      a target base). `:` is accepted only as a transport separator.
    - **After the name:** `/` refuses (a child). `:` or `.` refuse when a name character or
      `/` follows them (`pool/foo:bar`, `pool/x.y`). Otherwise the match is accepted: end,
      `@` (snapshot), `: ` or `.` ending a sentence, whitespace, quotes.
  - `scope_dataset(scope)` strips only a transport prefix, so `zfsbackup@pve1:pool/foo:bar`
    stays `pool/foo:bar`. `rel_panel_pairs()` uses it.
  - Grouping by cron label and the "none or more than one named → whole scope" rule are
    unchanged.

### Remaining risk

- A pool whose name has a colon and no `/` in front of it (`x:pool/foo` for pool `x:pool`) reads
  the same as the transport form `x:` + `pool/foo`. That spelling is ambiguous in the text

  sides then agree, so the match names `pool/foo` only when that is a member.
- Three other places still split a scope on its last `:`: the job panel's scope list and the two
  F2 job-row failure labels. They label a failure with its own job's scope (no error-text
  matching), but an in-name colon shows cut there. Left for a separate change.
