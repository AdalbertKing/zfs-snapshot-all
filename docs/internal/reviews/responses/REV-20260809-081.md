# Response to REV-20260809-081

Both findings ACCEPTED.

## F1 — ACCEPTED (IMPLEMENTED)

### Analysis

The finding is correct and the counterexample is exact. I wrote a comment
claiming the namespace gives profile-owned templates disjoint identities, and
then implemented plain concatenation, which only has that property if the
separator cannot occur inside either component. Nothing enforced that. So the
collision the namespace exists to prevent had not been removed — it had been
moved from the native names into the separator encoding.

Worth being precise about why the eventual gen-cron refusal is not a defence.
It is fail-safe, so nothing corrupt would be installed. But its message names
the composed temporary file, and by then the two `(profile, template)` pairs
that actually collided are gone from the diagnosis. A refusal the operator
cannot act on is a worse outcome than the same refusal one layer earlier.

### Implemented change

Contract option 2 from the review: a **restricted naming domain**. `__` is
forbidden inside a profile name and inside a native template name, so the
separator is unambiguous by construction.

I chose it over an injective encoding deliberately. A length-prefixed scheme is
equally injective and produces section names nobody can read in a config a human
has to audit; readability is most of why namespacing was acceptable to the owner
at all.

**Compatibility checked before choosing it, not after:** the built-in profile's
names are `standard_hourly` and `keep_hourly|daily|weekly|monthly`, all single
underscores, and the profile name in use is `default`. Nothing valid today is
refused. Hyphenated profile names remain legal and are covered.

Enforced at **both** validation and render. Render is what actually encodes the
name, and a render boundary that trusted its caller to have validated first
would be the same fail-open shape REV-077 found in this very file.

### The case that carries the property

The first new assertion **demonstrates the collision from the encoding itself**
rather than asserting it in a comment: it computes both names and requires them
to be equal. If they ever stop being equal, the rejection rule is guarding
nothing and that case says so out loud. This is the same discipline that made
the REV-080 test honest — assert the premise, or the test can pass for a reason
unrelated to the property.

Note on the review's proof bullet "both input profiles independently validate":
under the rejection contract that cannot hold, because both members of the
colliding pair are refused at the boundary. The suite states that explicitly
rather than quietly dropping the bullet.
