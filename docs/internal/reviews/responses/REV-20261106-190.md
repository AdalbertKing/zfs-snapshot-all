# Response to REV-20261106-190

## F1 — IMPLEMENTED

### Analysis

Accepted as stated. `add-replica --exclude-family` refused only a leading dash, whitespace and
quotes. Each name became `-E <name>` in the replica's `flags`, and gen-cron's
`replica_engine_cmd` appends `flags` to the root crontab line unquoted. `-E
foo;touch>/tmp/x` rendered a second command. The same holds for a hand-edited `flags` in a
`[replica:]` or `[dataset:]` section. `lint_flags` checks option letters, not shell syntax.
The relation field `exclude_family` (`lint_scope_exclude_family`) refused only blanks, empty
entries, a leading dash and whitespace, and it renders into the same `flags`.

### Planned or implemented change

One grammar for a snapshot family: `[A-Za-z0-9_.:-]`, not empty, not starting with `-`. The set
is deliberately narrow: no character a shell treats specially, no space.

- `gen-cron.sh`: `family_name_ok`, applied to every `exclude_family` entry and to every `-E`
  argument in `flags` (through `flags_opt_pairs`, so `-Efoo` is checked too).
- `gen-cron.sh lint_flags` (`[dataset:]` and `[replica:]`): a `flags` value containing `;`, `&`,
  `|`, `<`, `>`, a backtick, `$(` or a newline is refused before anything is rendered.
- `zfs-backup.sh check_family_list`: the same grammar for `--exclude-family` in `add-replica`,
  `local-backup`, `add-client` and `rux`. It runs when the argument is parsed, before any config
  is written. An empty entry (stray comma, empty value) is refused.

Hand-edited configs. `flags` stays the administrator's free-form engine options: letters,
paths and `-X` regexes such as `-swap$` or `x{2,3}` still render. What it can no longer carry,
in any option including a `-X` regex, is shell syntax: `;`, `&`, `|`, `<`, `>`, a backtick, `$(`
or a newline. The value is data
copied into a root command line, and one of those characters there either breaks the line or
runs a command. A `-X` regex with one of them was already a broken or unsafe cron line before
this change; it is now refused at render time. `-E` values are held to the family grammar wherever they come from.
The GUI default `__replicate_,vzdump,__migration__` passes.

Tests:

- `test/cron/run.sh` REV190: `flags` = `-E foo;touch>/tmp/rev190-proof`, `-E foo|id`, `-E $(id)`,
  `-E foo&` and `-E a*b` are refused, with no replica line emitted. Control: `-E autosnap_:x.1
  -E __migration__` renders literally. Rendering only; nothing generated is run.
- `test/scopefields/run.sh`: `exclude_family` with shell syntax and with a glob is refused; so is

- the existing A22 render test (`-E __replicate_ -E vzdump`) and the TUI argv test
  (`--exclude-family=__replicate_,vzdump,__migration__`) are unchanged.
