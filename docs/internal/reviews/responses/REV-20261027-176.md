# Response to REV-20261027-176

## F1 — IMPLEMENTED

### Analysis

Accepted as reported. In `restore_live_guard()` (`zfs-restore.sh`) the busy check ran only when
`command -v fuser` succeeded, so a host without psmisc skipped it with no diagnostic. The pipeline
also discarded the exit status of `fuser -m`, so an error read the same as "no holders".

Measured on pve9 (lab) before the change, `fuser -m <mountpoint>`:

| state | rc | stdout | stderr |
|---|---|---|---|
| idle | 1 | empty | empty |
| busy | 0 | the PIDs | `<mountpoint>:<access letters>` |
| error (missing path) | 1 | empty | `Specified filename ... does not exist.` |

So rc 1 alone does not separate idle from an error; stderr does.

### Implemented change

- `zfs-restore.sh`, `restore_live_guard()`: for a local, mounted file system restored in place
  (`rewind`/`replace`):
  - no `fuser` → refused ("cannot verify ... is idle: fuser is not installed (apt install psmisc)");
  - rc 0 with PIDs → refused, naming the holders (unchanged wording);
  - only rc 1 with empty stdout AND empty stderr counts as idle;
  - anything else (an error message, any other rc) → refused with the rc, and with fuser's message when it wrote one.

  All refusals happen in the pre-flight, before any ZFS change. `create` (beside the original) is
  not checked, as before. The remote path is unchanged: a remote mounted file system for an
  in-place mode was already refused outright (since 2026-10-26), and a remote guest probe that does not
  answer cleanly already refuses.
- `deploy.sh`: `check_dep fuser psmisc optional ...` installs psmisc with the package. It stays
  optional for the deploy, because the runtime refusal is the guard.

### Remaining risk

- psmisc missing at deploy time: the deploy warns and continues; the first in-place restore is
  then refused with the install hint. That refusal is the intended fail-closed behaviour.
- `fuser -m` lists processes using the file system. A process that only holds the mount busy
  through a submount or a bind mount elsewhere is outside what fuser reports for this path.
  This limitation is not new.
- No live destructive restore was run for this change. The lab live check of the busy refusal
  (a held mount on pve9) was done for #910 with the same message path.
