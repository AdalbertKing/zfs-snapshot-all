## F1 — the fallback was selected by presence, not delivery — IMPLEMENTED

### Analysis

Confirmed exactly as written. `command -v logger` succeeding proves a binary
exists, nothing about delivery: with syslog/journald down, its socket absent,
or logger failing for any other reason, the message was lost and the outer
`|| :` hid the loss. The file sink was therefore reachable only on hosts with
no logger installed — the hosts least likely to need it.

Worth naming plainly, because it is the same shape this project keeps
removing from its own checks: an audit trail that disappears when the logging
daemon is unwell, while the gate reports nothing wrong.

### Implemented change

`gate_log()` now branches on the exit status:

```sh
(
    logger -t zfs-pair-gate -- "$line" && exit 0
    printf '%s %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$line" >> "$GATE_LOG"
) >/dev/null 2>&1 || :
```

A missing logger and a logger that could not deliver are now one case, and
both fall through to the file. The caller contract from `6914c11` is
preserved and re-asserted by tests: logging never alters the decision or exit
code, never reaches stdout/stderr, and both sinks failing is documented
best-effort silence.

## F2 — the tests could not prove both branches — IMPLEMENTED

Correct: varying `GATE_LOG` alone means a host with logger exercises only
syslog and a host without it only the file. Five deterministic cases now stub
`logger` first on `PATH`:

1. logger succeeds → syslog receives it, the file sink is never created, the
   caller is silent;
2. **logger exists and fails → exactly one bounded record in the file sink**
   (the case the presence-based branch could never reach);
3. both sinks fail → the wrapped command's own exit code survives unchanged
   (asserted with `exit 5`, not with a success), caller silent;
4-5. the refusal path under both failure shapes → stderr carries exactly the
   single `PAIR_DISABLED` line the collector reads for the reason.
