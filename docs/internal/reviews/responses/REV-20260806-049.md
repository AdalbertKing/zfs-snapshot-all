# Response to REV-20260806-049

## F1 — a failed ownership restore still committed the replacement — IMPLEMENTED

Accepted without dispute, in `209231c`. The finding is exactly right: the
function knew the invariant, warned when it could not hold it, and then
committed anyway — leaving reachable the same lockout that `0058834` was
written to remove. A warning does not protect an account that can no longer
log into its own host.

The rule now applied: **an atomic writer owns the metadata invariant.** If
safe ownership cannot be established, the live file is not replaced at all. A
relationship that is not gated yet is a known and recoverable state; an
account locked out of its own host is not.

Hard failures before the rename, each dropping the staging file and returning
non-zero with the original untouched:

- ownership cannot be determined (`stat` fails, or empty result);
- ownership is structurally unusable — `:group`, `user:`, or empty;
- `chown` fails.

### One thing the review could not have seen

An *unconditional* chown also fails where it is not needed — when this
function runs as the account itself rather than as root, and on any
environment whose chown cannot name the same owner back (the dev box this
suite runs on does exactly that). Making the failure fatal without also
making the call conditional would have blocked correct writes on those hosts.
The desired and the actual ownership are therefore compared first, and a
chown happens only on a real difference. This is not a workaround for the
test environment: it is the correct rule either way, and the test environment
is simply where it surfaced.

### Point 6 — the live variant

Not repeated live, and here is the reason rather than a silent omission.
Forcing a genuine `stat`/`chown` failure on a real host means either breaking
`/usr/bin/chown` for the duration or running the writer as a principal that
cannot chown — the first is a hazard to an operational host far out of
proportion to what it would prove, and the second is precisely the
conditional-chown path, which now succeeds by design and so cannot
demonstrate the refusal. The deterministic tests inject the failure at the
exact boundary that matters and assert the file-level outcome, which is the
whole content of the invariant. The live check that *did* run (step 2's
residue/lockout check, recorded in the campaign plan) is what proved the
invariant was needed in the first place.
