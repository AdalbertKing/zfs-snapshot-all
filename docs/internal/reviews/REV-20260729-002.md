### R1 — actual `--join` validates too late

- Severity: P1 within F1
- Blocking: yes

`do_join()` performs package validation before its own account/key/ZFS mutations, but `do_join()` is dispatched only after earlier deployment phases have already run. In the current script, the root check and dependency installation path execute before the later `JOIN_MODE` dispatch.

Therefore an invalid or hostile package can still cause package installation, repository update or other deployment mutations before it is rejected. This does not satisfy the acceptance criterion that validation complete before the first persistent mutation of the `--join` invocation.

#### Required correction

- Perform a complete package preflight at the start of `--join`, before dependency installation, checkout updates, cron changes or any other persistent phase.
- Store the validated normalized values for the later join operation; do not parse a second independent copy later.
- A rejected package must leave the host unchanged except for a private temporary file/directory that is removed on exit.

#### Required test

Use stubs/canaries for the earliest mutating phase and prove that an invalid package reaches none of them.

### R2 — archive member types are not validated before extraction

- Severity: P1 within F1
- Blocking: yes

`assert_package_members()` compares only names from `tar -tzf`. It does not inspect archive entry types. The post-extraction checks reject symlinks and require `-f`, but:

- FIFO/device entries are created by root before being rejected;
- hard links extract as regular files and are not identified as hard links;
- the explicit F1 acceptance criterion required regular files only and rejection of hard links, symlinks, devices and FIFOs.

The current test suite includes a symlink case but no hard-link, FIFO or device case.

#### Required correction

Before extraction, inspect a machine-readable archive listing and require both entries to be ordinary regular files. Reject every other type before `tar -x` runs.

Do not rely on `-f` after extraction to infer the original archive type.

#### Required tests

Add rejection fixtures for:

- hard-linked `peer.conf`;
- hard-linked `pubkey.pub`;
- FIFO member;
- block/character device where the test platform can construct the header;
- any other non-regular tar type supported by the fixture builder.

Tests may build headers with Python's `tarfile` module and do not need root merely to construct or list them.

### R3 — package path is opened twice, leaving a replacement race

- Severity: P1
- Blocking: yes

The archive is opened once by `tar -tzf` for preflight and again by `tar -xzf` for extraction. If the supplied path is in a directory writable by another account, the file can be replaced between those operations. The bytes validated are then not necessarily the bytes extracted as root.

`--join-check` also cannot be treated as approval for a later `--join`, because each command independently reopens the path.

#### Required correction

- Create the private `0700` work directory first.
- Copy the supplied package into it as a root-owned `0600` file.
- Validate and extract only that private copy.
- Preferably record and print its SHA-256 so an operator can compare the checked and joined artifact.

A documented recommendation to place the original under `/root` is useful but is not a substitute for eliminating the race in code.

### R4 — dataset grammar accepts option-like and dot-segment names

- Severity: P1
- Blocking: yes

`pc_is_dataset()` accepts values such as:

- `-o`
- `.pool`
- `tank/./child`

These are then passed to `zfs list`, `zfs create` and `zfs allow`. Quoting prevents shell splitting but does not prevent an argument beginning with `-` from being interpreted as a command option, and dot segments are not valid normalized dataset paths for this contract.

The acceptance criterion required validation against the syntax actually supported by the scripts, not merely a character allow-list.

#### Required correction

- Reject dataset/target values whose first component begins with `-` or `.`.
- Reject `.` and `..` path components.
- Validate the pool/dataset component grammar explicitly and document intentional allowances such as `:`.
- Add option-like inputs to the regression suite.

### R5 — cleanup regression check uses a moving timestamp marker

- Severity: P2
- Blocking: yes for claiming the cleanup criterion verified

`tmp_count()` uses `find ... -newer "$WORK"`, but each `new_case()` creates a directory inside `$WORK`, changing `$WORK`'s modification time throughout the suite. A leaked temporary directory from an early case can therefore be older than the final `$WORK` mtime and disappear from the end-of-suite count.

The test can still pass while earlier cases leaked directories.

#### Required correction

Use an immutable marker file whose timestamp is never modified after creation, or snapshot the exact matching directory names before and after every invocation. The latter is preferred because unrelated system `tmp.*` activity can otherwise produce noise.

Verify the corrected assertion fails against the known bad commit `5ef323c` and passes against the fixed implementation.

### R6 — untrusted package has no size bounds

- Severity: P2
- Blocking: no for the original RCE fix, required for hardening before WAN use

Exactly two correctly named members can still be a compression bomb or declare extremely large files. Extraction occurs on the root filesystem before semantic validation.

Add conservative limits for:

- compressed package size;
- uncompressed `peer.conf` size;
- uncompressed `pubkey.pub` size;
- total expanded size.

The legitimate package is only a few kilobytes, so limits can be tight and documented.
