# REV-20260811-101 — Phase 5 local entrypoint drops the owner-approved multi-source WHAT contract

Review time: 2026-08-11 07:20 CEST
Reviewed implementation: `9b4a6e5a9c4dcd9c0a2f12159872dad9227dd0bd`

## Verdict

**CHANGES REQUIRED — do not wire the install/seed slice onto the current single-source parser.**

REV-097/098 correctly fixed explicit-source existence, additive preview, bare `--source/--target`, and comma-separated CONFIG-scope overlap. A separate owner-contract gap remains at the public Phase 5 input boundary.

## F1 — canonical multi-source selection is not implemented

Canonical owner direction `docs/discussions/EXPLICIT-SOURCE-BEATS-DISCOVERY-2026-08-09.md` explicitly applies to Phase 5 and says:

- one or more explicit roots are authoritative WHAT;
- `--source=rpool/data,rpool/vmstore,hdd/dokumenty` is valid;
- every requested root must validate;
- one invalid root refuses the whole operation;
- parent/child overlaps refuse rather than inventing precedence;
- unrelated roots remain independent entries in the candidate CONFIG.

Current `cmd_local_backup()` holds a single scalar `source`. Its character validation rejects comma, so the canonical comma-list form cannot be expressed at all.

Worse, repeated flags are not rejected: the parser simply executes `source="${a#*=}"` for each occurrence. Therefore:

```bash
./zfs-backup.sh --source=rpool/data --source=rpool/vmstore --target=hdd/backups
```

silently forgets `rpool/data` and plans only the last value. Repeated flags were optional in the owner direction, but silent last-one-wins semantics are not acceptable: an operator can believe both requested roots are protected while one was discarded.

This is still a read-only planner today, but slice 2 is intended to reuse this input path for real installation. The defect therefore must be corrected before that write boundary is enabled.

## Required correction — reduction-oriented

Do not build a source-selection framework. Implement the smallest owner-approved set semantics:

1. Support the canonical comma-separated form in one `--source=`.
2. Normalize into one explicit source-root list before any proposal/composition.
3. Validate every root with local ZFS; if any root is missing/unreadable, refuse the whole request and produce no partial candidate.
4. Exact duplicate roots: reject clearly or canonicalize to one; never emit duplicate ownership.
5. Parent/child overlap inside the explicit set: REFUSE; do not invent precedence/carve-outs.
6. Unrelated roots remain separate source entries in the candidate CONFIG and the generated cron must contain all of them.
7. For repeated `--source` flags either:
   - normalize them into the same set semantics if this is cheap, or
   - explicitly REFUSE repeated flags.
   Silent last-one-wins is forbidden.
8. Preserve REV-097/098 properties: additive composition over existing CONFIG, existing-policy preservation, overlap refusal against existing scalar/comma-list section scopes, bare canonical entrypoint, and read-only planning.

Do not touch frozen engines for this. If current local target mapping needs a narrow orchestration-side normalization for several disjoint roots, keep it in Phase 5 orchestration and prove the generated CONFIG/cron shape; do not create an include/exclude or precedence DSL.
