## Original findings and final disposition

### F1 — explicit `--source` must be authoritative and must exist

The original slice syntax-checked an explicit source but did not prove it existed. The corrected path crosses a real/stubbed `zfs list` boundary before rendering. An explicitly missing dataset hard-refuses the whole operation; it is not reinterpreted as discovery, an empty selection, or a fallback. This is the required fail-closed behavior for an operator-specified source.

### F2 — preview must be additive over the actual existing CONFIG

The original slice built its candidate from scratch and therefore could not prove "add B, do not mutate A". The corrected planner composes the candidate over the existing target CONFIG, preserves the unrelated existing job, and renders the complete A+B cron through the real `gen-cron.sh`. A missing CONFIG is allowed only when no installed managed block claims it; otherwise planning refuses.

The first REV-097 correction still had one safety gap: `config_section_overlap()` treated legal comma-separated `[dataset:]` / `[prune:]` scopes as a single path. REV-098 fixed that by expanding and trimming every member independently. The targeted regression proves an overlap on the second member of `[prune:rpool/other,rpool/data]` refuses, while a genuinely disjoint request still proceeds. REV-098 is independently APPROVED/CLOSED.

### F3 — canonical operator UX must be the bare high-level entrypoint

The public form `./zfs-backup.sh --source=... --target=...` now reaches the same planner directly. The internal `local-backup` alias may remain, but the operator does not need to learn an extra command-tree verb.

## Evidence boundary

This slice remains planning-only. The host-dependent installer/seed boundary is not exercised here, so a live ZFS transfer or real crontab write would not add proof for these findings. The appropriate evidence is the targeted `localbackup` regressions, real `gen-cron.sh` rendering, stubbed existence query, dependency-driven cascade and impact verification.

The separate manual `zfsbackup-live-pair` obligation remains relevant when Phase 5 crosses into real installation/seed behavior.
