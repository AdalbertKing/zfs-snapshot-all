## F1 — P1 — `profile__<profile>__<template>` is not an injective encoding

The implementation says namespacing gives profile-owned templates disjoint identities. It does not for all names the current boundary accepts.

`profile_name_ok()` allows letters, digits, `_` and `-`, including repeated underscores. `profile_validate_templates()` accepts `[template:NAME]` headers without forbidding `__` in the native template name. Therefore both of these are valid inputs to the current boundary:

```text
profile = a__b
native template = c
```

and

```text
profile = a
native template = b__c
```

But `profile_ns_name()` is simple concatenation with `__`:

```text
profile__a__b__c
profile__a__b__c
```

Two distinct `(profile, template)` pairs therefore normalize to the same CONFIG v4 section identity. The exact collision the namespace exists to prevent is still possible; it merely moved from native names to the separator encoding.

`gen-cron.sh` will eventually reject the duplicate section when both fragments are composed, which is fail-safe, but that is not the architectural property agreed for B1. The renderer should give different profile-owned objects different deterministic identities, or reject an ambiguous naming domain explicitly at the profile boundary. Relying on a later duplicate-section error also loses the useful diagnosis of which two profile/name pairs collided.

### Required correction

Choose one unambiguous contract and pin it now, before runtime persists generated names. Acceptable approaches include:

1. an injective encoding (for example length-prefix/escaping of each component); or
2. a deliberately restricted naming domain that makes the separator impossible inside both encoded components, with existing valid names checked for compatibility.

Do not merely add another printable separator unless the grammar proves that separator cannot occur in either component.

The corrected renderer must refuse any post-normalisation collision before a caller can adopt the composed CONFIG, and its error should identify both conflicting profile/native identities where composition has enough context to know them.

### Minimal proof for F1

Add a targeted regression using the exact pair above (or an equally strong pair admitted by the final grammar):

- both input profiles independently validate;
- after the fix their rendered template identities are distinct, **or** one is explicitly rejected by the new documented naming rule before rendering;
- composing the accepted pair through real `gen-cron.sh` succeeds without duplicate sections;
- the old separator-only implementation fails this new assertion (this is the useful negative control);
- existing default-profile rendering/reference rewrite tests remain green;
- dependency-selected `profiles` cascade + `impact.sh --verify` is sufficient for this step.

No live-host proof is required until `zfs-backup.sh` actually consumes the renderer and mutates CONFIG/cron/state.
