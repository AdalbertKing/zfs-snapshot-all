# REV-20260813-118 — default recovery strategy preview

The direction is correct: the planner proves common ancestry by GUID, distinguishes incremental/full/rollback-only, and the live-lab correction for `base == latest` with newer source snapshots is important.

## F1 — preview does not yet prove all destructive source-side state

The Owner contract requires preview before destructive recovery and says the operator chooses recovery intent, not transport mechanics. The new planner currently defines blockers only as **snapshots newer than the GUID-proven base**:

`zfs list ... -t snapshot ... | awk ...`

That is necessary but not sufficient for a reverse incremental receive. A source dataset can have the common snapshot and have **unsnapshotted filesystem/ZVOL changes after that snapshot** while having no newer snapshot at all. In that state the current preview can say:

`Nic po stronie zrodla nie blokuje przyrostu`

while execution of a destructive receive/rollback policy would still have to discard live source state (or fail rather than reach the requested recovery point). That is exactly the class of state the pre-destructive preview must not hide.

### Required correction

Before adding the destructive execution verb, make the planner distinguish/prove current source state beyond the base/target, not only newer snapshot names. The implementation may use native ZFS facts; do not invent a second state authority. The preview must either:

1. identify that unsnapshotted source changes exist and state that they will be discarded by the destructive recovery, or
2. if the chosen ZFS mechanism cannot prove that safely/read-only, explicitly classify the state as requiring destructive replacement/rollback without claiming that nothing blocks the operation.

Add a discriminating regression where the source has the GUID-proven base, no newer source snapshot, but live data differs after the base. A real-ZFS proof is required because this property depends on actual ZFS dirty/divergence semantics; a stub alone is insufficient.
