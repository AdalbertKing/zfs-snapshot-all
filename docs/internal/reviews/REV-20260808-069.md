# REV-20260808-069 — Stage 2.3 long-option pre-pass misclassifies an argument after a short-option cluster

**Initial review time:** 2026-08-08 03:00 CEST

**Initially reviewed head:** `46b96b47c0f1a5b2ff0785992aae697d84889b22` (2026-08-08 02:33:35 CEST).

## F1 — an option argument after a clustered short option is reinterpreted as a long option

- Severity: **P2**
- Blocking: **yes, for Stage 2.3 acceptance**
- Affected: `snapsend.sh::translate_long_options`, `snapget.sh::translate_long_options`, `test/recursion/run.sh`

### Original finding

The first Stage-2.3 pre-pass skipped the following argv only when the short-option token had exactly two characters. That preserved `-m --recursive=flat` but not the legal clustered equivalent `-em --recursive=flat`, where `getopts` reads `-e`, then `-m`, and therefore treats the next argv as the argument of `-m`. The pre-pass instead reinterpreted that MESSAGE data as a long recursion declaration.

The required outcome was to derive the argument boundary from the existing `OPTSTRING` and preserve the same cluster semantics as `getopts`, without introducing another hand-maintained list.

## Reviewer follow-up — APPROVED

**Review time:** 2026-08-08 04:01 CEST

**Reviewed implementation:** `b292b5fe20b890d946ae7daf0b21cb70fc2fc585`

**Verdict:** **APPROVED**

The implementation closes F1.

`cluster_needs_next()` now walks each short-option cluster from left to right and asks the existing `opt_takes_arg()` / `OPTSTRING` definition whether the current letter consumes an argument. If the first argument-taking letter is the final character of the cluster, the next argv is preserved as its data; if characters remain in the token, that remainder is the value and the following argv remains available to the long-option pre-pass. This matches the relevant `getopts` boundary for `-m`, `-em`, `-mfoo`, and equivalent clusters in both transfer engines.

The regression evidence is discriminating rather than ceremonial. The new probe uses deliberately invalid `--recursive=ture`: if that token is MESSAGE data, nobody validates it; if the pre-pass wrongly interprets it as a long option, the recursion-value error becomes observable. Against `46b96b47`, exactly the two decisive `-em` assertions fail — one in each engine — while the other cluster cases remain green and are correctly described only as regression cover. On `b292b5f`, the recursion suite is 64/64.

The implementation also refreshes `PROJECT_STATUS.md` to the new graph/status digest and records the added recursion coverage. No ZFS/root/SSH rerun is required to close this parser finding: the changed property is argv normalisation before any environment-dependent path. The previously planned delegated-account proof for the installed Stage-2.3 copy remains a separate Stage-2 acceptance obligation and must still be executed on the final Stage-2 SHA.

No additional parser finding is opened in this pass.
