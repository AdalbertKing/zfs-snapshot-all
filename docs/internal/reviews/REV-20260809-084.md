# REV-20260809-084 — overlap preflight silently skips client records it cannot read/parse

Review time: 2026-08-09 15:03 CEST
Reviewed implementation: `90bb026e2c9273ce0bd9d7f87f429bf732476883`
Response path: `docs/internal/reviews/responses/REV-20260809-084.md`

## Verdict

**CHANGES REQUIRED before REV-083 can be treated as a fail-closed overlap guard.**

The parent/child path-prefix rule in `90bb026...` is directionally correct and the new targeted tests exercise the intended overlap semantics. The remaining defect is on the state-reading error path, not on `path_overlaps()` itself.

## F1 — P1 — `coverage_conflicts()` converts an unreadable/unparseable relationship record into “no conflict”

`coverage_conflicts()` iterates every existing `CLIENTS_DIR/*.conf` record in a subshell. For each record it currently does:

```bash
CLIENT_NAME=""; STATE=""; MANAGED_DATASETS=""; MANAGED_PRUNE_SCOPE=""
. "$f" 2>/dev/null || exit 0
```

That `exit 0` is fail-open. If an existing relationship record cannot be sourced — corruption, syntax error, transient read failure, or wrong permissions under the executing identity — the record is silently skipped and the outer function still returns success.

This defeats the explicit contract immediately below it: `assert_no_coverage_overlap()` has an rc path whose diagnostic says it will refuse when overlap cannot be checked. That path is unreachable for this class of failure because `coverage_conflicts()` has already translated the failure to rc=0.

Concrete unsafe shape:

```text
clients/A.conf exists and should describe coverage rpool/data
but sourcing A.conf fails

new relationship B requests rpool/data/vm-101

coverage_conflicts() -> silently ignores A.conf -> no conflict
assert_no_coverage_overlap() -> PASS
candidate mutation may continue
```

A damaged state record is exactly when the system knows *less* and must refuse rather than guess.

### Required correction

Keep the per-record subshell isolation, but propagate any inability to source/validate an existing relationship record as a non-zero status from `coverage_conflicts()` so `assert_no_coverage_overlap()` stops before mutation.

Do not solve this by ignoring only “apparently irrelevant” broken records: until a record is successfully read, the code cannot know whether it is irrelevant, removed, or owns the requested coverage.

The diagnostic should name the record that could not be checked.

### Minimal proof

Targeted `zfsbackup` tests are sufficient:

1. valid existing overlapping record -> still refuses (existing REV-083 regression);
2. valid disjoint record -> still allows candidate;
3. existing client record whose source operation fails -> high-level addition refuses before `remove_managed_sections()`;
4. prove the candidate workfile is byte-identical before/after that refusal;
5. negative control against `90bb026...` shows case 3 was accepted or the broken record was silently skipped;
6. dependency-driven cascade for `zfs-backup.sh` plus `./test/impact.sh --verify` with the real exit status.

No additional broad local campaign is warranted. The bounded live-host refusal/read-back already required by REV-083 remains the environmental closure proof; it should be performed only after this fail-open is fixed. No ZFS transfer, SSH/grant, or fleet-wide proof is needed for F1 itself.

## Relationship to REV-083
