# REV-20260909-142 — relation export turns an ordinary relationship into passive on import

Review date: 2026-09-09
Reviewer: ChatGPT
Reviewed delivery: PR #372, `import-relation`, head `f385d802ec32a4730020626f7dd62884ef8288ee`
Canonical merge checked: `43dfc40ad7ac99bfe7c6d00fba9280a10a86f6dd`

## Verdict

**CHANGES REQUIRED — P1: an ordinary relationship created without
`--passive` is exported with `--passive`, and `import-relation --yes` faithfully
applies that false declaration. The restored relationship therefore has
different snapshot semantics from the source relationship.**

The JSON scanner, ordered argv replay, preview-only default, lifecycle order
and refusal of foreign verbs/positional arguments are not rejected. The blocker
is the incorrect boolean conversion at the export/import boundary.

## F1 — P1 BLOCKING — `PASSIVE=0` is emitted as the `--passive` switch

- Severity: P1
- Blocking: yes
- Affected: `cmd_export_relation()` boolean composition and the new
  `cmd_import_relation()` replay path.

### Reproduction

On fresh canonical `main` `4dee0ffd9adadcdadb3587c6b9fefd66d8114b57`,
the reviewer called the real `cmd_add_client()` with only `deploy.sh` and
profile validation stubbed, using:

```text
add-client reqtest --host=10.0.0.11 --mode=backup \
  --requested=rpool/data/vm-101 --target=hdd/backups --local-user=root
```

No `--passive` flag was supplied. The resulting record contained the ordinary
false value. Exporting it with the real `cmd_export_relation()` produced:

```text
record: REQUESTED_DATASETS=''  CLIENT_TARGET=hdd/backups
replay argv: "--host=10.0.0.11","--target=hdd/backups",...,"--passive"
```

Passing that JSON to the real `cmd_import_relation --name=reqcopy --yes`, with
only the three lifecycle verbs replaced by recording stubs, yielded:

```text
add-client|reqcopy|--host=10.0.0.11|--target=hdd/backups|--profile=default|--local-user=root|--passive
seed|reqcopy|--yes
activate|reqcopy|--yes
```

The cause is the export condition: a record writes `PASSIVE=0`, while the
composer treats every non-empty value other than the literal `no` as true.
Thus the newly added importer correctly replays an argv that is already false.

### Failure mode and impact

Passive is not presentation metadata. A passive relationship adopts existing
snapshots and does not stamp its own snapshot family. A recovery/import that
silently changes an ordinary relationship to passive can therefore stop the
expected snapshot creation and change monitoring behavior while completing
the documented `add-client -> seed -> activate` sequence successfully. This is
a loss of backup intent during a restore workflow and is P1.

### Existing verification and why it missed the defect

- PR #372 exact-head CI is green: run `34372721437`.
- Independent focused run on current main:
  `./test/zfsbackup/run.sh --section exportrel` — `31 PASS / 0 FAIL`.
- The fixture used by the suite declares passive truth and proves only that the
  switch survives. It does not export a real default `PASSIVE=0` record and
  assert that `--passive` is absent.

### Acceptance criteria

1. Export a passive switch only for the canonical true representation(s) that
   the record reader accepts; `0`, empty and `no` must not become `--passive`.
2. Add a discriminator that creates or loads an ordinary non-passive record,
   exports it, imports it through recording lifecycle stubs and proves the
   replayed `add-client` argv contains no `--passive`.
3. Keep the positive control: a genuinely passive record must export and
   import with exactly one `--passive` switch.
4. Preserve PR #372's existing guarantees: preview performs no calls; argv
   values and order survive; the follow-up order remains `seed`, then
   `activate`; invalid schema, positional argv and foreign verbs refuse before
   any lifecycle call.

### Required verification

- focused: non-passive negative discriminator plus passive positive control;
- regression: `./test/zfsbackup/run.sh --section exportrel`;
- consistency: `./test/impact.sh --verify` and exact-head CI.

No live ZFS mutation or broader campaign is required. Recording stubs around
the lifecycle verbs decide whether the imported declaration is correct.
