# REV-20260831-127 — relation restore stops after a late pre-mutation refusal

Review date: 2026-08-31
Reviewer: ChatGPT
Reviewed delivery: PR #199, head `97b2f93f159232b0037119955ee654351c9578c3`
Canonical base checked: `9f1cdabdf61856232491d6d8e20ccdac714a5227`

## Verdict

**CHANGES REQUIRED — P1: the D+B controller does not actually continue past
every execution failure. A real single-dataset refusal uses `die`/`exit`,
which terminates the whole relation before later datasets run.**

The whole-scope pre-flight and the three intended outcome classes are useful and
the focused policy suite is green. The blocking gap is confined to the boundary
between the new relation controller and the existing single-dataset primitive.

## F1 — P1 BLOCKING — the controller treats an exiting primitive as a returning one

- Affected: `zfs-restore.sh`,
  `restore_replace_relation_internal()` execution loop; and
  `test/restore/relpolicy.sh` execution stub.
- Blocking: yes.

### Evidence

The new execution loop invokes the real primitive directly:

```sh
restore_replace_internal "$ds" "$config" "$yes"; rc=$?
```

It can classify `rc` only if the function returns. The real primitive still
uses the shared `die()`, whose contract is `exit 1`, for refusals and failures
before destructive execution: an unreadable or changed config, a relationship
that disappeared or became ambiguous, a missing copy snapshot, a strategy that
became ineligible, or failure to create the technical measurement snapshot.

These facts can change after the whole-scope pre-flight, and the technical
snapshot can fail independently during execution. In those paths `die` exits
the shell running the relation controller. Later datasets are not attempted and
the controller never emits its outcome summary.

The committed policy test cannot expose this. Its replacement
`restore_replace_internal()` always uses `return "$rc"`, including the
simulated pre-destruction failure. That is not the control-flow contract of the
real function being wrapped.

### Smallest discriminating control

A reviewer-only harness used the submitted relation loop unchanged in the
relevant control flow. All of `a b c` passed pre-flight. During execution,
`a` returned success, `b` took the real primitive's `die`/`exit 1`
shape, and `c` was the sentinel that proves continuation.

```text
$ bash restore_relation_exit_control.sh
exec:a
exec:b
FATAL: late pre-mutation refusal for b
rc=1
```

There is no `exec:c` and no relation summary. Replacing the exiting refusal
with the suite's current `return 1` makes `c` run, so this control isolates
the missing execution boundary rather than the D or B policy itself.

### Failure mode and impact

A transient or concurrent late refusal on one dataset silently changes policy B
from “continue and recover everything still recoverable” to “stop here”.
Datasets later in the relation remain unrestored, and the promised
`odtworzone`/`nietkniete`/`ZMIENIONE I NIEDOKONCZONE` summary is absent.
For a destructive recovery controller this is an operationally significant
contract failure even though the public CLI door is not yet exposed.

### Acceptance criteria

1. Isolate each real single-dataset execution so its `exit` cannot terminate
   the relation controller. Convert its final status into the existing three
   relation outcomes without weakening the single-dataset safety refusals.
2. A pre-destruction `die`/exit 1 after a successful whole-scope pre-flight
   must classify that dataset as `nietkniete`, continue with every later
   dataset, emit the complete summary, and return relation status 1 unless a
   changed/incomplete result raises it to 2.
3. Preserve status 2 for a dataset whose destructive execution began and did
   not complete; it must still outrank ordinary untouched failures.
4. Add one focused regression control with `a b c`: all pass pre-flight,
   `b` exits rather than returns during execution, `c` must execute, and the
   final summary must name `b` as untouched.
5. Keep the established D pre-flight behavior, internal-only surface, grant and
   destructive safety checks unchanged.

### Required verification

- automated: `bash test/restore/relpolicy.sh`;
- negative control: the new exiting-refusal case must fail against
  `97b2f93f159232b0037119955ee654351c9578c3` for the missing `c` execution;
- consistency: `./test/impact.sh --verify` and exact-head CI;
- no broad Restore campaign or live destructive run is required for this
  bounded correction.

### Assumptions and uncertainty

The relation entry point is currently internal, so this does not claim an
already exposed operator incident. The defect is in the policy contract being
prepared for that public door and blocks acceptance of this Restore slice.
