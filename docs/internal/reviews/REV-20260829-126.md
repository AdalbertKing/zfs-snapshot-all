# REV-20260829-126 — source-only no-work gate can leave a rotated medium stale

Review date: 2026-08-29
Reviewer: ChatGPT
Reviewed delivery: PR #181, merge `9b442ed459dc4792da9e62ab9e8eb286638da87c`
Finding introduced by: `a0ed00d7cf50a751b8fb0d0089ed800ad45c99e`
Current canonical descendant checked: `23be8e59610746dca50acf71024425ea7e3917b3`

## Verdict

**CHANGES REQUIRED — P1: the new pre-import optimisation can skip a stale
rotated replica because it proves only that the source is quiet, not that the
medium in the slot is current.**

The safety work around bounded export, ownership markers, pull warnings and the
nightly default is directionally sound. The blocking defect is confined to the
new `attach` fast path that returns before importing the medium.

## F1 — P1 BLOCKING — `written@latest-source-snapshot == 0` is not a fact about this medium

### Evidence

`zfs-media-gate.sh` now runs the no-work test before it asks whether the pool is
imported. For every source dataset it selects the newest source snapshot whose
name matches the replica prefix and reads `written@<snapshot>`. If all values
are zero, it returns `1` and deliberately never imports the medium.

At that point the gate has read no fact from the target. It does not know the
medium GUID, its newest snapshot, or which bookmark/base it last received. A
quiet source proves only that nothing changed after the newest source snapshot;
it does not prove that this particular rotated disk contains that snapshot.

The normal two-medium sequence is enough to reproduce the false skip:

1. medium A is synced through `replica_s1` and exported;
2. medium B is inserted and synced through the newer `replica_s2`;
3. the source remains unchanged after `replica_s2`, so
   `written@replica_s2 == 0`;
4. medium A returns. The new pre-check sees zero on the source, exits `1`, and
   never imports A, although A still ends at `replica_s1` and lacks `s2`.

Every later run repeats the skip while the source is quiet. On an archival or
otherwise stable dataset the older off-site copy can therefore remain stale
indefinitely, with a log claiming there was nothing to copy.

The green L1 case in `test/mediagate/run.sh` models only one source-side
snapshot and one byte count. It contains no per-medium target state, so its
`101/0` result proves the branch executes but cannot distinguish a current
medium from a rotated stale one. This is the same missing discriminator as the
defect.

### Acceptance criteria

1. A no-work decision must be specific to the medium that would be skipped.
   If that medium is exported and its current replica identity cannot be proved
   without importing it, fail open and import it. A durable outside-the-medium
   record is acceptable only if it is keyed by stable pool GUID and advanced
   solely after a verified successful transfer.
2. Add the discriminating A/B rotation case: A ends at `s1`, B advances the
   source family to `s2`, the source is quiet after `s2`, then A returns. A must
   be imported and brought to `s2`. The case must fail against
   `a0ed00d7cf50a751b8fb0d0089ed800ad45c99e` for the false early skip.
3. Preserve the useful optimisation for a medium independently proved current:
   current medium at `s2` plus zero source writes may skip without opening the
   import window.
4. Missing, unreadable, stale or contradictory per-medium evidence fails open
   to the real engine; it must never be interpreted as “current”.
5. Run the targeted `mediagate` suite, `./test/impact.sh --verify`, and exact-head
   CI. No additional replica modes, GUI surface or protocol machinery belongs
   in this correction.
