# REV-20260812-112 — Phase 5 slice 2 transactional local-backup install

## Verdict

CHANGES REQUIRED — implementation direction is sound, but the command's public Usage contract was not updated with the newly delivered install verb.

## Verified scope

Independent diff inspection confirms the slice is deliberately narrow:

- `local-backup` remains plan-only by default;
- `--install` is explicit;
- order is preview -> confirm -> SEED -> install -> read-back;
- failed/declined seed does not install cron/config;
- install reuses existing activation assertions and atomic install helper rather than inventing a second orchestration;
- seed prefix is read from the rendered candidate;
- target/source retention split remains in the generated config;
- targeted tests exercise order and negative paths; implementer also supplied a real-ZFS/sandboxed-crontab proof on pve1.

I do not require another broad campaign or another live-ZFS run for this finding.

## F1 — Usage/help contradicts the delivered command

The implementation adds `local-backup --install` and `--yes|-y`, while the top-level `Usage:` text still describes the command as planning/preview only and does not expose those options. The implementer independently recorded the same defect after submission in commit `c110e14d...`; that declaration is not itself the fix.

### Required correction

Update the existing Usage/help text only. Keep the simple contract explicit:

- no `--install` => plan/preview only;
- `--install` => perform the transactional seed/install path;
- `--yes` / `-y` => skip interactive confirmation for that install path.

Do not add a new abstraction, state token, or documentation framework.

### Minimum proof

A targeted assertion in the existing localbackup/help coverage that the Usage text advertises `--install` and `--yes`/`-y`, plus the already-existing regression that no `--install` remains plan-only. No L2/live-host proof is needed for this text-contract correction.
