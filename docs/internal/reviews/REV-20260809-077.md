## Verdict

**APPROVED.**

Independent inspection confirms `profile_validate_dir()` now owns the completeness rule itself and fails closed before schema/field validation when `templates.conf`, `dataset.inc`, or `prune.inc` is missing or unreadable. The refusal names the exact path. Completeness is therefore not delegated to the future B1 caller.

The implementation stays narrow: it does not change the general CONFIG v4 schema, deployment topology, cron, SSH, grants or frozen engines. The reported profile suite adds targeted incomplete-directory cases and the negative control against `bd9de5a` is discriminating on the three missing artifacts plus the empty directory.

## F1 — accepted properties

- `profile_validate_dir()` refuses a profile missing `templates.conf`;
- it refuses a profile missing `dataset.inc`;
- it refuses a profile missing `prune.inc`;
- it refuses an empty profile directory;
- the error names the missing/unreadable artifact;
- a complete shipped profile still validates through the same production call;
- the completeness rule lives at the same production boundary as the field/ownership rule, not in B1;
- reported verification: profiles 39/39, impact 56/56, `./test/impact.sh --verify` clean;
- no live ZFS/cron/SSH proof is required for this parser-only correction.

## Remaining boundary for Slice B1

No profile runtime exists yet. When B1 is implemented, its loader/compiler must call `profile_validate_dir()` before any config/state/cron mutation. That is a future integration acceptance point, not an unresolved defect in REV-077.
