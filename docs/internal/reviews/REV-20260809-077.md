## F1 — P1 — `profile_validate_dir` treats missing required profile artifacts as valid

`profile_validate_dir()` is documented as "The whole profile directory, which is what a runtime should call." But its body only validates a component if that file happens to exist:

```bash
if   [ -f "$dir/templates.conf" ] && ! profile_validate_templates ...; then rc=1
elif [ -f "$dir/dataset.inc" ]    && ! profile_validate_fragment ...; then rc=1
elif [ -f "$dir/prune.inc" ]      && ! profile_validate_fragment ...; then rc=1
fi
return "$rc"
```

Therefore an existing empty directory, or a directory missing any one of the three profile artifacts, returns success from the production boundary.

The current test suite separately checks that the shipped `profiles/default/{templates.conf,dataset.inc,prune.inc}` files exist, so the built-in fixture is protected. But that is not the same property. B1 is expected to call `profile_validate_dir()` for whichever named profile it loads. If completeness is checked separately in B1, the very problem REV-076 was meant to remove comes back: the test/runtime must remember a second piece of profile grammar outside the one production boundary.

Slice A explicitly defines the built-in profile as the three artifacts `templates.conf`, `dataset.inc`, and `prune.inc`; they are not optional pieces of an open-ended directory format. The whole-profile validator should own that structural contract as well as field ownership.

### Required outcome

Make `profile_validate_dir()` fail closed when any required profile artifact is missing or unreadable:

- `templates.conf`
- `dataset.inc`
- `prune.inc`

The error should name the missing/unreadable path. Do not move the check into B1; keeping completeness inside the same production boundary is the point.

If the design intentionally wants any of these artifacts to become optional, that is a profile-format contract change and must be written explicitly before implementation rather than inferred from `[ -f ]` control flow.

### Required regression / negative controls

Smallest useful proof:

1. profile suite: remove/rename `templates.conf` in a temporary profile copy -> `profile_validate_dir` refuses;
2. same for `dataset.inc`;
3. same for `prune.inc`;
4. empty profile directory -> refuses;
5. complete shipped profile -> still passes;
6. `./test/impact.sh --verify` plus dependency-selected cascade.

No live ZFS/cron/SSH proof is needed: this is a local profile parser/format boundary and changes no host state.
