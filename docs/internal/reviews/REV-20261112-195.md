# REV-20261112-195 — bookmark-wins engine release bypasses guards and has no batch submission

Scope: new `bookmark_beats_common`/`bookmark_bridge_snap` behavior and the publication boundary for that engine batch.

## F1 — push bookmark promotion skips the target-divergence guard before recv -F

- Severity: **P1**, blocking **yes** for non-destructive sync/exact-target behavior.
- Path: `snapsend.sh:1833–1849,1918–1969,1981–1991`.
- Precise code-path proof: when an older snapshot is common and the target head's GUID matches the source bookmark, the new rule sets `bookmark_base` and then `common_snapshot="null"`. The push divergence guard at 1918 requires `common_snapshot != null`, so its target `written@` read and its refusal for a non-backup landing with target writes are skipped entirely. `recv_flags` still defaults to `-F -s` at 1969. A non-backup/exact `-t` target with writes after its head can consequently reach a forced receive without the permission/proof required on the ordinary common-snapshot path. The pull guard separately handles a bookmark-backed target head; the push guard does not.
- Impact: a source-retention event, by removing the latest common source snapshot while its bookmark survives, can turn a normally refused target-divergence scenario into a forced rollback of target writes. A bounded execution of the exact promotion/guard blocks, with target written=1024 and no backup-landing exception, returned `ABORT target divergence; ordinary rc=1` before promotion, versus `common=null recv=zfs recv -F -s tank/dst; promoted rc=0` with promotion. This is a demonstrated guard bypass, not a claim that the Reviewer executed a destructive receive.
- Acceptance: use the GUID-matched target snapshot as the receive base and perform the same divergence/unknown-evidence decision before every forced receive, including the new bookmark-wins path. Preserve the intended backup-landing behavior. Add push cases for non-backup and `-t` targets with writes after the matched head, unreadable `written@`, and the no-write positive case. Prove the old candidate fails the new refusal test and both engines retain their intended semantics. A real isolated ZFS negative control is required because the risk concerns rollback.

## F2 — failed bridge enumeration silently drops promised intermediate history

- Severity: **P1**, blocking **yes** for the new history-preservation contract.
- Path: `lib-zfs-snap.sh:3490–3522`; `snapsend.sh:1981–1996,2177`; `snapget.sh:2170–2185,2380`; `record_send_bookmark` at `lib-zfs-snap.sh:3394–3413`.
- Evidence: if `bookmark_bridge_snap` returns 1 because its snapshot/bookmark list cannot be read, both engines log that intermediate snapshots are not carried and continue using the previously prepared single `-i bookmark latest` send. Successful transfer then advances the per-target bookmark to latest. The next run starts at/after latest, so the missing intermediate snapshots are not carried automatically later. The helper also returns successful empty output if its expected bookmark or latest endpoint is missing from the list, treating incomplete/racy evidence like a proved interval containing no intermediate snapshots.
- Impact: a temporary list failure becomes a successful but permanently incomplete historical copy. The log's phrase `not carried this run` understates the consequence; the endpoints/bookmark advance past those snapshots. This contradicts the new default behavior promising the snapshots between bookmark and latest.
- Acceptance: distinguish proved empty interval from failed/incomplete evidence. For default history mode, fail before receive/bookmark advancement when the bridge cannot be determined reliably. Test list rc!=0, missing bookmark, missing latest, no eligible intermediate (valid positive single diff), and normal bridge. Verify the following run does not silently lose the obligation to copy the intermediate snapshots. Preserve explicit `-i` semantics.

## F3 — bookmark promotion bypasses the configured -T history threshold

- Severity: **P2**; blocking **yes for claiming compatibility with configured history policy**.
- Path: `snapsend.sh:1844–1852,1981–1992`; `snapget.sh:1913–1917,2093–2100,2170–2181`.
- Evidence: the `-T` calculation runs only while `common_snapshot != null`. Bookmark promotion sets it to null, so an explicit threshold that would switch an old snapshot-based interval to a single diff is not applied; the new bridge path then sends the intermediate history when `SKIP_INTERMEDIATES` remains 0.
- Acceptance: define and apply the same threshold policy to a bookmark-backed interval, based on verified base age, or obtain an explicit Owner contract change. Test old and fresh bookmark bases with `-T`, explicit `-i`, both engine directions, and parity of plan versus actual send selection. No new CLI knob is requested.
