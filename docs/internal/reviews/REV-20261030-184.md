## F1 — a supported `host:dataset` source is not inspected before a tree job runs

- Severity: **P1**
- Blocking: **yes for PR #1007 and any release containing it**
- Affected: `zfs-job.sh`, recursive `--pve-guests=HOST:tree` snapshot/prune
  commands; missing control in `test/cron/run.sh`

### Evidence

PR #1007 adds a run-time guard which finds the source tree in the wrapped
command and lists it before a recursive snapshot or prune. Its scanner says the
accepted operand is `dataset` or `[user@]host:dataset`, but the actual case arm
accepts a remote operand only when it contains both `@` and `:`:

```bash
case "$_w" in -*|/*|*[!A-Za-z0-9_.:/@,-]*) continue ;; */*|*@*:*) ;; *) continue ;; esac
```

The account is optional throughout the engine contract. Therefore the valid
source `pveA:tank/data` is skipped, `want` remains empty, no remote tree is
listed, and the command runs without the exclusions which the new guard is
supposed to add. The submitted positive test covers only
`zb@pveA:tank/data`, so it cannot detect this bypass.

Executable exact-head negative control (fixture stubs only; no ZFS or host
access):

```bash
TARGET_REPO=/path/to/zfs-snapshot-all \
  TARGET_SHA=3e6ba19963a310b73590813654427178017a79c8 \
  bash docs/internal/reviews/evidence/REV-20261030-184-host-only-tree-guard.sh
```

Observed on the exact target:

```text
sha=3e6ba19963a310b73590813654427178017a79c8
wrapped=0 -s -m p_ -R pveA:tank/data
remote_tree_lists=0
FAIL: host-only remote tree bypassed the PVE guest guard
```

The same harness with `zb@pveA:tank/data` does list the tree and adds the
expected `-X` exclusion. The complete focused suite on the target reports
`PASS=275 FAIL=0`, demonstrating the missing negative control rather than a
covered failure.

### Failure mode and impact

The guard exists to stop a recursive snapshot or retention prune after a PVE
guest has migrated and the local tree is now a replication target. With a
supported host-only remote source, the candidate silently skips that decision.
In particular, a generated `delsnaps.sh -R` job can proceed across a migrated
guest disk instead of returning the guard's `rc=76`. The command wrapper still
reports normal execution, so this is a fail-open path in destructive retention.

### Acceptance criteria

- Parse the wrapped command by its accepted command grammar, not by requiring
  an optional account. Recognize local `pool/path`, `host:pool/path`, and
  `user@host:pool/path` tree sources while continuing to reject option values,
  paths and copy targets as the source.
- Both remote spellings must list the tree through the line's own SSH options
  and add the same guest-disk exclusions, or take the documented conservative
  failure path when the tree cannot be inspected.
- A generated prune containing `-L` and `-P __replicate_:2` must still select
  the dataset rather than an option value and must not run over a migrated PVE
  guest disk.
- Do not change the owner's selected warning policy for an unavailable remote
  listing as part of this finding; make the host-only form obey the same policy
  as the account-qualified form.

### Required verification

- Add actual-wrapper controls for local, `host:dataset`, and
  `user@host:dataset` recursive snapshot and prune commands. Assert the remote
  list count, exact `-X` propagation, and `rc=76` for a moved guest.
- Keep negative controls proving that `__replicate_:2`, SSH key/known-hosts
  paths, option arguments, and a copy target are not selected as the source.
- Add remote-list failure controls for both remote spellings and preserve the
  documented notification/result behavior.
- Make the executable reproducer above pass on the implementation SHA and
  remain failing on `3e6ba19963a310b73590813654427178017a79c8`.
- Run `test/cron/run.sh`, focused wrapper/generator tests, shell syntax,
  `git diff --check`, `test/impact.sh --verify`, and exact-head CI.

## Reviewer verification — APPROVED

The reviewer approves implementation
`40f9b1dd37746c60c91e816bb2ef6a9b22d80e85`.  The implementation parses a
remote operand when a colon is present and the prefix before the first colon is
not a local dataset path; this accepts both `host:dataset` and
`user@host:dataset` while preserving a local dataset such as `tank/data:x`.

The executable evidence script had one reviewer-owned defect: its SSH-log grep
was anchored at the hostname even though the fixture logs the SSH options
first.  The corrected anchor includes `ConnectTimeout=10 pveA` and produces the
required distinguishing result:
