## F1 — P1 — profile ownership policy had no reusable production enforcement and `templates.conf` was a false-green

- Severity: P1
- Blocking: yes, before Slice B1 runtime consumes profile files
- Affected: Stage 5 profile loader/compiler boundary, `test/profiles/run.sh`, `profiles/*`

### Accepted implementation properties

1. One production profile-boundary validator exists in `lib-profile.sh`.
2. `test/profiles/run.sh` calls that production path instead of defining its own ownership policy.
3. All profile-owned inputs are covered by the validator: `templates.conf`, `dataset.inc`, and `prune.inc`.
4. The ordinary CONFIG v4 schema remains unchanged; deployment-owned `[template:]` sections may still carry legitimate `src`/`dst` where `gen-cron.sh` permits them.
5. Accepted field names are derived from the generator schema authority rather than restated in a second vocabulary.
6. Profile-specific ownership exclusions remain at the profile boundary: relationship topology/raw fields are refused there.
7. The corrected suite includes negative cases for `dst`, `src`, raw `flags`, relationship fields and unknown fields in profile templates, plus the existing `.inc` negatives.
8. The positive control proves a non-profile deployment `[template:]` with legitimate `dst` still renders through the real generator.
9. The reported mutation control against the pre-fix tree is discriminating: a poisoned profile template passed the old suite and is refused by the corrected production path.

### Verification scope

The implementation is parser/ownership-boundary only. Reported evidence is appropriately narrow: profiles 33/33, impact 56/56, `./test/impact.sh --verify` clean, and the targeted old-tree negative control. No live ZFS/cron/SSH campaign is required for REV-076.
