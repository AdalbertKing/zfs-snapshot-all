# REV-20261109-193 — Unknown inserted-disk identity bypasses the replica filter

Reviewer: ChatGPT. Date: 2026-11-09.

Target: developer `main` at `dc359a208c05983f5f83b0e76eb3f91e138626ad` (PR #1147), and release `zfsbackup` at `68ac8d3ecd1c7117a5836d7aacab8b2d05e756ae` (1.0.17, `RELEASE-OF` at `f3e90e63dc10fe8e181b2dd7c20327343ef67d1b`). This is an independent audit of the newly shipped `run-replicas --on-insert --device` contract. The prior USB media and GUI fixes are not reopened.

## F1 — A ZFS disk with unreadable pool identity triggers every on-insert replica

- Severity: **P2 (wrong-job execution and false alert/status)**. Blocking: **yes for claiming that an unrelated inserted ZFS disk cannot trigger on-insert replica jobs**.
- Affected path: `zfs-backup.sh` `cmd_run_replicas`, lines 7144–7157 and 7195–7229 on the target `main`; udev calls this path with `--device=%k`. The fix is already present in the release package.
- Evidence: after `blkid` reports `TYPE=zfs_member`, the command reads `LABEL` and `UUID` separately. If both reads are empty or fail, `ins_known` stays `0`. The sole ownership filter is guarded by `oninsert=1 && ins_known=1`, so this input skips every pool/GUID comparison and executes each `#on-insert` job. The new `test/zfsbackup/run.sh` cases cover known pool names and GUIDs, but do not cover the empty-identity case. This is a direct code-path proof; the Reviewer did not run a live disk insertion or a new ZFS test.
- Failure mode: a temporary `blkid` failure, incomplete metadata, or unsupported label layout on an otherwise detected ZFS member recreates the behavior PR #1147 was meant to prevent. A foreign disk may produce job records, false success or refusal alerts. The downstream media gate can refuse an unavailable medium, but it does not restore the promised property that unrelated jobs are never started.
- Expected: for an event with `--device`, an unverified disk identity must not select every replica. Log a clear identity-probe failure and skip or refuse safely; keep the established behavior of manual and scheduled runs. Distinguish intentionally device-less invocations, if supported, from failed identity reads.
- Acceptance: demonstrate a `TYPE=zfs_member` event where both `LABEL` and `UUID` probes yield empty output and verify that no on-insert replica command, job record or alert is produced. Keep positive GUID and pool-name matching, foreign-disk rejection, and the existing `--collect` rule working. Add a discriminatory control showing the current released code fails the new test; run the focused suite, impact verification and exact-head CI. State any live insertion test separately as EXECUTED or NOT RUN.

No production system or production code was changed by the Reviewer. No private identifiers are included in this review.
