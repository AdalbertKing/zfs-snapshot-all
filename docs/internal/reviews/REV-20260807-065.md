# REV-20260807-065 — V2 rejection derives the wrong workflow state

**Review time:** 2026-08-07 20:04 CEST

**Original reviewed implementation:** `135c0311caddaa0a620168ec8bca089f712441bd` (`Review Protocol V2: the ledger is generated, so it cannot drift`).

## F1 — rejecting the submitted SHA leaves ownership with Reviewer instead of returning to Claude

- Severity: P1
- Blocking: yes — Protocol V2 cutover
- Affected: `test/reviewctl.sh`, `test/reviewctl/run.sh`

### Evidence

`docs/project/PROTOCOL.md` defines the only backward transition as:

`IMPLEMENTED -> OPEN`

when the reviewer rejects the currently submitted implementation.

The implementation in `135c031` did not implement that rule. `state_of_raw()` ignored `reviewed-implementation` for `CHANGES-REQUIRED`; if any response implementation existed it emitted `IMPLEMENTED`.

The deterministic test contained the same defect visibly. Case `world c` was labelled `reviewer rejects sha1 -> OPEN again for the implementer` but expected `IMPLEMENTED`.

### Required outcome

1. Derive `OPEN` when `verdict=CHANGES-REQUIRED` and `reviewed-implementation` equals the current response `implementation`.
2. Preserve `IMPLEMENTED` when Claude advances the same response to a new SHA after that rejection.
3. Correct case `world c` so the expected state is `OPEN` and assert the generated owner/next action (`Claude`, `implement and respond`).
4. Keep the approval-mismatch behavior: an old approval must never approve a newer submitted SHA.

### Required verification

No broad campaign and no live-host proof are warranted: this path is pure artifact/state derivation with no ZFS, crontab, UID, SSH, grants or deployment dependency.

Run only the dependency-driven slice:

- `./test/reviewctl/run.sh`;
- `./test/impact.sh --verify`;
- negative control against `135c031` showing the corrected rejection case fails there while unaffected happy-path cases still pass.

The graph edge is already correct: `test/reviewctl.sh -> suite reviewctl` and `test/reviewctl/run.sh -> suite reviewctl` are declared in `test/deps.conf`.
