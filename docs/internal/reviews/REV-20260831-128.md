# REV-20260831-128 — a selected dataset list is silently treated as a whole-relation rebase

Review date: 2026-08-31
Reviewer: ChatGPT
Reviewed delivery: PR #206, head `8c870aca5b961cdaeead53f8c36ab47d660adcae`
Canonical base checked: `28309c37acf674a00ae4bd615f4fff4427557e7c`

## Verdict

**CHANGES REQUIRED — P1: `--target A,B --onto X` is accepted as the
whole-relationship form even though the owner grammar requires equal-length
positional lists whenever a selection was supplied.**

The common-root calculation, longest-match mapping and ordinary equal-length
pairing pass the focused suite. The blocker is confined to distinguishing the
two public `--onto` forms before that arithmetic is invoked.

## F1 — P1 BLOCKING — the helper infers grammar from list lengths and loses selection provenance

- Severity: P1
- Blocking: yes
- Affected: `zfs-restore.sh`, `restore_onto_plan()` and both calls from
  `cmd_restore()`; `test/restore/onto.sh`.

### Evidence

The owner decision gives the two forms different contracts:

- with `--source`/`--target`, `--onto` is a positional list of the same length;
- only with no selection list may one `--onto` path rebase the whole relation.

`restore_onto_plan()` receives only the destination list and an array of source
roots. It does not receive whether those roots came from an explicit selection.
Consequently this condition:

```sh
if [ "$n_to" -eq 1 ] && [ "$n_from" -gt 1 ]; then
```

always selects the whole-relation branch. The selected-scope call passes
`RESTORE_SCOPE_SRC[@]` in exactly the same shape as the whole-relation call
passes recorded roots, so the helper cannot enforce the public distinction.

### Smallest discriminating control

The submitted focused suite is green:

```text
$ ZB=./zfs-restore.sh bash test/restore/onto.sh
PASS=14 FAIL=0
```

A reviewer-only control then invoked the submitted planner with the values the
public selected-scope path supplies for:

```text
restore source destination \
  --target rpool/data/disk-0,rpool/data/disk-1 \
  --onto hdd/recovered
```

Observed result:

```text
rc=0 pairs=1 from=rpool/data to=hdd/recovered
```

Required result is a refusal before pre-flight or mutation: the selection has
two members and `--onto` has one. This is not the whole-relation form because an
explicit selection was supplied.

The existing test at `test/restore/onto.sh:112-114` explicitly accepts one
destination over several roots, but exercises the context-free helper and
therefore cannot distinguish the allowed whole-relation call from the forbidden
selected-list call.

### Failure mode

An operator who accidentally omits the second destination path does not receive
the promised cardinality refusal. The command instead derives a common root and
constructs destination paths the operator did not state as positional pairs.
Because this is a destructive cross-host restore, silently changing an invalid
pairing request into a different valid mapping is a blocking targeting error.

The selected dataset scope itself is not widened by this defect; the risk is
where the selected datasets land.

### Acceptance criteria

1. Preserve whether `--source`/`--target` selection was explicitly supplied
   through the `--onto` planning boundary.
2. With an explicit selection, require the `--onto` list to have exactly the
   same number of members, including the two-selected/one-destination case.
   Refuse before pause, pre-flight, preview or mutation.
3. Keep one `--onto` path valid for the whole-relation form with no selection,
   including common-root derivation from multiple recorded roots.
4. Add one public-CLI regression pair: the selected two-to-one form refuses,
   while the otherwise identical bare whole-relation form remains accepted.
5. Preserve positional order, duplicate-destination refusal, longest-match child
   mapping and dataset-name-boundary common-root behavior.

### Required verification

- automated: `bash test/restore/onto.sh` with the new public-CLI regression pair;
- negative control: the selected two-to-one case must fail against
  `8c870aca5b961cdaeead53f8c36ab47d660adcae` because it returns success and one
  inferred rebase pair;
- consistency: `./test/impact.sh --verify` and exact-head CI;
- no live destructive Restore campaign is required for this bounded grammar fix.

### Notes and uncertainty

This review does not reject the whole-relation rebase design or the mapping
arithmetic. It rejects only the lost provenance that makes the selected-list
and whole-relation grammars indistinguishable at the helper boundary.
