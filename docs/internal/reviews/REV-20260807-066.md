# REV-20260807-066 — Stage 2 verification must follow the dependency/risk graph

**Original review time:** 2026-08-07 20:58 CEST

**Original reviewed design:** `8b69e1afc40ab6a25a0b42532db9769508797fde`.

## Original finding

The three Stage 2 behavior contracts were accepted, but their verification plan incorrectly applied one broad common cascade to independent changes. The required correction was to derive evidence per change from the dependency/risk graph, use live hosts only where the environment can discriminate the property, and keep broad escalation conditional rather than default.

The required model was:

- Stage 2.1 run suffix/correlation: focused regression + negative control + graph-selected suites + one real-ZFS proof;
- Stage 2.2 recursion declaration normalization: focused parser/conflict tests + negative control + graph-selected suites, with no mandatory host/ZFS run for pure argv normalization;
- Stage 2.3 long aliases: focused equivalence/conflict tests + negative control + graph-selected suites + one delegated installed-copy invocation where it proves deployed-version compatibility;
- `impact.sh --verify` as the common graph-integrity gate;
- `cron`/`cron2conf` and wider campaigns only when the actual diff/graph requires them.

## Approval — 2026-08-07 22:58 CEST

**APPROVED implementation:** `39663b2b754f2194b0342f068a93fe3b22aaeadc`.

Independent review confirms the revised contract now follows the intended cost/evidence model. The response explicitly maps 2.1/2.2/2.3 to different environmental dependencies; removes unconditional real-ZFS/host work from 2.2; limits 2.3 to a discriminating installed-copy check; makes generated-cron/cron2conf evidence conditional on the dependency graph; and keeps `impact.sh --verify` as the one common gate.

The follow-up commit `39663b2b` also removes two contradictory leftovers (`one cascade` and unconditional four-host byte identity), so the document no longer states the new rule in one section and violates it in another.

No runtime campaign is required to approve this review because the finding was test-planning/documentation only. Runtime/live obligations remain attached to the later Stage-2 implementation slices according to the approved matrix.
