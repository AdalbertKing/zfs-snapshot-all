## F1 — P2: an error naming one dataset is rendered as ambiguous for prefix-colliding scopes

PR #920 correctly deduplicates one failed cron line shared by several datasets.
It then tries to identify the affected dataset with:

```python
named = [s for s in scs if s in (f[2] or "")]
ds = named[0] if len(named) == 1 else u", ".join(scs)
```

This is substring matching, not dataset-name matching. For scopes
`pool/vm-10` and `pool/vm-100`, an error that explicitly names only
`pool/vm-100` also contains `pool/vm-10` as a prefix. The panel therefore
prints both datasets instead of the one actually named by the error. Short
names such as `data` / `metadata` have the same class of collision.

Executable isolated reproducer, run unchanged against both exact development
head and the exact release tree:

```bash
python3 - <<'PY'
import importlib.util
s = importlib.util.spec_from_file_location('zt', 'tui/zfs-tui.py')
m = importlib.util.module_from_spec(s); s.loader.exec_module(m)
m.job_cron_label = lambda j: 'shared'
m.job_run_issue = lambda data, j: (
    (1, '2026-10-27 13:00', 'cannot receive pool/vm-100: dataset is busy'), None)
class D:
    stats = {'window_days': 7}
    def failed(self, _): return False
row = {'kind':'relation', 'name':'r',
       'rel':{'name':'r','state':'active','mode':'backup','profile':'default'},
       'monitors':[], 'vword':'aktualne', 'verdict':'OK', 'reasons':[],
       'last':None, 'next_epoch':0, 'next':'-', 'stats':{}, 'gb':'-',
       'jobs':[{'section_kind':'dataset','scope':'pool/vm-10'},
               {'section_kind':'dataset','scope':'pool/vm-100'}]}
for key, value in m.rel_panel_pairs(row, D(), 0, m.Chars(False)):
    if 'Przyczyna' in key: print(value)
PY
```

Observed at release `f5e97d4eaefb8963c250cc4e58afcd27ab745ec5` and
implementation `5f7aaf31e046df0366598801e3ae6712fb602ebd`:

```text
pool/vm-10, pool/vm-100: cannot receive pool/vm-100: dataset is busy
```

The pre-change base `448c86a3ace310c0e60f8efc6b4b68b20abd8867`
incorrectly pinned the same error to the first dataset (`pool/vm-10`). The new
code removes that worse misattribution, but does not satisfy its own boundary:
when the error text unambiguously names one member, the panel should name that
member rather than report the whole shared scope.

## Acceptance

- Preserve one-row deduplication for one cron label shared by several datasets.
- Attribute a failure to one dataset only on an exact, boundary-aware match of
  the recorded scope (including remote/transport forms); prefix or substring
  collisions must not count as additional matches.
- If no member or more than one member is genuinely named, show the complete
  shared scope without guessing.
- Add actual-function tests for `pool/vm-10` versus `pool/vm-100`, `data`
  versus `metadata`, no named member, and genuinely multiple named members.
  Assert the rendered `Przyczyna` row and that the shared failure is counted
  once without a synthetic `(+N)`.
- Run focused `test/tui`, `test/impact.sh --verify`, `git diff --check`, shell
  and Python syntax checks, and exact-head CI. Respond in the canonical
  response file with the full implementation SHA.
