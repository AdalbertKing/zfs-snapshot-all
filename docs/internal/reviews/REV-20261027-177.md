## F1 — P2: an error naming one dataset is rendered as ambiguous for prefix-colliding scopes

PR #920 correctly deduplicates one failed cron line shared by several datasets.
It then tries to identify the affected dataset with:

```python
named = [s for s in scs if s in (f[2] or "")]
ds = named[0] if len(named) == 1 else u", ".join(scs)
```

This is substring matching, not dataset-name matching. For scopes
`pool/vm-10` and `pool/vm-100`, an error that explicitly names only
`pool/vm-100` also contains `pool/vm-10` as a prefix. The panel therefore
prints both datasets instead of the one actually named by the error. Short
names such as `data` / `metadata` have the same class of collision.

head and the exact release tree:

Observed at release `f5e97d4eaefb8963c250cc4e58afcd27ab745ec5` and


The pre-change base `448c86a3ace310c0e60f8efc6b4b68b20abd8867`

code removes that worse misattribution, but does not satisfy its own boundary:
when the error text unambiguously names one member, the panel should name that
member rather than report the whole shared scope.

## Reviewer verification of implementation `a37fe416e34aadceb6039ddf7d85511131bf0db5`

Verdict: **CHANGES-REQUIRED**. The submitted implementation fixes the reported
`vm-10` / `vm-100` and `data` / `metadata` examples, but it does not meet the
exact, boundary-aware requirement for the repository's accepted dataset-name
grammar.

`lib-scope.sh::pc_is_dataset()` explicitly accepts `:` inside a dataset name,
and an adjacent engine comment states that a dataset path may legally contain a
colon. The new matcher instead excludes `:` from its name-character class so
that it can recognize the transport spelling `host:dataset`. Consequently it
also treats a colon *inside* a dataset name as a boundary.

Executable negative control on the exact submitted implementation:

```bash
python3 - <<'PY'
```

Observed:


`pool/foo:bar` is not a member of the shared job, so no member is genuinely
named. The required fail-safe result is the complete shared scope
`pool/foo, pool/other`, not attribution to `pool/foo`.

Required continuation in this same REV:

- match exact dataset tokens without treating a legal in-name `:` as a dataset
  boundary;
- still recognize the transport separator in `account@host:dataset@snapshot`;
- add an actual-function regression for the legal collision
  `pool/foo` versus error text naming `pool/foo:bar`, alongside a positive
  remote-form case;
- retain all original acceptance criteria and rerun their focused and CI gates.
