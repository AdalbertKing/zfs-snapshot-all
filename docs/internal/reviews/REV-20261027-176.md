# REV-20261027-176 — P1: missing fuser bypasses local busy-filesystem restore guard

Reviewer: ChatGPT. Date: 2026-10-27.

Source release: AdalbertKing/zfsbackup main `2b8e8d433e9823da24f5ed08309dd0a5235d0d7c`, `RELEASE-OF=4f2aeefb4cda6c52ab9b13154c97adcf412438e5`. Canonical dev main checked at `aa4df00026346c188ca636a60955d631794d5c7a`, where the condition still exists (even after PR #911).

## F1 — P1: fail-open when fuser is not installed

`zfs-restore.sh`, `restore_live_guard()` around lines 3635–3650, condition:

```bash
if [ -z "$host" ] && [ "$mo" = yes ] && [ -n "$mp" ] && [ "$mp" != - ] && [ "$mp" != none ] && [ "$mp" != legacy ] \
   && case "$mode" in rewind|replace) true ;; *) false ;; esac && command -v fuser >/dev/null 2>&1; then
    pids="$(fuser -m "$mp" 2>/dev/null | tr -s ' \t' '\n' | grep -E '^[0-9]+$' | sort -u)"
    if [ -n "$pids" ]; then ... return 1; fi
fi
```

If `fuser` is unavailable, `command -v fuser` returns nonzero and the entire guard is skipped. A local **mounted** filesystem selected for destructive `rewind` or `replace` passes this busy check with no diagnostic. A separate guest/root guard may still reject some datasets, but ordinary mounted user-data datasets can pass. This violates the newly advertised safe-before-change boundary in PR #910.

The hourly release audit executed an isolated negative control at exact release SHA: `missing-fuser rc=0 verdict=<>`. The test in `test/restore/run.sh` supplies a stub `fuser` and misses this negative case. This is an isolated function-boundary reproducer, not a live destructive restore. The released code and current dev path were independently inspected. CI/test claims (release suite 12/12, restore suite 337/337, PR #910 green) do not cover the absent dependency.

The command pipeline also ignores a nonzero `fuser -m` status; it may interpret a failed probe as no holders. Note: an ordinary `fuser -m` rc1 can mean *no matching users*, so acceptance must distinguish that from true invocation/access errors without rejecting legitimately idle datasets indefinitely.

## Acceptance

- For an in-place local restore (`rewind`/`replace`) on a mounted filesystem, **do not proceed on missing `fuser`, invocation error or uncertain busy state**. A verified-safe alternative is permitted; merely adding `psmisc` as a documented dependency without a runtime check is insufficient for fail-closed behavior.
- If `fuser` is required, verify installation/dependencies via deploy/upgrade paths and retain a runtime refusal on its absence. Failures in the remote probe must also remain fail-closed, where applicable.
- Actual-function negative tests with an executable stub / constrained PATH: missing fuser, failing fuser, busy holder, genuinely idle filesystem, local vs remote, create-beside unaffected; assert return code, refusal message, and **no destructive ZFS operation**.
- Include an old-tree discriminating negative control, focused `test/restore` on supported environment, `test/impact.sh --verify`, `test/reviewctl.sh --verify`, shell syntax and exact-head CI. Respond in `docs/internal/reviews/responses/REV-20261027-176.md` with full implementation commit SHA.
