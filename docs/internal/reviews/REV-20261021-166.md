## F1 — P1: U45 passes `HOST:PORT` as an SSH hostname and hard-codes port 22

- Severity: **P1**
- Blocking: **yes** for the advertised self-starting import on a supported non-default SSH endpoint
- Affected: `zfs-backup.sh`, `cmd_import_relation()`, ordinary U45 replay after U62 export

### Evidence

U62 deliberately exports the active address and keeps a non-default port in the replay argument:

```text
--host=source.example:2222
```

`cmd_import_relation()` extracts that entire value into `peer_host`, but the U45 decision still calls:

```bash
rux_root_ssh "$peer_host" 22 "true"
```

The existing `parse_endpoint_arg()` helper already defines the canonical `HOST[:PORT] -> HOST PORT` contract, but U45 does not use it. Consequently the probe becomes SSH port 22 to hostname `source.example:2222`, instead of port 2222 to hostname `source.example`.

The reviewer exercised the actual shipped `cmd_import_relation()` from canonical `main` with an isolated exported JSON document and stubbed only the network/change boundaries. No network, ZFS, account or live-host operation ran. The decisive trace was:

```text
CASE=nondefault endpoint=source.example:2222 root=available
root-ssh|source.example:2222|22|true
add-client|portprobe|--host=source.example:2222|--bandwidth=20M
```

The root oracle accepted only `source.example`, port `2222`; therefore `--join-remotely` was absent. The default-port positive control proves the same harness reaches and selects U45:

```text
CASE=default-positive endpoint=source.example root=available
root-ssh|source.example|22|true
add-client|portprobe|--host=source.example|--bandwidth=20M|--join-remotely
```

The no-root control retained the intended manual path and also omitted `--join-remotely`.

The shipped focused suite remains green (`bash test/zfsbackup/run.sh --section exportrel`: **63 PASS, 0 FAIL**) because its `rux_root_ssh` stub accepts any host/port whenever `IM_ROOT` is set. It verifies that U62 exports `10.98.0.2:2222` and separately that U45 adds `--join-remotely`, but never makes the U45 oracle require `(10.98.0.2, 2222)`. `bash -n zfs-backup.sh` also passed. PR #639 CI run `39443794866` and current-main PR #716 CI run `39675323627` were green; neither resolves this missing cross-feature assertion.

### Failure mode and impact

A valid relation using a non-default SSH port exports successfully, but same-collector import cannot detect the root channel U45 needs. It silently chooses ordinary `add-client` without `--join-remotely`; the source does not learn the new pairing key, and the subsequent seed can fail with the exact “has --join run there yet?” class U45 was intended to remove. The import can leave a resumable record and require manual package/join work despite the root channel being available. No data-loss path was demonstrated.

### Required outcome / acceptance criteria

- [ ] Parse the selected replay endpoint once through the existing canonical endpoint parser before any root probe; pass the hostname and effective port as separate `rux_root_ssh` arguments.
- [ ] Preserve the replayed `--host=HOST[:PORT]` argument exactly for `cmd_add_client`; parsing for the probe must not silently rewrite the imported relationship.
- [ ] Add an actual `cmd_import_relation()` regression where `--host=source.example:2222`, root is available only at `(source.example, 2222)`, and ordinary U45 replay appends exactly one `--join-remotely`.
- [ ] Keep the default-port positive control and no-root negative control; the latter must still take the documented manual-join path without claiming automatic join.
- [ ] Cover an older export whose `ACTIVE_ENDPOINT=HOST:PORT` replaces the pairing address under U62, so both current and migrated files use the same endpoint/port contract.
- [ ] Make the network stub validate all three arguments rather than returning success for any host/port, so the current defect is a failing negative control.
- [ ] Run `bash test/zfsbackup/run.sh --section exportrel`, `bash test/impact.sh --verify`, `bash test/reviewctl.sh --verify`, and CI against the exact submitted SHA.

### Evidence boundary

This is deterministic call-boundary evidence through the shipped import entry function. It proves the wrong SSH arguments and resulting missing `--join-remotely`; it does not claim a live non-default-port import was attempted. The earlier PR #639 live evidence covered the default-port path only. The reviewer made no production-code change.
