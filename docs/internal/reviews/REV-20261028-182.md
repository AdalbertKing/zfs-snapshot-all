## F1 — failed `zfs get creation` becomes an empty GFS ladder and deletion

- Severity: **P1**
- Blocking: **yes for GFS retention**
- Affected: `delsnaps.sh`, `delete_snapshots()`, `mode=gfs`

### Evidence

GFS captures each creation value with command substitution but does not check
the command status or validate an integer epoch. An empty value fails every
bucket comparison, so the affected snapshot is not selected as a survivor and
falls through to the ordinary `zfs destroy` path. The metadata diagnostic does
not set `EXIT_CODE`; successful destruction makes the overall command return 0.

Executable exact-blob negative control (stub `zfs`; no pool or host access):

```bash
bash docs/internal/reviews/evidence/REV-20261028-182-gfs-creation-read-failure.sh
```

Against both exact affected SHAs it observes `zfs get ... creation` failing,
then records `destroy -- tank/data@one` and `delsnaps_rc=0`.

### Failure mode and impact

A transient read/permission/transport failure can turn every unreadable GFS
candidate into a non-survivor. A snapshot that is the only member of the newest
hourly bucket is therefore destroyed instead of kept, while the run reports
success. With multiple failed reads this can remove all eligible snapshots.

### Acceptance criteria

- Any failed, empty, non-integer, negative or otherwise unusable creation value
  in GFS mode must make the dataset run fail closed before its first mutation.
- The command must return nonzero and name the affected snapshot/metadata read;
  it must not emit success stats for that dataset.
- No `zfs destroy` may run for any candidate in that dataset after incomplete
  GFS inputs. Do not silently keep/delete only the readable subset.
- Preserve correct bucket selection, reserved-prefix protection, holds,
  dry-run behavior, remote transport and explicit clear-cut semantics.

### Required verification

- Add negative cases for nonzero `zfs get`, empty output, nonnumeric output and
  partial failure among multiple candidates; each asserts nonzero and zero
  destroy calls.
- Retain positive single- and multi-tier GFS cases proving exact survivors and
  deletion scope, locally and through the remote-command abstraction.
- Make the reproducer above PASS on the implementation SHA and remain FAIL on
  both affected exact SHAs.
- Run the focused `delsnaps` suite, shell syntax, `git diff --check`,
  `test/impact.sh --verify` and exact-head CI. No live pool is requested.

focused suite, reproducer, syntax, `git diff --check`, `impact --verify` and
