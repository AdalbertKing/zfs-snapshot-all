## F1 — P1 — new reconciliation semantics depend on real ZFS properties but have only stub proof

The commit changes runtime `gen-cron.sh --reconcile` and makes classification depend on real ZFS state, including `usedbydataset`, child topology, and the meaning of recursive engine exclusions (`-S`, `-X`). The submitted proof is:

- `test/reconcile` 41/41;
- negative control against the previous implementation, with 5 new assertions failing.

That proves the comparison logic against the stub model. It does **not** prove the assumptions the stub is standing in for:

1. a real structural parent on the fleet reports `usedbydataset` low enough to be safely classified as data-empty;
2. putting real data directly in such a parent crosses the guard and prevents suppression;
3. a real ZFS hierarchy exercised through `--reconcile` respects `-S` / `-X` the same way the engine does, rather than merely the way the test stub models those flags.

This project explicitly treats local green suites as a filter rather than final evidence for ZFS/host-state-dependent behaviour. This change crossed that boundary.

### Minimum sufficient proof

Do **not** rerun the whole four-host Stage-4 campaign. A targeted live proof on one suitable ZFS host is enough if it exercises the actual changed assumptions:

1. **Structural-parent positive case** — real parent dataset with covered children and no meaningful direct data is reported under the suppressed/structural heading and is not counted as uncovered.
2. **Direct-data negative control** — write enough real data directly into that parent to cross the implementation threshold; rerun reconciliation and prove the parent becomes an uncovered finding rather than remaining suppressed.
3. **Coverage negative control** — leave one child uncovered and prove the parent is not suppressed.
4. **`-S` proof** — on a scratch real ZFS hierarchy/config, prove recursion with skip-parent does not mark the skipped parent covered.
5. **`-X` proof** — prove an excluded real child remains uncovered instead of inheriting recursive coverage.
6. Destroy scratch state afterwards and record exact host, identity, commands/config, relevant ZFS property values and outputs/exit status.

The fleet reportedly does not currently use `-S` / `-X`; therefore synthetic scratch ZFS is appropriate and cheaper than modifying production jobs.

### Dependency / graph boundary

Because `gen-cron.sh` changed, report the actual `impact.sh`-selected cascade for the final proof commit and `impact --verify`. If the graph selects only `reconcile`, explain why that edge covers the changed runtime path; if it fails to select a suite that owns shared generator behaviour, treat that as graph drift rather than manually papering over it.

No transfer-engine live campaign is required: the frozen engines were not changed. No real crontab write is required because `--reconcile` is read-only.

### F1 follow-up — P1 — reconciliation does not parse legal bundled `-S` / `-X` spellings like the engine

The engine uses `getopts` and explicitly supports clustered short options. Its parser therefore treats, for example:

```text
-eS
```

as `-e` plus `-S`, and:

```text
-SX drop$
```

as `-S` plus `-X drop$`.

The new reconciliation coverage code does not use that grammar. It walks whitespace-separated tokens and only recognizes:

```bash
-S
-X
-Xpattern
```

as whole-token shapes. Therefore legal engine invocations such as `flags = -eS` or `flags = -SX drop$` are misread by `--reconcile`. In the second case reconciliation can miss both skip-parent and exclusion, mark the skipped parent / excluded child as covered, and return a false green.

This is not a new REV: it is the same REV-074 acceptance property — reconciliation must honor `-S` / `-X` **the same way the engine does**.

### Required correction

Do not add another ad-hoc list of special token spellings. Parse the relevant `flags` with the same getopts-equivalent short-option grammar already established elsewhere in this repository, including option-argument consumption and clusters. Reuse/extract an existing walker if that is the smallest way to keep one grammar source; otherwise prove equivalence explicitly.

At minimum add discriminating regression cases for:

1. `flags = -eS` — parent is skipped exactly as with separate `-e -S`;
2. `flags = -SX drop$` — parent is skipped and matching child excluded;
3. argument-boundary negative control such as `flags = -X fooS` — the `S` inside the `-X` argument must **not** become skip-parent;
4. retain the existing separate-token `-S` / `-X` cases.

Run the dependency-selected cascade and `impact.sh --verify`. Add a negative control against the currently rejected implementation showing the new bundled-form assertions fail there.

### Live-proof boundary after the parser fix

**Do not repeat the real-ZFS campaign if the fix is parser-only.** The submitted live proof has already established the ZFS property/topology assumptions. The remaining defect is argv interpretation, so a targeted regression + mutation/negative control is the smallest sufficient proof.
