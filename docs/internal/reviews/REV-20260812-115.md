# REV-20260812-115 — CI graph gate cannot validate Protocol V2 from a shallow checkout

## Verdict

CHANGES REQUIRED. Product/runtime work at current `main` is not reopened. This is an independent CI/process defect: the repository's mandatory `./test/impact.sh --verify` job is red because GitHub Actions checks out only one commit while `reviewctl` deliberately validates historical review SHAs for reachability from the published branch.

## F1 — `actions/checkout` depth 1 makes the review reachability gate false-fail

Current `.github/workflows/tests.yml` uses plain `actions/checkout@v4` in the `graph` job. Its default is `fetch-depth: 1`.

Current `test/reviewctl.sh` intentionally requires every commit-bearing review/delivery header to name a commit that exists locally and is reachable from `origin/main`/HEAD. That is the accepted REV-067/Protocol V2 property; weakening it would reintroduce orphan/unpublished SHA false-greens.

On current HEAD `e64094ec25ac0721522fe49d2bba9a027f9478cf`, GitHub Actions run `31636965517`, job `dependency graph matches the tree` (`94249623441`) executes `./test/impact.sh --verify` and fails. The log shows checkout fetching exactly:

    git ... fetch --depth=1 origin +e64094ec...:refs/remotes/origin/main

Then `reviewctl` reports historical SHAs such as REV-065 through REV-114 as `not a commit in this repository`, followed by `GRAPH DRIFT -- fix deps.conf`.

Those commits are valid published repository history; they are absent only because CI intentionally did not fetch that history. Therefore the gate is not measuring repository correctness in CI. It is measuring checkout depth and producing a permanent false-red signal, which masks a real future graph/review drift failure.

## Required correction

Keep the review reachability invariant. Fix the CI checkout boundary instead.

Minimum acceptable shape:

- the `graph` job that runs `./test/impact.sh --verify` must fetch enough published `main` history for every durable review/delivery SHA to be resolvable and ancestry-checkable;
- simplest/recommended: `actions/checkout@v4` with `fetch-depth: 0` for that job only;
- do not broaden other jobs unless they actually need history;
- do not weaken `require_commit()`, switch it to mere string/existence checks, or special-case Actions.

## Required evidence

1. `./test/impact.sh --verify` passes in a full-history checkout at the corrected tree.
2. The GitHub Actions `dependency graph matches the tree` job is green on the corrected commit (this is the boundary that was broken).
3. `test/impact/run.sh` remains green; no product/ZFS/SSH campaign is required.
