# REV-20261029-183 — P1: root job-stats cache follows attacker-controlled /tmp symlinks

Reviewer: ChatGPT. Date: 2026-10-29.

Source release: `AdalbertKing/zfsbackup` main
`3dc6e1ae4d69daacd916805aeba6a06349e2832b`, with
`RELEASE-OF=79bdbe66bf6b707ff290cb934a451bd13456ba96`.

## F1 — predictable cache temporary file can overwrite an arbitrary root-writable path

- Severity: **P1**
- Blocking: **yes for the root GUI/update release path**
- Affected: `zfs-backup.sh`, `cmd_job_stats()`, `_js_snaps()`, `--vol-cache`

### Evidence

When `$XDG_RUNTIME_DIR` is absent or not writable, `_js_snaps()` falls back to
`/tmp` and writes the cache through the predictable pathname
`/tmp/zfs-snapshot-all-jobstats-snaps.<uid>.$$`:

```bash
printf '%s\n' "$snap_raw" > "$cf.$$" && mv -f "$cf.$$" "$cf"
```

Shell redirection follows a pre-existing symbolic link. The subsequent `mv`
moves that attacker-controlled link onto the stable cache pathname. The
ownership check applies only when reading the stable cache and does not protect
creation of the temporary file.

Executable exact-blob negative control (stub `zfs`; no pool or host access):

```bash
sudo TARGET_REPO=/path/to/zfsbackup TARGET_SHA=3dc6e1ae4d69daacd916805aeba6a06349e2832b \
  bash docs/internal/reviews/evidence/REV-20261029-183-jobstats-cache-symlink.sh
```

On the exact release it observes `job_stats_rc=0`, changes the sentinel target
to the snapshot listing, and reports `cache_is_target_symlink=yes`. The same
behavior is present in the exact `RELEASE-OF` tree.

### Failure mode and impact

The normal root GUI requests `job-stats --vol-cache`. On hosts without a
writable `/run/user/0`, a local unprivileged user can pre-create symlinks for
predictable root PIDs. A successful race makes the root process truncate and
write an attacker-selected path, then leaves the stable cache as a symlink.
This is a local privilege boundary violation and can corrupt root-owned system
or application state. The command still returns success.

### Acceptance criteria

- Cache creation must never follow a symlink or overwrite a non-regular,
  foreign-owned, or otherwise unsafe path, for both the stable name and every
  temporary name.
- Do not create predictable temporary files directly in a shared directory.
  Use a private, owner-validated directory and exclusive/atomic creation, or
  disable caching and perform a fresh read when no safe cache location exists.
- A hostile pre-existing stable path, temporary path, directory, FIFO, hard
  link or symlink must not be read, truncated, renamed over, or treated as a
  cache hit. The command may safely continue without caching or fail clearly.
- Preserve one-listing semantics, cache reuse for the same user, log-mtime
  invalidation, permissions no broader than `0600`, and valid JSON output.

### Required verification

- Add deterministic negative tests for attacker-controlled stable and
  temporary symlinks in the fallback path; assert the target sentinel remains
  byte-for-byte unchanged and no unsafe cache object survives.
- Add controls for a safe cache hit, stale invalidation, concurrent writers,
  and unavailable runtime/cache directories.
- Make the reproducer above PASS on the implementation SHA and remain FAIL on
  release `3dc6e1ae4d69daacd916805aeba6a06349e2832b`.
- Run the focused `zfsbackup` job-stats suite, release packaging suite, shell
  syntax, `git diff --check`, `test/impact.sh --verify`, and exact-head CI.
  No live host or pool is requested.

### Notes and uncertainty

The deterministic reproducer controls the process PID rather than attempting a
timing race; it proves the vulnerable filesystem operation directly. Practical
exploitation requires local write access to `/tmp` and predicting or covering a
root PID, which is feasible on ordinary Linux hosts. No production code, host,
pool, snapshot, or release repository was modified by this review.
