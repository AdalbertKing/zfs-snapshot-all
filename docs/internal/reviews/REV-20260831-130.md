# REV-20260831-130 — `-E` breaks the following long recursion option in both transfer engines

Review date: 2026-08-31
Reviewer: ChatGPT
Reviewed delivery: canonical `main` at `6519b5a11f8c4456a507988392da8313e50e2ea4`; independently surfaced while reading draft PR #235, head `18d6a6d01d6d1e7e76004e798592fa72072253b7`
Canonical base checked: `6519b5a11f8c4456a507988392da8313e50e2ea4`

## Verdict

**CHANGES REQUIRED — P1: both transfer engines reject a valid invocation when
the argument-taking `-E` option is followed by a long recursion declaration.**

The long-option pre-pass derives its short-option argument grammar from
`OPTSTRING`. In both `snapsend.sh` and `snapget.sh`, that string omits `E:` even
though the real `while getopts` grammar includes it. The pre-pass therefore
mistakes the argument of `-E` for the first positional argument and stops before
translating the following `--recursive=...` option.

## F1 — P1 BLOCKING — valid `-E VALUE --recursive=MODE` is refused

- Severity: P1
- Blocking: yes
- Affected: `snapsend.sh`, `snapget.sh`, and the focused argument-normalisation
  coverage in `test/recursion/run.sh`.

### Evidence

On exact canonical `main`, both engines declare `E:` in the grammar that
actually parses short options:

```sh
while getopts "...L:E:" opt; do
```

but omit it from the grammar used by `translate_long_options()`:

```sh
OPTSTRING="...K:O:L:"
```

Reviewer-only control, run against both real engines with no ZFS or root
requirement:

```sh
bash snapsend.sh -E foo --recursive=flat tank/src tank/dst
bash snapget.sh  -E foo --recursive=flat tank/src tank/dst
```

Both refuse the valid command before dependency or dataset work:

```text
illegal option -- -
Nieznana opcja -
```

The matched control substitutes another argument-taking option already present
in `OPTSTRING`:

```sh
bash snapsend.sh -X foo --recursive=ture tank/src tank/dst
bash snapget.sh  -X foo --recursive=ture tank/src tank/dst
```

Both controls reach the long-option parser and name the deliberately invalid
value:

```text
Error: --recursive= takes atomic, flat or no (got 'ture')
```

The same visibility probe with `-E foo --recursive=ture` does **not** name
`ture`, confirming that the long option was never translated. This is not a
missing-dependency false positive: the refusal happens in argument parsing, and
the `-X` control exercises the same path with only the grammar entry changed.

### Failure mode and impact

`-E` is a public option for excluding a snapshot family, while
`--recursive=flat` is the public long spelling for flat recursive transfer. A
job combining them is valid according to the engines' own final `getopts`
grammar but is rejected as an unknown option by the earlier pre-pass. The
result is a stopped backup job with a message that points at neither `-E` nor
the grammar drift. This is directly relevant to the Profiles stage, which is
currently separating relationship decisions from the legacy flags field and
must be able to render supported combinations without discovering that the
engine refuses them.

### Acceptance criteria

1. The long-option pre-pass in both `snapsend.sh` and `snapget.sh` must classify
   `-E` as argument-taking, consistently with each engine's final `getopts`
   grammar.
2. `-E foo --recursive=flat` and `-Efoo --recursive=flat` must both reach normal
   post-parse processing in both engines; neither may report an unknown `-`.
3. A visibility regression using `-E foo --recursive=ture` must be rejected by
   the long-option parser and must name `ture`, proving that the value following
   `-E` was consumed as data and the next argument remained an option.
4. Preserve the existing stop rules after `--` and after a genuine positional
   argument, and preserve all current recursion declaration/refusal cases.
5. Add the focused cases to `test/recursion/run.sh`; do not broaden this into a
   live ZFS campaign.

### Required verification

- automated: `bash test/recursion/run.sh` with the new spaced and bundled `-E`
  cases for both engines;
- negative control: the spaced visibility case must fail against
  `6519b5a11f8c4456a507988392da8313e50e2ea4` because `ture` is not seen by the
  long-option parser;
- consistency: `./test/impact.sh --verify` and exact-head CI;
- no live transfer or destructive ZFS test is required for this bounded parser
  correction.

### Notes and uncertainty

Draft PR #235 fixes the corresponding `-E` grammar omission in `gen-cron.sh`
but explicitly leaves the frozen engines unchanged. That generator correction
does not resolve this finding. The REV is limited to making the engines accept
an option combination their public grammars already declare; it does not ask
Profiles to change ownership or topology policy.
