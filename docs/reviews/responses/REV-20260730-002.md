## F2 P2 test debt — partially addressed

Of the three gaps the review named:

- **an atomic-rename-only failure distinct from temp-file creation/write
  failure** — addressed. `test/selfupdate/run.sh` case 20 (new): `chattr +i`
  on the pre-existing DESTINATION FILE, not the whole state directory,
  isolates exactly the rename -- the directory stays writable (`mktemp` and
  the write into the tempfile both succeed), and only `mv -f tmp dst` fails.
  Confirmed live on pve0 before writing the test: an immutable destination
  file makes `mv -f` fail with "Operation not permitted" while a plain new
  file in the same directory writes fine. Tests `write_state_file()` directly
  (the shared primitive every `do_self_update`/`do_rollback`/
  `do_resume_updates` transition goes through), asserting both that the call
  reports failure and that the pre-existing destination content is completely
  undisturbed -- no half-written state.
- **every individual caller of the shared hold/remove primitives as a
  separate scenario** — not separately addressed this pass; the review's own
  closure note already accepted "these paths converge on the tested
  primitives" as sufficient, and case 20 strengthens exactly that primitive.
- **an explicit update failure after resume combined with a simultaneous
  failure to restore the hold** — deliberately left as accepted P2 debt, not
  attempted. Constructing this deterministically would require either a
  mid-function test hook in `update-control.sh` (to pause execution between
  removing the hold and the subsequent failed update/restore attempt) or a
  racy timing test (start `--resume-updates` in the background, flip
  permissions mid-flight). The review itself names "injectable operations or
  command hooks" as the path to this specific combination; that is
  test-scaffolding inside production code, which this project avoids as a
  matter of course, and a racy test would be worse than no test. Left
  exactly as the review classified it: P2 debt to revisit only if
  `write_state_file()`, `remove_state_file()`, `emergency_disable()`,
  `do_self_update()`, `do_rollback()`, or `do_resume_updates()` are
  materially changed again.
