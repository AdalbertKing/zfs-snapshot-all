### F1 — freeze failure must abort the snapshot — MET

`freeze_one()` returns non-zero for every case listed (already frozen, failed
`fsfreeze-freeze`, failed container `sync`, mode/kind mismatch); the loop
collects the results and any failure skips the snapshot entirely.

- exit 5 = quiesce preparation failed, no snapshot attempted
- exit 4 = snapshot failed
- exit 6 = a guest is still frozen after a failed thaw

which satisfies "the final process exit must clearly distinguish quiesce failure
from snapshot failure". Already-frozen is blocking, and the message says this run
did not establish the freeze and must not claim it did.

Two cases stay deliberate non-failures because nothing needed quiescing: a guest
that is not running, and a dataset whose guest does not exist on this host (a
replica leaf parses identically to the original — an existing, tested property).

### F2 — missing `setsid` must not degrade — MET, and the test tightened

Checked before any freeze, fatal (exit 3), plus a `kill -0` check that the
deadman is actually alive — a pid that already exited is not a safety net
either, and `command -v setsid` alone would not have caught that.

The review asks specifically for a regression test proving **no `freeze` call
occurs**. The first version asserted only that the log lacked "froze VM", which
is weaker; it now greps the call trace for any `freeze <id>` invocation. The
trace is written by the sudo stub, so it records attempts, not just outcomes.

Making `setsid` absent needed different mechanics per platform (emptying PATH
only proves `mktemp` is missing; copying coreutils gives unusable `.exe` stubs on
MSYS). The test detects which world it is in and is noted in place.

### F3 — failed thaw must not clear the recovery list — MET, now atomic

Only confirmed-thawed ids are removed; failures stay; `thaw_all()` returns
non-zero; the EXIT trap keeps the state file while any id remains, and only stops
the deadman once nothing is frozen.

The review's data flow ("atomically replace frozen_file with retry_file") was
followed literally in this pass: the rewrite is now `mv -f` from a temp file
created in the **same directory** (`mktemp "${frozen_file}.XXXXXX"`), in both
`thaw_all()` and the deadman. The previous `cat >` left a window in which the
deadman could observe an empty list — and "empty" is exactly the state that makes
it stand down. Good catch; it was a real race, not a style point.

Deadman logging distinguishes outcomes as required: a per-attempt
`thaw attempt N left guest(s) frozen: ...`, and on exhaustion
`GAVE UP after N attempts -- guest(s) STILL FROZEN ... manual thaw required`.
It no longer always claims `thawed guest(s)`.

## §3.7 — artifacts left behind by a removed relationship — IMPLEMENTED

Accepted, and this was a genuine gap: nothing removed the grant.

`deploy.sh --revoke-quiesce=ACCOUNT` removes the per-account pieces — the
whitelist and the sudoers rule. Together they are the entire grant; without them
the helper refuses that account with rc=4.

The helper binary itself is **kept, and the operator is told so**, because it is
one file shared by every peer on the host and removing it would silently break
the other relationships. When the last grant is gone, the command says so and
gives the exact removal line for anyone who wants it gone. This is the "cleaned
up **or** explicitly documented as retained shared state" branch the review
allows, chosen deliberately.

It is a standalone command rather than part of `--unpair` because the grant lives
on the SOURCE host, which is the `--join` side, and that side holds no manifest
describing the initiator — teardown there cannot be inferred, so it is named.

Tested: removal of both artifacts, a second run as a clean no-op (teardown
scripts run on hosts that may never have had the grant), and refusal of a
malformed account name.

the wrong thing to put in front of an administrator, and

to is itself still open (REV-005 F5), and inventing a second, parallel entry
point now would produce exactly the duplication the wrapper exists to avoid. The
two should land together. Recorded as open rather than quietly dropped.
