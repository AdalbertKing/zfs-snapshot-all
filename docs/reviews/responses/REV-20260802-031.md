## F1 — the rollback report must not fail open — ACCEPTED, IMPLEMENTED

### Analysis

Accepted without qualification. REV-030 introduced a three-outcome contract, and
`abandon_set()` contained a path that could report outcome 2 while outcome 3 was
true: the survivor list was staged in a **second** `mktemp`, so a failed
allocation plus a failed `zfs destroy` produced *"nothing committed"* and the
clean-rollback exit code while an ordinary-looking snapshot from an incomplete
set remained — for the next `-e` job to consume as the current tier. A reporting
path that can fail open is not a contract; it is a contract-shaped comment.

### Implemented change

The review's preferred direction, taken literally: **the second temporary file
is gone**, not handled.

- each survivor is printed the moment `destroy_one` fails, next to the exact
  `zfs destroy` that removes it;
- a shell variable — an assignment that cannot fail — decides the exit code;
- *"nothing committed"* is therefore reachable only when that flag says so.

The failure mode is absent by construction rather than defended against, which
is why there is nothing left to inject for the `mktemp` half.

**The second half of the review — a ledger WRITE that fails** — is the same
class: a snapshot exists that the run cannot promise to remove. It no longer
under-records and reports a clean rollback at the end. The append is checked; on
failure the run names the snapshot and its removal command and exits **7**
immediately.

### Two test defects of my own, both the shape of the bug being fixed

Recorded because in both cases the assertion measured something other than its
subject, which is exactly the failure class this review is about:

1. the first injection failed `mktemp` **globally**, which also broke
   `thaw_all`'s own `mktemp`. The run exited **6 with the guest still frozen**
   and the check read that as its result. The ledger is the *second* allocation
   in that script, not the first — hence the counting stub that sabotages only
   allocation #1;
2. the structural guard matched the word `mktemp` inside the **comment
   explaining why there is no `mktemp`**. It now reads comment-stripped source.
   A guard that breaks when someone documents the thing it guards is worse than
   no guard.

## Remaining risk

The remote script is a constant streamed to the peer and cannot source this
library (the peer may be on a different revision, and a delegated account cannot
read `/root`), so the two `abandon_set` implementations are pinned by the suite
rather than shared. The suite asserts the invariant on **both** paths, which is
as close as that constraint allows.

Exit 7 still means an operator has to act: a `zfs destroy` can fail for reasons
that outlive the run — a hold, a clone, a busy dataset. The run names the
snapshot and the command, which is the most it can honestly offer.
