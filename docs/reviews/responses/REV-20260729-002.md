## R1 — validation completes after deployment phases — ACCEPTED, FIXED

`do_join()` validated before its own mutations, but it is dispatched after
Phases 1-7. Measured on pve2, same hostile package against both versions:

```
OLD (main):  8 phases ran before rejection
NEW (branch): 0
```

The package preflight is hoisted to sit beside `--join-check`, before the root
check and every phase. `do_join()` now consumes the already-validated result and
re-reads nothing; reaching it without one is an internal error.

## R2 — archive member types unchecked before extraction — ACCEPTED, FIXED

Correct, and the earlier post-extraction `-f` test could not have covered it:
a FIFO or device node is created by root before that test runs, and a hard link
arrives as an ordinary regular file that nothing on disk can distinguish.

`assert_package_members` now reads the verbose listing and requires every entry
to be a regular file, rejecting symlink, hard link, directory, FIFO, device and
anything else, before `tar -x`.

Fixtures added: hard-linked member, FIFO, directory, character device (header
built with Python's `tarfile`, so no root is needed). The directory case asserts
the *name* check's message, not the type check's: `tar` records a directory with
a trailing slash, so the name check fires first. The type check keeps its `d`
arm for a header crafted without one.

## R3 — package opened twice — ACCEPTED, FIXED

`prepare_package` creates the private `0700` directory first, copies the package
into it with `install -m 600` (mode set at creation, so there is no window where
it exists with the source's permissions), and validates and extracts only that
copy. Its SHA-256 is printed by `--join-check` and logged by `--join`, so the
checked and joined artifacts can be compared:

```
package preflight OK (sha256 34c359f9dc8f03e8d92f078816a9631b52552835359c0c74d6958a1950b7fc14)
```

## R4 — dataset grammar accepts option-like and dot-segment names — ACCEPTED, FIXED

Confirmed by running the predicate against the review's own examples: `-o`,
`.pool` and `tank/./child` were all accepted, and the call sites passed
`"$ds"` with no `--`.

Worth recording that this is not a new class of mistake here: `delsnaps.sh`
already hit the leading-dash trap once and fixed it with `--`. That lesson had
not propagated. Both halves are now closed — the grammar rejects a first
component beginning with `-` or `.` and any `.`/`..` component, and the six
`zfs list`/`create`/`allow` call sites in `do_join` pass `--` before the dataset
argument.

## R5 — cleanup check used a moving marker — ACCEPTED, FIXED, and it corrected me

Correct: `find -newer "$WORK"` compares against `$WORK`'s mtime at the END of
the run, and every `new_case` moves that mtime, so an early leak drops out of
the count. Replaced with exact directory names captured immediately before and
after each invocation, checked per case rather than once at the end.

Applying it produced a result worth stating plainly, because it contradicts
what I wrote in `d4e65fe`: **the leak was never on the rejection path.** `die`
exits from inside the function, where the `local workdir` is still in scope, so
the trap worked there. The function only loses that variable by RETURNING, which
happens on the accepted path. Measured against `5ef323c`:

```
rejected package: leaked []                     <- my earlier claim was wrong
accepted package: leaked [/tmp/tmp.SjUuBFsNIF], 1 unbound-variable error
```

So the per-case assertion this review asked for would not have caught the
original bug either. The assertion that does is the one covering the ACCEPTED
package, which is now present. `d4e65fe`'s commit message overstates the
blast radius and is corrected here rather than rewritten, since it is on `main`.

The full new suite cannot be run against `5ef323c` to demonstrate this: the
oversize fixture makes the pre-fix parser non-terminating (see R6). The targeted
comparison above is the evidence instead.

## R6 — no size bounds — ACCEPTED, FIXED, and more serious than P2

A compressed cap (64 KiB) is checked before decompression, and each member's
DECLARED size (8 KiB) is checked from the listing before extraction, so a bomb
is refused rather than expanded.

While building the fixture this turned out to be more than a disk-space
concern. A **4307-byte** package declaring a 4 MiB member does not merely waste
space on the pre-fix code -- it does not finish. One `--join-check` on `5ef323c`
was still running after 876 seconds and did not respond promptly to `SIGTERM`,
because the pathological work happens inside a bash pattern match that traps
cannot interrupt. The same package on this branch is refused in about 5 ms:

```
FATAL: a wsad member declares 4194304 bytes, over the 8192-byte limit
```

That makes R6 a denial-of-service reachable by an unprivileged sender, not only
a hardening item. Nothing about the fix changes; the severity assessment does.

  archive. Transfer remains manual and out-of-band by design.

  legitimate package is one to two kilobytes, so there is room, but a future
  field would eventually need them raised.
